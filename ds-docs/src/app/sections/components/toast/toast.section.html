Auto-dismissing notification in a vertical stack, one variant per event severity. Trigger it with ToastService.show().

The stack sits top-right by default. Move it with provideDsConfig({{ '{' }} toast: {{ '{' }} position: {{ '{' }} horizontalPosition, verticalPosition, offset {{ '}' }} {{ '}' }} {{ '}' }}); the newest toast sits nearest the anchor edge.

A toast dismisses itself after 5 s; the clock stops while the pointer or keyboard is inside the stack. Pass durationMs to change it, or 0 to keep it until dismissed.

show() returns a ToastRef with dismiss(); dismissAll() clears the stack.

With action

Pass action: {{ '{' }} label, handler {{ '}' }} to show() for a trailing button (e.g. Undo). An action toast never auto-dismisses and is always dismissible, since a keyboard user cannot reach the region (last child of body) within five seconds.

ToastService.promise() shows a loading toast while the promise is pending and turns it into success or error when it settles. This demo succeeds 60 % of the time.

Screen readers, and what the service owns

ToastService announces through the CDK LiveAnnouncer, not the toast element: a live region created with its text already in it is silent in NVDA and JAWS. Errors and warnings are assertive, the rest polite, and a burst is one announcement.

A <ds-toast> placed by hand has no role or aria-live and is silent, so route real events through the service.

The service also keeps the stack above a modal, drawer or confirm opened after it. --layer-toast cannot, because overlays live in the top layer where z-index does not apply.

A region holding four toasts at maxVisible: 3: newest on top, and a +1 strip for the one still queued. toast.showQueueCount: false hides the strip.

maxVisible queue

toast.maxVisible in provideDsConfig caps concurrent toasts (default 5, 0 for no cap). Extras queue and appear as earlier ones dismiss; fire the button twice to see the queue.
