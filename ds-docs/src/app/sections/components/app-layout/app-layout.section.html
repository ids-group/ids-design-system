Opening the rail from your own chrome

Below lg the rail is an overlay opened from your topbar.

  • dsRailTrigger on a native button toggles it and syncs aria-expanded / aria-controls
  • On ds-icon-button the attributes would land on the wrapper; bind its forwarding inputs off a <ds-app-layout #layout> ref 
<ds-icon-button
  icon="menu"
  ariaLabel="Open navigation"
  [ariaExpanded]="layout.railOverlay() ? layout.railOpen() : null"
  [ariaControls]="layout.railOverlay() ? layout.railId : null"
  (pressed)="layout.railOpen.set(!layout.railOpen())" />
  • Both attributes drop while the rail is not an overlay
  • [(railOpen)] : the open state
  • railLabel : the overlay dialog name, default DS_INTL.appLayout.railLabel
  • The overlay traps focus; Esc or a scrim click closes it and refocuses the trigger
  • Requires provideRouter

Returning the reader to where they were

[restoreScroll]="true" remembers scroll per path; a new screen starts at the top. These docs use it.

  • Restores on history traversal (popstate: Alt +←, back, forward, mouse side button, edge swipe)
  • Restores on the first navigation after a reload
  • Restores on navigation with state: {{ '{' }} dsRestoreScroll: true {{ '}' }}
  • Waits for content to grow tall enough, up to restoreScrollTimeout (default 2000 ms)
  • Wheel, touch or key input cancels a pending restore
  • scrollReset : the default 'path' returns the content to the top on a path change only, so search, sort and paging keep the place; 'always' also on a query- or fragment-only navigation (server-paged lists); 'never' leaves it to the screen's scrollToTop() .
Service member Use
AppLayoutNavigationService.pathChanged Path-only NavigationEnd, de-duplicated, skips state: {{ '{' }} dsSamePage: true {{ '}' }} . Inject it; do not derive your own.
AppLayoutScrollService.scrollToTop() Scrolls the content to the top
AppLayoutScrollService.consumePendingOffset() Takes the offset and cancels the restore, for a page that sets its own scroll (a virtualizer)

The rail footer on its own

<ds-sidenav-footer> is configured, not composed: profile row, alert bell, collapse handle.

  • [collapsed] picks the state; width comes from the sidenav, so outside one give it a frame
  • Emits only collapseToggled and signOutSelected ; the parent acts, so the unbound collapse row here does nothing
  • A null searchProvider or alertItems makes that row inert
  • An empty profileRoute makes "Your profile" a no-op
