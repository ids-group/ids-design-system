Opening the rail from your own chrome

  • Below lg the rail is an overlay opened from your topbar.
  • dsRailTrigger on a native button - toggles it, syncs aria-expanded / aria-controls.
  • ds-icon-button - the attributes would land on the wrapper; bind its forwarding inputs off a <ds-app-layout #layout> ref: 
<ds-icon-button
  icon="menu"
  ariaLabel="Open navigation"
  [ariaExpanded]="layout.railOverlay() ? layout.railOpen() : null"
  [ariaControls]="layout.railOverlay() ? layout.railId : null"
  (pressed)="layout.railOpen.set(!layout.railOpen())" />

Both drop when the rail is not an overlay: aria-expanded="false" would misstate a visible rail.

[(railOpen)] is the open state; railLabel names the overlay dialog (default DS_INTL.appLayout.railLabel ). The overlay traps focus; Escape or a scrim click closes it and refocuses the trigger. Requires provideRouter.

Returning the reader to where they were

[restoreScroll]="true" remembers scroll per route; a new screen starts at the top. These docs use it.

  • Restores on history traversal (popstate: back, forward, mouse side button, Alt+←, edge swipe), reload, or navigation with state: {{ '{' }} dsRestoreScroll: true {{ '}' }}.
  • Wheel, touch or key input cancels a pending restore.
scrollReset Back to the top on
'path' (default) Path change only; search, sort and paging keep the place.
'always' Also query/fragment-only navigation (server-paged lists).
'never' Left to the screen, via AppLayoutScrollService.scrollToTop().

AppLayoutNavigationService.pathChanged answers "did we go elsewhere?": NavigationEnd , path only (no query or fragment), de-duplicated, skipping navigations with state: {{ '{' }} dsSamePage: true {{ '}' }} . Inject it; do not derive your own.

  • The offset waits for content to grow tall enough (a ResizeObserver, capped at restoreScrollTimeout): 8 of 40 rows loaded still lands close.
  • A page that sets its own scroll (a virtualizer) takes the offset itself: inject(AppLayoutScrollService).consumePendingOffset().

The rail footer on its own

  • <ds-sidenav-footer> - the rail part you configure, not compose: profile row, alert bell, collapse handle.
  • [collapsed] - picks the state.
  • Width comes from the sidenav; outside one, give it a frame.
  • Emits only collapseToggled and signOutSelected; the parent acts, so the unbound collapse row here does nothing.
  • Null searchProvider or alertItems - that row is inert.
  • Empty profileRoute - "Your profile" is a no-op.
