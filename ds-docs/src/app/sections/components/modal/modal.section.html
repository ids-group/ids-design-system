Status

status takes the same DsStatus vocabulary as the rest of the library, and one word drives four things: the icon-badge tint, the title colour, the DEFAULT icon and the ARIA role. The icon comes with the status on purpose — a tint alone signals by colour only, which a colour-blind reader cannot act on. Pass icon to override the glyph, or dialogRole to override the role.

error and warning resolve to alertdialog — the role for a dialog that interrupts with something the reader must act on — and everything else stays dialog. Same split ds-alert makes between alert and status.

Without dividers

[dividers]="false" drops the rules and tightens the vertical padding in one move, because those are one design decision. Hiding the rules alone — --ds-modal-divider: transparent — leaves the header and body padding stacked into a gap sized for a rule that is no longer drawn.

Which padding collapses is deliberate: the BODY's goes to zero and the header and actions keep theirs. The body is the scroll container, so a gap living in its padding would scroll away and content would meet the title; the header's own padding-bottom cannot, so it separates the two at every scroll position.

For a whole-app opinion, set it once — provideDsConfig({ modal: { dividers: false } }) rather than a binding on every modal. It also reaches where an attribute cannot: a ModalService confirm renders a ds-modal-card with no ds-modal ancestor to bind, and the injected default gets there. An explicit [dividers] on the element still wins.

Persistent

[persistent]="true" disables both backdrop click and Esc — only an explicit close button or programmatic open.set(false) can dismiss the dialog. Use for multi-step wizards or save-required flows where accidental dismissal causes data loss. [closeOnBackdrop]="false" disables only the backdrop click while keeping Esc active.

A backdrop dismissal needs the press AND the release on the backdrop. Selecting text in the body and letting go past the edge does not close the dialog, and neither does a slider drag that overshoots — the browser reports that gesture as a click on the backdrop, which is what used to dismiss it. ds-bottom-sheet behaves the same way; ds-drawer never had the problem, because its scrim is a sibling of the panel rather than its parent.
