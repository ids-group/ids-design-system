Text input that filters a token-tagged list. Single-select for picking a record (a Member, a venue); multi-select for picking a set (allowed products, audience tags). Distinct from <ds-select> (fixed-list dropdown) and Command palette (global search).

Which one, when. The two overlap on multi-value picking and the boundary is about the LIST, not the count. Reach for autocomplete when the set is too big to scan and typing is how you narrow it — a member, a venue, a product out of thousands; its value is the filter, and the chips are how it reports what typing found. Reach for ds-multi-select when the options are few enough to read: it shows them as a checkbox list, so a reader sees the whole choice at once and what is NOT selected, which typing hides. A rule of thumb that holds in practice: if a user could not name the options without seeing them, they need to type — that is autocomplete.

Width

Default width="fill" stretches to the container. width="content" hugs the chips/value plus a minimum typing area — for filter toolbars where a full-width trigger looks broken next to one short chip. --ds-autocomplete-input-minw tunes the typing area (default 80px), --ds-autocomplete-maxw caps the trigger in either mode.

Validation states

hint renders a helper line below the field; [invalid]="true" switches it to an error; [disabled]="true" makes the control inert.

Option groups

Pass optionGroups instead of options to render labelled sections in the panel. Filtering hides entire groups whose options produce no matches.

Create new

Add allowCreate to show a Create «text» row when the typed text has no exact match. Selecting it emits a create output — the consumer decides how to add the item. In this demo the new tag is appended to the list and auto-selected.
