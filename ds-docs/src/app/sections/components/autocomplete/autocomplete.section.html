Text input that filters a token-tagged list. Single-select for picking a record (a Member, a venue); multi-select for picking a set (allowed products, audience tags). Distinct from <ds-select> (fixed-list dropdown) and Command palette (global search).

Which one, when. The two overlap on multi-value picking and the boundary is about the LIST, not the count. Reach for autocomplete when the set is too big to scan and typing is how you narrow it — a member, a venue, a product out of thousands; its value is the filter, and the chips are how it reports what typing found. Reach for ds-multi-select when the options are few enough to read: it shows them as a checkbox list, so a reader sees the whole choice at once and what is NOT selected, which typing hides. A rule of thumb that holds in practice: if a user could not name the options without seeing them, they need to type — that is autocomplete.

The same rule settles single-value picking against ds-select , which is the comparison that actually comes up: the LIST decides, not the count and not the look. Once a value is chosen the two are deliberately close — autocomplete shows the label and collapses its filter input away, so a settled field reads as a picker rather than a text box — and they part again the moment you open it, where one lets you type and the other does not. Pick by whether the reader can find the option by scanning.

Capping the chips

The trigger stays one line by default. maxVisibleChips defaults to "fit" — it measures and keeps as many chips as the trigger is wide, with the rest behind "+N more", re-split whenever the trigger resizes. Left to grow, a multi-value trigger gains a line per selection and pushes the rest of the form down the page. Same input and same default on ds-multi-select, so the two multi-value pickers do not diverge. Backspace still removes the last SELECTED chip, not the last visible one.

The other two modes are one binding away. A number is a CEILING — at most that many, and fewer when the trigger is too narrow to hold them beside the count and the typing area. It measures for the same reason the default does: honouring the count on a phone pushed the text input onto a second line, which is the growth the cap exists to prevent. maxVisibleChips="all" is the one mode that does not measure — it shows every chip and lets the trigger grow.

Drag the handle to watch the default split move with the width.

Width

Default width="fill" stretches to the container. width="content" hugs the chips/value plus a minimum typing area — for filter toolbars where a full-width trigger looks broken next to one short chip. --ds-autocomplete-input-min-width tunes the typing area (default 80px), --ds-autocomplete-max-width caps the trigger in either mode. An option label too long for the panel, the create row's included, is cut with an ellipsis and shows in full in a tooltip on hover; one that fits shows none.

Validation states

hint renders a helper line below the field; [invalid]="true" switches it to an error; [disabled]="true" makes the control inert.

Option groups

Put groups in the same options input — flat options and groups may be mixed, and render in the order given. Filtering hides a group whose options produce no matches.

Create new

Add allowCreate to show a Create «text» row when the typed text has no exact match. Selecting it emits a create output — the consumer decides how to add the item. In this demo the new tag is appended to the list and auto-selected.

Icons in the options

An option carries an optional icon , rendered before its label at 16px in the panel rows. Same field and same markup as ds-select and ds-multi-select : all three read one DsOption shape. Use it for a set the reader recognises by glyph, like a channel or a priority scale; an icon per row costs scanning speed everywhere else.

An option can also carry disabled — the row greys out, says aria-disabled , refuses the click, and the arrow keys step OVER it rather than parking on a row that Enter would ignore. Same field and same behaviour as ds-select and ds-multi-select .

Only ds-select repeats the icon in its trigger, because its trigger is a button showing one label and has room for it. Here the trigger is the text input the reader types into, and its leading slot belongs to [dsAutocompletePrefix] — the DS will not put a glyph in it uninvited.

Object values keep their selection

compareWith decides when two values are the same one. The default is ===, which for an object is reference identity — so a re-fetch returning equal data as new objects would drop the selection. Key the comparator on whatever identifies the value. Press Refetch: the selection survives.
