A cell that is a link

A clickable row has no href: it is not a link to a screen reader, Ctrl/Cmd-click cannot open it, and its hover tint is invisible to keyboard and touch users. Give the column a link function returning an Angular route target and the value renders as a real <a>.

Return null and that row's cell stays plain text. External URLs need a [cell] template; this takes route targets only.

With rowInteractive the link stops its click from reaching the row, so the rest of the row still fires the row handler. That costs two tab stops per row; on a long list drop rowInteractive once the link is there.

Column picker · reorder

With dsTableColumns, the header Columns button opens a panel that toggles hideable: true columns (two-way [(hiddenKeys)]; hidden: true starts hidden; the last visible column is locked).

[reorderableColumns]="true" adds a drag handle and up/down buttons per row, two-way through [(columnOrder)]. Reset to default clears both.

Resizable columns

dsTableResize adds a drag handle to each header's right edge. It takes no input: seed widths from column.width, read live ones via viewChild(DsTableResize).columnWidths() (a Map<key, px>), and use persistLayout to carry them across reloads.

The first drag records a width for every visible column, so untouched auto-sized columns do not jump.

The handle is a focusable role="separator" with aria-valuenow/min/max in px. Arrow keys step 16px, PageUp/PageDown 64px, Home returns the column to auto; the maximum is the scroll viewport.

Inline editing

Columns marked editable: true (Record, Venue, Capacity here) become an input on double-click; Enter or blur commits, Escape cancels. (cellEdited) emits {{ '{' }} row, key, value {{ '}' }} and the host applies the update.

Persisted layout & export

[persistLayout]="true" with a storageKey keeps column order, widths and hidden set in localStorage across reloads. Without a key nothing is stored.

dsTableExport renders the CSV button; exportFilename names the download (default table.csv, also the name a Blob from the fetcher is saved under). A server-paged table passes [exportFetcher] to export the whole set; bind (exportFailed) or a rejected fetch is silent.

On a coarse pointer the drag handle is off (it would swallow the scroll swipe). Width moves into the column panel as - / + / Fit buttons with the keyboard step sizes, and the panel opens as a ds-bottom-sheet. The buttons also show on desktop.

Toolbar slot · the export button anywhere

The [toolbar] slot is a row above the table for controls that act on it: a search box (here bound to [filterQuery]), a status filter, a refresh. Several projected controls are laid out flex, wrapping, 8px gap; a single projected element owns its own layout.

The row disappears when the slot is empty and dsTableExport is off. Page-level filters still belong in a ds-filter-bar.

Truncation · full-text popover

truncate: true ellipsis-clips a text column at its width (240px when unset). The full value shows in a tooltip, and clicking a clipped cell opens it in a popover; an unclipped cell passes the click to the row.

Clip detection runs only in truncate columns, and finds an ellipsis on a descendant a dsCellTemplate renders.

Sticky horizontal scrollbar

[stickyScrollbar]="true" hides the native bar and pins a proxy scrollbar to the bottom of the viewport while the table is on screen, so a tall, wide table stays scrollable sideways. Set it app-wide with DS_CONFIG.table.stickyScrollbar.

The bar cancels the scroll container's bottom padding so it rests on the visible edge. For another edge set [stickyScrollbarOffset] or DS_CONFIG.table.stickyScrollbarOffset; the --ds-table-sticky-scrollbar-offset hook out-ranks both.

CSV export

dsTableExport enables export. exportCsv() then downloads the visible columns of the filtered and sorted rows, all pages; without the directive it logs a warning instead. Call it from your own button through a template reference; [dsTableExport]="false" hides the built-in button.

Server-side filtering, and a filter of your own

Header filters default to filterMode="server": the table tracks columnFilters and filters nothing, so your request drives the rows. Pass the full value domain through columnFilterOptions, or the checklist offers only this page's values.

Declare filterMode="client" when the table holds every row. A dev warning fires for a filter: 'set' column on a table that binds no total and declares no mode. filterMode="none" removes the affordance.

For a criterion that is not a list of values (a date range, a threshold, an async lookup), project the panel with dsHeaderFilter. The table keeps the header button, popover and active styling; active tells it when your criterion is set. 

<ng-template dsHeaderFilter="opened" [active]="!!range()" let-close="close">
  <ds-date-picker mode="range" [(value)]="range" />
  <ds-button size="sm" (pressed)="apply(); close()">Apply</ds-button>
</ng-template>

What a screen reader is told

One role="status" region announces sort ("Sorted by Owner, ascending") and range ("Showing 1-25 of 240"). Loading takes precedence, and the first render is silent.

sortAnnouncement and rangeAnnouncement take the facts and return the sentence; an empty string means silence.

A paged table left with no rows announces its empty-state text, or calls rangeAnnouncement(0, 0, 0) when that state has none. A server page that comes back empty with total above 0 stays silent.

Virtual scroll

10 000 rows. With [virtualScroll]="true" only the rows in view are in the DOM, with two spacer rows standing in for the rest, so the scrollbar spans the full data. It needs maxHeight as the viewport.

Every row is exactly virtualRowSize tall: virtual mode fixes the row height from it, forces table-layout: fixed and keeps cells to one line. Row expansion is suppressed with a dev warning; sorting, selection, sticky header and sticky first column keep working.

Lazy loading

The same 10 000 records, starting with none loaded. With [lazy]="true" the window requests the range it is about to show through (lazyLoad), and every index not yet filled renders a skeleton row.

data is a sparse array total long: write each fetched row at its absolute index. The scroller is sized from total. A request in flight is never re-sent; this demo answers after 600 ms.
