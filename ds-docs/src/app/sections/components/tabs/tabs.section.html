Keeping the tab in the URL

urlParam="tab" keeps the active tab in ?tab=<name>, so it survives reload, sharing and Back. Leave it out and the URL is untouched; outside a routed context it is inert. 

<ds-tabs urlParam="tab">
  <ds-tab label="Profile"  value="profile" />
  <ds-tab label="Activity" value="activity" />
</ds-tabs>

<!-- second tab active -->  ?tab=activity

Names come from each tab's value, else a slug of its label ("License Verification Status" gives license-verification-status). Set value so renaming a tab does not break links. Without value, tabClosed emits the raw label, not the slug.

The first tab writes no parameter, every write replaces the history entry, and an unknown name opens the first tab. Query-only writes do not trip ds-app-layout's pathChanged scroll reset.

Use one strip per parameter name (tab, subtab); a dev-mode warning names a clash.

Reopening the last tab

rememberLastTab (needs urlParam) reopens the last tab per path from sessionStorage. A link always wins over memory, and storage failures are ignored.
