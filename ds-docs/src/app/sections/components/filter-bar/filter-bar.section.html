Priority+ filter row: as many filters as fit, the rest behind "+N more".

Put each filter in an ng-template [dsFilterItem] with its width in px ([dsFilterItem]="170"; bare = 180). The bar splits filters from those widths and one ResizeObserver on the row, never by measuring the filters, so nothing flashes before collapsing.

Move the Frame width slider: filters collapse into the panel from the right as room runs out; controls marked dsFilterBarTrailing stay put. Mark each trailing control - a wrapper div would stack its children. Anything that is neither a dsFilterItem template nor marked dsFilterBarTrailing is not rendered.

If one component must hold two trailing controls, mark that component dsFilterBarTrailing and give its :host the bar's own trailing rule (below); the gap reads the same token. 

{{ trailingWrapperSnippet }}

Sizing the "+N" trigger

triggerSize (default md) sets the "+N" trigger height; match it to the filters' size - the bar cannot read it. Unset beside sm filters, the trigger is 8px taller.

What the width buys

Each slot is exactly its declared width, in the row and in the panel; a wider control is narrowed.

Moving into or out of the panel re-creates the filter, so an open dropdown or focus is lost; the value survives in your own signal or form control. The trigger shows the count as text with aria-expanded ; the panel is a focus-trapped dialog, and each filter exists once in the accessibility tree.
