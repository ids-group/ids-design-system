Priority+ filter row: as many filters as fit, the rest behind "+N more".
  • Each filter - an ng-template [dsFilterItem] with its width in px ([dsFilterItem]="170"; bare = 180).
  • The split reads those widths and one ResizeObserver on the row; filters are never measured, so nothing flashes.
  • Filters collapse into the panel from the right; dsFilterBarTrailing controls stay.
  • Mark each trailing control - a wrapper div would stack its children.
  • Neither a dsFilterItem template nor dsFilterBarTrailing - not rendered.

For one component holding two trailing controls, mark it dsFilterBarTrailing and give its :host the bar's trailing rule (below).

triggerSize (default md) sets the "+N" trigger height; match it to the filters' size , which the bar cannot read (unset beside sm filters, it is 8px taller).

What the width buys

  • Each slot is exactly its declared width, in row and panel; a wider control is narrowed.
  • Moving between them re-creates the filter: an open dropdown or focus is lost; the value survives in your signal or form control.
  • The trigger shows the count as text, with aria-expanded; the panel is a focus-trapped dialog.
  • Each filter exists once in the accessibility tree.
