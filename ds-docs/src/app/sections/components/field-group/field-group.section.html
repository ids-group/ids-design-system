Several controls, one bordered box — scope + search, amount + unit, input + action.

The group owns the border, radius, divider and a single focus ring; the controls inside render naked. Each control detects the group by injecting DS_FIELD_GROUP , so there is no per-child flag to forget. disabled dims the box only - disable each control as well.

Segments hug their content. Mark the one that should take the slack with grow .

Trailing action, and a unit after the value

Any supported control can be a segment, in any order — a ds-button at the end is the same mechanism as a ds-select at the start.

Every supported control

Six controls can be segments: ds-input , ds-select , ds-search , ds-autocomplete , ds-date-picker and ds-button . Not ds-number-stepper (already a composite of its own) or ds-multi-select (its chips wrap, which a fixed-height row cannot take).

Sizes, error and full width

size is the field family's scale, so a group lines up with a plain field beside it. invalid colours the whole box: a single segment cannot be in error on its own, because the border is not its own.

Saying what is wrong

error turns the state on and shows its text once, under the whole row; invalid paints the state when the text lives elsewhere (a form summary); hint uses the same row.

Every field segment (not a ds-button) carries aria-invalid while the group is in error and points at the one message through aria-describedby , so a reader who tabs straight to the second segment hears the error there too.

Do not give a grouped control a label or a hint : its message row would break the glued line, so both are suppressed. Name each segment with ariaLabel. For a group label, put your own markup above the group.
