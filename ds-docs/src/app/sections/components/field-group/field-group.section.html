Several controls, one bordered box — scope + search, amount + unit, input + action.

The group owns the border, radius, divider and one focus ring; controls inside render naked, detecting the group by injecting DS_FIELD_GROUP - no per-child flag. disabled dims the box only - disable each control as well. Segments hug their content; mark the one that takes the slack with grow .

Trailing action, and a unit after the value

Segments go in any order, e.g. a ds-button at the end.

Every supported control

Six controls can be segments: ds-input , ds-select , ds-search , ds-autocomplete , ds-date-picker and ds-button . Not ds-number-stepper (already a composite) or ds-multi-select (its chips wrap).

Sizes, error and full width

size matches the field scale, so a group lines up with a plain field. invalid colours the whole box; a single segment cannot be in error alone.

Saying what is wrong

error sets the state and shows its text once, under the row; invalid paints the state when the text is elsewhere (a form summary); hint uses the same row.

Every field segment (not a ds-button) carries aria-invalid while the group is in error and references the message via aria-describedby , so tabbing to any segment announces it.

A grouped control's label and hint are suppressed - do not set them. Name each segment with ariaLabel ; put a group label in your own markup above.
