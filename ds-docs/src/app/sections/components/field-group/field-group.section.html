Several controls in one bordered box.
  • The group owns border, radius, divider and one focus ring.
  • Controls inside detect it via DS_FIELD_GROUP and render naked; no per-child flag.
  • disabled - dims the box only; disable each control too.
  • Segments hug their content; grow marks the one that takes the slack.

Trailing action, and a unit after the value

Segments go in any order, e.g. a ds-button at the end.

Go

Every supported control

Segments: ds-input , ds-select , ds-search , ds-autocomplete , ds-date-picker and ds-button . Not ds-number-stepper (already a composite) or ds-multi-select (its chips wrap).

Sizes, error and full width

size matches the field scale, so a group lines up with a plain field. invalid colours the whole box; no segment errors alone.

Saying what is wrong

  • error - sets the state, shows its text once, under the row.
  • invalid - the state only, when the text is elsewhere (a form summary).
  • hint - the same row.

Every field segment (not a ds-button) carries aria-invalid while the group is in error and references the message via aria-describedby : tabbing to any segment announces it.

A grouped control's label and hint are suppressed; do not set them. Name each segment with ariaLabel ; put a group label in your own markup above.
