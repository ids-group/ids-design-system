The scaffold for the screens in front of the login — counterpart to ds-app-layout , which only ever covers what sits behind it.

Sign-in, forgot password, reset and MFA share four parts: a brand lockup, an optional tagline, one card holding the form, and a support line. The brand row takes the sidenav's brand / logoLetter / [dsBrandName] contract, but the tile has its own --ds-auth-layout-mark-* hooks, so retinting the mark means setting both.

Project a real logo into [brand] (sized by --ds-auth-layout-brand-max-height). It does not suppress the tile: leave brand / logoLetter unset when you supply a logo.

Set the brand once: provideDsConfig({ brand: { name, logoLetter, tagline } }) serves this layout and ds-sidenav. Each field resolves on its own and an element input beats the config; brand="" drops the wordmark while a configured logoLetter still paints the tile. Clear both for no brand row.

The config has no accent: put the plain name in the config and project [dsBrandName] where a two-tone wordmark is wanted; the projection wins over both.

Everything inside the card is yours: the default slot projects straight into it, and the layout deliberately leaves your headings and form alone so its type scale never fights your screen's. The support line goes into [dsAuthSupport] and renders as the page's contentinfo landmark when this layout IS the page — nested inside another layout's main (as on this docs site) it is a plain footer. Leave it out and the footer collapses. The card itself is an article, which is not a landmark, so the layout marks it main by default; nested inside another layout's main , as on this docs site, set landmark="none" .

On a short screen the chrome compresses, not the card

On short viewports the block padding, column gap and masthead gap clamp against svh, reaching full size at 800px of viewport height - which many laptops do not have after browser chrome. Type stays fixed: the wordmark, the tile and its glyph do not shrink.

The demos above cannot show it: the clamps read the real viewport, and a framed demo only shrinks its own box. Make the browser window short, or rotate a phone, and watch the padding, the column gap and the masthead gap come down together.

svh and not dvh : the dynamic unit changes as a mobile URL bar hides, which would re-space the column while the reader scrolls. Setting either of --ds-auth-layout-padding-block or -gap to a fixed value opts out of the compression for that one dimension.

A card taller than the remaining space still scrolls; the chrome stays in the flow rather than being taken out with position: absolute, so it never overlaps a tall form.

Why it centres with auto margins

The host is the only full-height box. The column centres with auto margins, not align-items: center, so in a fixed-height parent (--ds-auth-layout-min-height: 100%) a form taller than the box pins to the top padding and scrolls instead of landing above the scroll origin. Both demos above are the real component with that token lowered to fit this page.

The notch needs one line from YOUR app

This layout pads itself by env(safe-area-inset-*) , so a notched phone in landscape does not put the card under the cutout — and ds-bottom-sheet does the same for the home indicator. Those insets are 0 until the host document opts in , and a library cannot do it for you: it lives in the viewport meta tag, which belongs to your index.html . 

<!-- your index.html -->
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />

Without it a cutout is not enough — the browser simply reports 0 for every inset and the padding you see is the plain one. This site sets it, so the behaviour above is the real thing rather than a description of it.
