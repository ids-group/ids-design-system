Sizes

size takes sm, md or lg; unset, it reads DS_CONFIG.control.size, then md.

Clearable

[clearable] shows an inline × button when the field has a non-empty value. Defaults to true for type="search" and false otherwise — pass an explicit boolean to override.

Password toggle

On type="password", [passwordToggle]="true" adds an eye button that flips the field between masked and plain text. Two-way [(passwordVisible)] exposes the state.

Character counter

[maxLength] caps input length natively and shows a live current/max counter below the field — right-aligned, aligned with the hint.

Required vs optional

[required]="true" appends a red asterisk to the label; [optional]="true" appends the muted "(optional)" suffix. They are mutually exclusive — pick one.

Messages: error, warning, hint

A field shows exactly ONE message, highest first: error → validation errors → warning → warning-kind errors → success → hint . Only one line ever renders, so the field's height never depends on how many of them you bound. All three fields below carry the same hint; the second adds a warning and the third adds both.

The control paints the state too: an error takes a red border and tinted fill, warning and success the border only. All nine bordered fields share one rule keyed on the host's data-field-state attribute - style against that, not a class.

Focused, a field keeps its state's colour: the halo is --ds-field-focus-shadow-error, --ds-field-focus-shadow-warning or --ds-field-focus-shadow-success, where a plain field takes the blue --ds-field-focus-shadow. Under data-focus ring, edge and inset the indicator takes the field's border colour instead. Set a state's token to var(--ds-field-focus-shadow) to keep the blue for it.

The glyph on the message line

error , warning and success each bring a glyph so state is not hue alone (WCAG 1.4.1: light-theme warning #8A7400 vs success #156822). hint has none - a resting line with an icon on every field reads as noise; stateIcons.hint adds one if you want it.

Per state, app-wide: DS_CONFIG.field.stateIcons — each key independent, a name replaces the glyph, false removes it, and stateIcons: false removes all four. On one field, messageIcon wins over both:

Bind error and it shows at once. Without one, the field reads the form control's errors and waits for the first blur, so required never greets an untouched form. The fields below are plain [formControl] with Validators - focus, leave empty, blur.

A validator can raise a warning: "Display name" above returns {{ '{' }} warning: 'Long runs of capitals are hard to scan' {{ '}' }} (the kind DS_FIELD_WARNING_KIND ). The field shows the warning but stays valid - no aria-invalid , submit guards are not blocked. Reactive validators use the key as the kind; signal-forms ValidationError carries its own.

The text for required and minlength above comes from one shared map — provideDsConfig({{ '{' }} field: {{ '{' }} errorMessages: … {{ '}' }} {{ '}' }}) on this section — because Angular's built-in validators carry a detail object and no wording. A validator that supplies its own message wins over the map: "admin" is rejected by a custom validator returning {{ '{' }} taken: 'That handle is already taken' {{ '}' }} . In signal forms the same thing is written at the validator — required(path, {{ '{' }} message: … {{ '}' }}) — and the field needs no binding there either, because errors and touched are the names Angular's FormUiControl contract binds automatically.

Reserved message row

reserveMessage (default off) holds a message line's height even when there's no hint or error, so a form doesn't reflow the moment validation appears. Turn it on with [reserveMessage]="true" on a single control, or with the dsReserveMessages directive for a whole form (below). The reserved row sits ~23px under the control, so stack reserved fields tighter — <ds-stack gap="none"> — than bare ones, or the gap reads as a hole.

For a whole form, put the dsReserveMessages directive on it instead of binding every control: <form dsReserveMessages>…</form> . It provides DS_CONFIG for its subtree, merged with the config above it, and a field's own [reserveMessage] still wins. It applies to fields declared inside the host — projected content keeps the injector of the template it was written in.
