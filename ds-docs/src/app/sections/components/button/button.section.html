Two axes: color (brand/status hue family) × variant (solid · tonal · outline · ghost). Loudness is the variant (solid > tonal > outline/ghost); colour is orthogonal. Plus sizes, states, leading icon, subtext, full-width and toggle. For icon-only actions see the Icon button component; for a link-styled action use the global .link class on a button.

Only solid and tonal paint a fill. outline , ghost and text are transparent, so they adopt whatever surface they sit on — an outlined button on a tinted card reads as drawn on the card, not as a white sticker over it. Set --ds-button-bg-color per instance if a button sits on a photo or a gradient and needs its own opaque ground.

Color × variant

Every color × variant combination — all of them render. Defaults are color="primary" variant="solid" . Cells marked ⚠ are UX-discouraged: they work (and emit a dev-mode warning), but read poorly — grey solid looks disabled; quiet success/warning (outline/ghost) is too low-contrast — prefer solid/tonal there.

The whole text column is marked ⚠ on purpose: variant="text" is a no-chrome, underlined, link-styled button, which is exactly what the global .link class already gives any <a> /<button>. For a link-styled action prefer .link (lighter, no component) — reach for variant="text" only when you genuinely need the ds-button API on a link look (loading, fullWidth, the typed (pressed) output, leading/trailing icons). It's kept, not removed — just not the default choice.

secondary and tertiary are brand hue roles , not fixed colours — they ship distinct default hues (a warm orange, a cool violet), independent of --primary , so the three brand rows read apart out of the box. Changing --primary alone won't recolour them — a brand reskins each by overriding --secondary-h/s/l / --tertiary-h/s/l .

Refused with reason

Two kinds of refusal, and they take different treatments. The third column is the room the second one needs.

Standing

Nothing on this screen will lift it.

No permission to grant, no integration to connect. Set disabledReason beside disabled : the reason renders as a second line inside the button, and the button switches from the native disabled attribute to aria-disabled so it stays focusable and the reason is announced. Clicks are swallowed either way. Length is uncapped — a long reason wraps and the button grows.

Temporary

The user's own next action lifts it.

Do not disable the button at all: leave it live, judge validity in the submit handler, and carry the text under the button with hint , warning or error — the same three inputs the fields take, with the same message line under them. A message longer than the label widens the pair, button included, the way a field's control spans its own message.

Navigation that looks like a button

Three elements, decided by destination: routerLink renders an <a [routerLink]> , href a plain <a href> , and neither a <button type="button"> . The look is identical across all three, because the styling is class-based — so a call-to-action can stay a real link, and middle-click, open-in-new-tab and the "link" role a screen reader announces all keep working.

type and loading are button-only and warn in dev if set here. A disabled link-button takes aria-disabled and tabindex="-1" instead of the native attribute, which an anchor does not have.

Everything else a link can carry

fragment , queryParams and queryParamsHandling go with a routerLink ; target and rel go with either link. Each is a pass-through to the element the component already renders, and each warns in dev on a destination that cannot carry it. For the options with no input of their own — relativeTo , preserveFragment — build a UrlTree with Router.createUrlTree and pass that as the routerLink . 

<ds-button [routerLink]="['/ai-solutions', slug]" fragment="enquiry">
  Talk to us
</ds-button>

<!-- for relativeTo and preserveFragment, which have no input here -->

What an active link announces

A link that IS the current page announces aria-current="page" ; a link to a section the reader is INSIDE announces aria-current="true" , which is what ARIA means by each. The active class stays prefix-matched so a section link keeps looking lit — they are separate questions, and routerLinkActiveOptions moves the class without touching the announcement. Link-styled action

A link-styled action is the global .link class on a <button> (replaces the old variant="text" ). It is an action, not navigation — navigation is what the Link section covers.
