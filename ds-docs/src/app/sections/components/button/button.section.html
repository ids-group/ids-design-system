Two axes: color (brand/status hue family) × variant (solid · tonal · ghost · outline). Loudness is the variant (solid > tonal > ghost/outline); colour is orthogonal. Plus sizes, states, leading icon, subtext, full-width and toggle. For icon-only actions see the Icon button component; for a link-styled action use the global .link class on a button.

Only solid and tonal paint a fill. outline , ghost and text are transparent, so they adopt whatever surface they sit on — an outlined button on a tinted card reads as drawn on the card, not as a white sticker over it. Set --ds-button-bg-color per instance if a button sits on a photo or a gradient and needs its own opaque ground.

Color × variant

Every color × variant combination — all of them render. Defaults are color="primary" variant="solid" . Cells marked ⚠ are UX-discouraged: they work (and emit a dev-mode warning), but read poorly — grey solid looks disabled; quiet success/warning (ghost/outline) is too low-contrast — prefer solid/tonal there.

The whole text column is marked ⚠ on purpose: variant="text" is a no-chrome, underlined, link-styled button, which is exactly what the global .link class already gives any <a> /<button>. For a link-styled action prefer .link (lighter, no component) — reach for variant="text" only when you genuinely need the ds-button API on a link look (loading, fullWidth, the typed (pressed) output, leading/trailing icons). It's kept, not removed — just not the default choice.

secondary and tertiary are brand hue roles , not fixed colours — they ship distinct default hues (a warm orange, a cool violet), independent of --primary , so the three brand rows read apart out of the box. Changing --primary alone won't recolour them — a brand reskins each by overriding --secondary-h/s/l / --tertiary-h/s/l .

Refused with reason

Two kinds of refusal, and they take different treatments.

Standing

Nothing on this screen will lift it (no permission, no integration). Set disabledReason beside disabled : the reason renders as a second line inside the button, and the button switches from the native disabled attribute to aria-disabled so it stays focusable and the reason is announced. Clicks are swallowed either way. Length is uncapped — a long reason wraps and the button grows.

Approve invoice Delete contract

Temporary

The user's own next action lifts it. Do not disable the button at all: leave it live, judge validity in the submit handler, and carry the text under the button with hint , warning or error — the same three inputs the fields take, with the same message line under them. A message longer than the label widens the pair, button included, the way a field's control spans its own message.

Reserved room

Icon buttons

ds-icon-button takes neither: an icon button has no room for a second line. It gained ariaDescribedBy instead, to point at text the page already shows.

Full width

Set fullWidth to stretch the button to its container — for mobile primary CTAs and full-bleed form submits. The host becomes block-level at 100% width.
