Chip-based multi-value selector with search filtering, keyboard navigation, and optional overflow collapse. For a set too large to scan — where typing is how you narrow it — reach for autocomplete instead; this one shows the options as a checkbox list, so a reader sees the whole choice at once and what is not selected.

Basic usage

Chips expand horizontally; all selected values are always visible. [selectAll] adds a row that toggles every filter-matching option at once (shows an indeterminate state on a partial selection).

Overflow collapse

maxVisibleChips defaults to "fit": the trigger keeps as many chips as it is wide and collapses the rest into a "+N more" pill, re-splitting on resize. A number is a CEILING — at most that many, and fewer when the trigger is too narrow to hold them beside the count and still fit what comes after; it measures for the same reason the default does. Only maxVisibleChips="all" skips measuring: it shows every chip and lets the trigger grow a line per selection. Same input and same default on ds-autocomplete , so the two multi-value pickers do not diverge.

Compact trigger

triggerDisplay="compact" swaps the chip field for a caption and a selected-count badge at intrinsic width — a fixed footprint for a filter toolbar, where a field that grows with the selection does not fit. A projected dsPickerTrigger WINS over it, and triggerDisplay is then not read at all.

Custom option and chip content

dsOptionTemplate fills an option row's label area, dsChipTemplate fills the selected chip — so a visual that identifies the option does not vanish the moment it is picked. Both are honoured by ds-select (rows only), ds-multi-select and ds-autocomplete.

The row and the chip stay library-owned: role="option", aria-selected, the checkbox, the check glyph and the chip's close button are not projected.

Option groups

Groups go in the same options input as flat options and render in the order given, so the two may be mixed. A group's own disabled disables every option in it. Filtering hides a group whose options all fail the query.

Width

Default width="fill" stretches to the container and pins the panel to the trigger. width="content" hugs the trigger's own content and takes that width as the panel's floor instead — so a short trigger no longer forces a panel too narrow to read. --ds-dropdown-panel-minw and --ds-dropdown-panel-maxw bound the panel in that mode.

Helper / error text

hint renders a helper line below the control. Paired with [invalid]="true" it switches to an error style with role="alert".

Icons in the options

An option carries an optional icon , rendered before its label at 16px. Same field and same markup as ds-select and ds-autocomplete — all three read one DsOption shape, so a field added for one picker is not missing from the other two. Use it for a set the reader recognises by glyph, like a priority scale; it is decoration for anything else, and an icon per row costs scanning speed.

The chips stay text-only. A glyph inside a chip eats the width the label needs, and the chips are already the part of the trigger that runs out of room — maxVisibleChips exists for exactly that.
