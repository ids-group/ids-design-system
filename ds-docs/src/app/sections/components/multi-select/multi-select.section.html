Chip-based multi-value selector with search filtering, keyboard navigation and overflow collapse. It shows the options as a checkbox list, so the whole choice is visible at once; for a set too large to scan, where typing is how you narrow it, use autocomplete.

Basic usage

Chips expand horizontally; all selected values are always visible. [selectAll] adds a row that toggles every filter-matching option at once (shows an indeterminate state on a partial selection).

Overflow collapse

maxVisibleChips defaults to "fit": as many chips as fit, the rest behind "+N more", re-split on resize. A number is a ceiling - fewer when the trigger is too narrow. "all" shows every chip and grows the trigger. Same input and default on ds-autocomplete.

Labels in the trigger, and per-group select-all

triggerDisplay="labels" keeps the compact footprint but names what is selected instead of counting it, cut to the width with the rest behind «+N» — the same measurement the chips use. selectAll takes 'group' or 'both' to head each group with its own row.

Hiding the filter row

searchable takes true (always, the default), false (never), or a number — the threshold at which the row appears, stated where it applies. Set DS_CONFIG.picker.searchable to give the whole app one threshold and override it per panel. searchPlaceholder sets the filter input's placeholder (default DS_INTL.picker.filterPlaceholder).

Hiding the row moves the panel's keyboard model onto the trigger: arrows, Enter, Escape and aria-activedescendant belong to the filter input when it is there.

Compact trigger

triggerDisplay="count" swaps the chip field for a caption and a selected-count badge at intrinsic width — a fixed footprint for a filter toolbar, where a field that grows with the selection does not fit. A projected dsPickerTrigger WINS over it, and triggerDisplay is then not read at all.

Custom option and chip content

dsOptionTemplate fills an option row's label area, dsChipTemplate fills the selected chip — so a visual that identifies the option does not vanish the moment it is picked. Both are honoured by ds-select (rows only), ds-multi-select and ds-autocomplete .

The row and the chip stay library-owned: role="option" , aria-selected , the checkbox, the check glyph and the chip's close button are not projected.

Option groups

Groups go in the same options input as flat options and render in the order given, so the two may be mixed. A group's own disabled disables every option in it. Filtering hides a group whose options all fail the query.

Width

Default width="fill" stretches to the container and pins the panel to the trigger. width="content" hugs the trigger's own content and takes that width as the panel's floor. --ds-dropdown-panel-min-width and --ds-dropdown-panel-max-width bound the panel in that mode. A label too long for the panel is cut with an ellipsis and shows in full in a tooltip on hover; one that fits gets no tooltip.

The panel is portaled: panelClass is the only way to style one instance, and it reads --ds-multi-select-panel-bg-color, --ds-multi-select-check-bg-color, the --ds-dropdown-panel-* tokens and the shared --ds-option-* selected and check colours.

Helper / error text

hint renders a helper line below the control; error replaces it with error text announced via role="alert", and warning / success show their own states. [invalid] paints the error border without text. size takes sm · md · lg and falls back to DS_CONFIG.control.size; required and optional mark the label.

Icons in the options

An option's optional icon renders before its label at 16px - the same DsOption field as ds-select and ds-autocomplete . Use it for a set recognised by glyph (a priority scale). Chips stay text-only: they are the part of the trigger that runs out of room.

Server-side search

filterChange reports what was typed and filterWith="none" stops the panel narrowing the list again: the options you hand back are the ones rendered. loading replaces the empty row with a spinner while a request is in flight, and dsEmptyTemplate replaces the No-matches row. The panel emits opened (where the first fetch belongs) and closed.

Panel header and footer

dsPanelHeaderTemplate and dsPanelFooterTemplate fill a strip above and below the options, with count, total and query in context. Both sit outside the listbox, so nothing here is counted as an option, and neither scrolls with the list.

Group headings, and why an option is off

dsGroupLabelTemplate fills a group's heading — the element itself stays ours, so the id the group is named by cannot be detached from it. An option's disabledReason reaches the row as aria-describedby : the row already looks disabled, the sentence is for whoever cannot see that. Open the panel and read the "On leave" rows with a screen reader.
