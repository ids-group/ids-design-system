One track and one fill, for a measurement inside a table cell.

In a table cell

A chart is a block with a caption, a legend and an annex table; in a 60px cell that chrome is the whole cell. This is the mark on its own — the bar below sits in a 64px track beside its figure. max is the ceiling the column is read against — usually the column's own largest value, so the longest bar fills its track and the rest are its share.

Give the cell a width

The meter fills whatever box it is in, so the column decides how wide the bar is. A box sized to its content — width: 'content' on ds-table , or a shrink-to-fit flex or grid item — is sized by what its contents contribute intrinsically, and a bar that is 100% of its cell contributes nothing: a meter alone in such a cell comes out 0px wide. So the host carries a min-inline-size of 3rem , which --ds-meter-min-width overrides. Give it a width of your own where the bar should be a fixed size — the table above puts it in a 64px grid track.

What it is not

It is not ds-progress , which reports how far a task has got and says so with role="progressbar" . A rate, a score or a count against a ceiling is a measurement: it has no beginning and no completion, and a table of two hundred of them would announce two hundred progress bars. So the mark is hidden from assistive technology unless ariaLabel names it — set it where the bar is the only place the number appears, and leave it unset where the cell prints the figure beside it.

Colour

The fill takes --ds-meter-fill-color , so a column is coloured once in a stylesheet rather than once per row. The color input overrides it where the colour carries meaning — a threshold, a status. --ds-meter-height , --ds-meter-track-color and --ds-meter-radius set the rest.

Edge cases

A value past max fills the track rather than overflowing it, a negative one draws nothing, and a max of zero or less falls back to 100 — a scale with no width has no fraction to draw.
