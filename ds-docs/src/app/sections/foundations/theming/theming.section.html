Colour is layered in three concerns — a theme-independent base palette , the theme role maps (light / dark), and optional brand overlays. Light is the default; dark is opt-in. Components only ever read semantic roles, so swapping a theme or brand re-skins everything without touching component code.

Activation

The active theme is a single attribute on the document root (<html>) — a whole-document switch, not per-subtree.

  • nothing — light (default)
  • <html data-theme="dark"> — dark
  • <html data-theme="light"> — explicit light (same as the default)

There is no automatic prefers-color-scheme switch — light is deterministic by default. To follow the OS, opt in from your app bootstrap; set the attribute before first paint to avoid a flash:

Three layers

Base palette (themes/_base-palette) — theme-independent primitives at :root : hue ramps + HSL channels, --static-white / --static-ink (never flip), fonts.
Theme / roles (themes/_semantic + themes/<t>/ ) — the semantic role map (--primary, --surface-* , --text-* , --neutral-* , --focus-ring ). Light at :root , dark at :root[data-theme='dark'] .
Component / scale (styles/_tokens, *.component.scss ) — --space-* , --radius-* , --ds-* , motion. Theme-independent.

Hard rule: components never read base-palette primitives (--blue-600) directly — only Tier-2 roles (--primary, --text-secondary ) or component tokens.

Sibling themes, not a patch

Light and dark are sibling role maps sharing the base palette and the same role structure. The dark block declares the complete token set, so :root[data-theme='dark'] fully replaces light rather than delta-patching it. On-fill text uses theme-stable --static-white / --static-ink so it keeps correct contrast across themes.

Writing your own theme or brand

Two levers. A brand is a thin overlay scoped by attribute ([data-brand="X"]) — override the brand hue ramp (--blue-*) and/or --primary plus a few roles. A full theme is a new sibling role map.

You author on light — the default. Dark is a self-contained sibling, so a light-authored brand does not automatically carry into dark. If the brand must also restyle dark, add a separate [data-theme='dark'][data-brand="X"] block.
