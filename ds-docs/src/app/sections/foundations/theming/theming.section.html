Three colour layers (base palette, light / dark role maps, brand overlays) let a theme or brand re-skin every component.

Activation

One attribute on <html> switches the whole document, not a subtree.

  • nothing - light (default)
  • <html data-theme="dark"> - dark
  • <html data-theme="light"> - explicit light

<html data-neutrals="brand"> re-tints the neutral ramp from --primary-h ; light theme only, dark keeps its own ramp.

No automatic prefers-color-scheme switch. To follow the OS, add provideDsTheme({{ '{' }} followSystem: true {{ '}' }}) .

  • Sets data-theme at startup and on each OS change, not on the server
  • A data-theme already on <html> at startup wins

Three layers

Layer Source Holds
Base palette themes/_base-palette Theme-independent primitives at :root : hue ramps + HSL channels, --static-ink (never flips), fonts
Theme / roles themes/_semantic + themes/<t>/ Role map (--primary, --surface-* , --text-* , --neutral-* , --focus-ring ); light at :root , dark at :root[data-theme='dark']
Component / scale styles/_tokens , *.component.scss --space-* , --radius-* , --ds-* , motion; theme-independent

Hard rule: components never read base-palette primitives (--blue-600), only Tier-2 roles (--primary, --text-secondary ) or component tokens.

Sibling themes, not a patch

Light and dark are sibling role maps over one base palette; the dark block declares the complete set and replaces light.

  • On-fill text: white, or --static-ink on light fills; neither flips

Writing your own theme or brand

Brand
A thin overlay [data-brand="X"] on <html> : re-point palette channels (--blue-h/s/l, read by --primary-h/s/l ), optionally a few roles
Theme
A new sibling role map

Author on light.

  • Palette and channel overrides carry into dark
  • Role overrides (--primary, --primary-h/s/l , --surface-* ) lose to the dark block; restate them under [data-theme='dark'][data-brand="X"] 
{{ brandSnippet }}

Leave --primary-hover / --primary-pressed to the DS color-mix() derivation (toward black in light, toward white in dark). Full guide: themes/README.md .

Brand checklist

Five tokens take their hue from --primary in both themes. Check each against the brand; set it where it fails. Links stay blue under any brand: set --ds-link-color to change them.

Token Paints Must meet
--primary-strong Text on a tint: tag, tonal button, selected row, tab, sidenav item 4.5:1 on every tint and on --surface-default
--surface-tint Active rows and items: list, tree, empty state Text and link 4.5:1 on it
--primary-subtitle Selected option; tonal fills: button, tabs, table, calendar day, sidenav item Text 4.5:1 on it
--primary-muted Selected option on hover; button, tag, avatar, sidenav item Text 4.5:1 on it
--primary-muted-strong Tonal button hover, outline button border Text 4.5:1 on it
  • Light brand (yellow, lime, cyan): the derived --primary-strong fails, set it
  • Still on --primary-h/s/l: focus ring, field halo; set the channels
  • Dark: restate --primary and the channels under [data-theme='dark'][data-brand]

App-level defaults — provideDsConfig

Tokens set looks; provideDsConfig sets app-wide input defaults (a house size="sm" , [stickyScrollbar]="true" on every table).

  • Precedence: input > config > built-in
  • Provide at the root, on a Route or a component; calls merge per section, the later winning per key
  • provideDsIntl merges the same way 
{{ configSnippet }}

control.size is not the same axis as [data-density] . Density rewrites hit targets and padding per route; size picks one of three control sizes. Both apply.

Locale and wording

Text Follows
