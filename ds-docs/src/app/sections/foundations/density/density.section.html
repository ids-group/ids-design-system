What density rewrites

  • Hit targets - --hit-cozy (all tiers), --hit-min (ultra-compact)
  • Checkbox / radio size, switch geometry
  • Avatar default size, badge dot size, status dot size
  • Sidenav width
  • Segmented control button height
  • Field, table-cell and surface padding (--ds-surface-padding) — ultra-compact only

Choosing density per screen

Density is a screen-level decision, not user-global. The Tweaks panel exposes it for prototyping — in the product, set [data-density] on the route container, not on <html>.

Control size (sm/md/lg) is a separate axis, defaulted by DS_CONFIG.control.size.

A 32px toolbar — use compact, not a per-control pin

data-density="compact" levels a toolbar at 32px, and it is the supported way to get one. Measured on a nine-control row at default size: search, input, select, autocomplete, date picker, time picker, multi-select, number stepper and button are all 40px out of the box and all 32px under compact. So a screen whose controls should be 32px sets density once on its container, rather than pinning --ds-search-height and its siblings per component — which is what the height contract exists to remove.

Controls that hold chips (multi-select, autocomplete) set min-height, not height, so they stop following the tier once it drops below the text line. Under ultra-compact they measure 33px and 29px against 24px, because density does not scale type (a 14px font keeps a 19.6px line box). Under compact the gap is 33px vs 32px. For a true 24px row, shrink the type in that container too.

Padding follows the tier only at the bottom. compact and comfy resize controls and leave padding alone; ultra-compact also compresses field padding, table cells and --ds-surface-padding — the inner padding ds-card and ds-stat share — from 24px to 16px. For a surface padding between the two rungs, set that one token at :root ; it is the lever both components default to.
