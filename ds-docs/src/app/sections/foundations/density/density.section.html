What density rewrites

  • Hit targets - --hit-cozy (all tiers), --hit-min (ultra-compact)
  • Checkbox / radio size, switch geometry
  • Avatar default size, badge dot size, status dot size
  • Sidenav width
  • Segmented control button height
  • Field, table-cell and surface padding - ultra-compact only

Choosing density per screen

Density is a screen-level decision, not user-global (the Tweaks panel offers it for prototyping only).

  • Set [data-density] on the route container, not on <html>
  • Control size (sm/md/lg) is a separate axis, defaulted by DS_CONFIG.control.size

A 32px toolbar — use compact, not a per-control pin

data-density="compact" levels a toolbar at 32px. Do not pin --ds-search-height and its siblings per component.

Tier Control height Chip controls, with chips Padding
cozy (default) 40px Multi-select 42.8px, autocomplete 40px Unchanged
compact 32px Multi-select 42.8px, autocomplete 38.8px Unchanged
ultra-compact 24px Multi-select 42.8px, autocomplete 38.8px Field and table-cell padding; --ds-surface-padding 24px to 16px
  • Follow the tier: search, input, select, autocomplete, date picker, time picker, multi-select, number stepper, button
  • Chip controls (multi-select, autocomplete) set min-height ; density does not scale type, so a 14px font keeps a 19.6px line box. For a true 24px row, shrink the type in that container
  • A surface padding in between: set --ds-surface-padding (shared by ds-card and ds-stat ) at :root
