What density rewrites

  • Hit targets - --hit-cozy (all tiers), --hit-min (ultra-compact)
  • Checkbox / radio size, switch geometry
  • Avatar default size, badge dot size, status dot size
  • Sidenav width
  • Segmented control button height
  • Field, table-cell and surface padding (--ds-surface-padding) — ultra-compact only

Choosing density per screen

Density is a screen-level decision, not user-global (the Tweaks panel exposes it only for prototyping). Set [data-density] on the route container, not on <html>. Control size (sm/md/lg) is a separate axis, defaulted by DS_CONFIG.control.size .

A 32px toolbar — use compact, not a per-control pin

data-density="compact" levels a toolbar at 32px - the supported way to get one. Search, input, select, autocomplete, date picker, time picker, multi-select, number stepper and button measure 40px at default and 32px under compact. Set density once on the container instead of pinning --ds-search-height and its siblings per component.

Chip-holding controls (multi-select, autocomplete) set min-height , not height , so they stop following the tier once it drops below the text line. Under ultra-compact they measure 33px and 29px against 24px, since density does not scale type (a 14px font keeps a 19.6px line box); under compact, 33px vs 32px. For a true 24px row, shrink the type in that container too.

Padding follows the tier only at the bottom. compact and comfy leave padding alone; ultra-compact also compresses field padding, table cells and --ds-surface-padding (shared by ds-card and ds-stat ) from 24px to 16px. For a value in between, set that token at :root .
