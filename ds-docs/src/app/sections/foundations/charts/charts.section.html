Reading a value without keeping the pointer still

An inert tooltip cannot be read at high zoom, cannot have its number selected, and cannot be cleared without moving the pointer somewhere else. WCAG 1.4.13 asks for all three, so every chart panel here takes the pointer and Esc closes it. Once cleared it stays cleared until you visit another mark, so pressing Esc to get the panel off the screen actually gets it off the screen.

The panel goes when the pointer does — one left behind sits over the plot you have moved on to. tooltipLingerMs is how long it stays after the pointer leaves, and it is 0 . Raise it only where a panel holds something to REACH — a link, a figure, a selectable string — which is what WCAG's hoverable clause is about; the built-in panel is one line of text and has nothing in it to reach. The panel is portaled out of the chart, so crossing the gap to it at an ordinary pointer speed takes about 140 . Set it per chart, or on DS_CONFIG.chart.tooltipLingerMs for an app whose tooltips all carry one.

pinOnClick goes further on all five charts: clicking a mark holds it, its tooltip, and — with dimOthers — the dimming of everything else, so a comparison survives the pointer leaving the chart entirely. Esc or a press outside releases it, and the click output fires either way, because pinning is a state rather than a handler. On ds-line-chart the pin hangs off the data markers, so Enter and Space pin from the keyboard too.

The frame a chart draws around itself

A chart draws its own bordered, padded box by default, because it is read as an object — a plot with axes, a legend and an annex table — and without an edge those parts run into whatever sits beside them. Inside a card the page has already drawn, that is a second box around the first. frame="none" turns it off for one chart; DS_CONFIG.chart.frame turns it off for an app, which is where the decision usually belongs — whether charts live in cards is settled once per product, not per plot.

frame = auto (default)
frame = none

The --ds-chart-frame-* tokens still size the frame when it is on. Reaching for them to switch it OFF is the thing the input replaces: a rule against a component's own chrome from a global sheet.

What a chart says to a screen reader

A path and a set of arcs describe nothing one mark at a time, so a chart does not expose its marks — it carries ONE generated sentence: its caption, then each series with its readings, then a pointer to the annex table when one is rendered. The plot wears that sentence as its accessible name and the marks are closed off behind it. caption is the visible title and feeds that sentence; the table beneath carries the numbers themselves.

summary replaces the generated sentence outright, on all five charts. Reach for it where the generated one is true and useless — forty categories read out one by one, or a plot whose point is a shape rather than its values ("Conversion falls sharply after the third step"). Leave it alone otherwise: the generated sentence follows the data, and a hand-written one goes stale the moment the numbers change.

App-wide chart defaults

Six things are the same decision for every chart in an app rather than a choice per plot, so they resolve through DS_CONFIG : valueFormat (a number reads one way in a product, and a formatter passed per chart drifts as soon as there are two screens), dataTable (whether the numbers behind a plot have a non-visual route is an accessibility policy), frame (whether charts live inside cards), tooltipLingerMs (a property of what the app puts in its tooltips), and the emptyText / errorText copy. Precedence is the input, then the config, then the built-in default — so binding one on a single chart still wins. 

providers: [
  provideDsConfig({
    chart: {
      valueFormat: (value) => value.toLocaleString('de-DE'),
      dataTable: 'visible',
      frame: 'none',
      tooltipLingerMs: 140,
      emptyText: 'Нет данных',
      errorText: 'Не удалось загрузить',
    },
  }),
]
