Three layers: raw ramps → semantic role tokens (surface, border, text, status) → component tokens. Components only consume role tokens, so a brand re-skin propagates without code changes.

Secondary role

The --secondary family is the DS's secondary colour role — a complementary tone for non-interactive emphasis (active rails, decorative indicators, accent pills). It defaults to the orange family, distinct from --primary ; override --secondary-h/s/l to reskin it. Secondary is not a second CTA — primary action stays on --primary . Opt-in adoptions: <ds-tabs class="secondary"> , <ds-status-dot [style.--ds-status-dot-color]="'var(--secondary)'"> , sidenav active rail, stat delta neutral.

Switching the focus style brand-wide

Fields take a halo (--ds-field-focus-shadow); everything else takes a --focus-ring-width outline in --focus-ring-color. Set data-focus on <html> to change it everywhere: ring gives fields the double ring, edge makes both flush (offset 0, 1px field ring). Omit it and nothing changes.

Anything focusable that styles nothing itself still gets a ring: focus.emit-rules emits :where(:focus-visible) with the outline at zero specificity, so a component rule or your own CSS out-ranks it. Without it a close button in ds-alert, a link in projected content or your own <button> falls back to the browser's outline: auto.

Building a ringed shell: silence the one control inside

A composite that rings on :focus-within (field box, segmented row, toolbar cell) must turn the base outline off on its one inner control, or two rings show. Name that control, never the whole box: a box-wide reset also removes the ring from inner tab stops (clear button, password toggle, stepper), a WCAG 2.4.7 failure. The DS shells use focus.owns-the-focus-ring($control) or focus.ring-for($control).

Under forced-colors every focused element gets a CanvasText outline, because Windows High Contrast drops box-shadow, so the silencing rule stays out of that mode. Consumers who @use the DS partials à la carte need @use 'styles/focus' as focus; and then @include focus.emit-rules; in their one global stylesheet to get these rules; the bundled styles/ds entry already includes them.

A clipping ancestor eats the ring: data-focus="inset"

Every style above draws outside the border box, so an ancestor with overflow: hidden (a ds-card with padding="none" clipping a full-bleed child) cuts the indicator away. inset pulls the control outline inside (negative offset) and turns the field halo into an inset double ring.

It is the one style not pinned to <html>: put it on the clipping element and everything inside inherits it. Tab into both wells to see it.
