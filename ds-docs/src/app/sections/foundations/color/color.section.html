Three layers: raw ramps (50–950) → semantic role tokens (surface, border, text, status) → component tokens. Components only consume role tokens, so a brand re-skin propagates without code changes.

Secondary role

The --secondary family is the DS's secondary colour role — a complementary tone for non-interactive emphasis (active rails, decorative indicators, accent pills). Defaults at :root alias --secondary to --primary so unbranded apps render unchanged; per-brand overrides introduce a true secondary hue. Secondary is not a second CTA — primary action stays on --primary. Opt-in adoptions: <ds-tabs class="secondary">, <ds-status-dot [style.--ds-status-dot-color]="'var(--secondary)'"> , sidenav active rail, stat delta neutral.

Switching the focus style brand-wide

The two families above are the default split — a soft halo on fields, a crisp double ring on controls. Set data-focus on <html> to change it everywhere at once: ring puts the double ring on fields too, field puts the halo on controls, edge is a hairline flush against the element, and outline swaps the shadow for a real outline. Omit the attribute and nothing changes. It works because 20 components already resolve through the --ds-field-focus-shadow / --ds-control-focus-shadow roles, so the switch only has to retarget two roles rather than reach every component.

Anything focusable that styles nothing itself still gets a ring. The library emits one base rule — :where(:focus-visible) with --ds-control-focus-shadow — at zero specificity, so a component rule and your own CSS both out-rank it. Without it a close button inside ds-alert, a link in projected content, or a plain <button> of yours fell through to the browser default, which in Chrome is a black outline: auto — visibly foreign beside the DS ring. Audited across the docs: 247 focusable elements on one page, none left without an indicator.

Building your own ringed shell? Silence the control inside — and name it

The base rule is a box-shadow, so outline: 0 cannot cancel it. If your composite control paints a ring on :focus-within — a field box, a segmented row, a toolbar cell — the element inside it still gets the base ring, and the result is two: a tight one on the control and the halo on the box. This is the trap the DS itself fell into twice, in ds-input and ds-textarea, both found by measuring in a browser rather than by reading the styles.

Silence one named control, never the whole box. A box-wide reset also hits the tab stops living inside — a clear button, a password toggle, a stepper arrow — and then tabbing from the field to that button changes nothing on screen, so a keyboard user cannot tell what has focus. That is a WCAG 2.4.7 failure, and it is the same defect seen from the other side. The DS ships focus.owns-the-focus-ring($control) for its own shells and fails its build when one is missing.

outline is the one style that also emits a rule, because an outline cannot be carried by a box-shadow token; it is written at zero specificity with :where() so a component or your own CSS still wins. Separately, and regardless of which style is set: under forced-colors every focused element gets a CanvasText outline, because Windows High Contrast DROPS box-shadow and a shadow-only indicator disappears there completely. Consumers who @use the DS partials à la carte need @use 'styles/focus' to get either; the bundled styles/ds entry already includes it.

A clipping ancestor eats the ring — data-focus="inset" is the answer

Every style above draws OUTSIDE the border box, so an ancestor with overflow: hidden cuts the indicator away and leaves the element focusable with nothing to see. That ancestor is not exotic: clipping a card is how a full-bleed child stays inside a rounded corner, and ds-card with padding="none" invites it. inset draws the same two rings INSIDE the box instead, where nothing can clip them.

It is the one style not pinned to <html>. A clip is local, so put the attribute on the clipping element and the two roles inherit into everything below it — Tab into both wells to see it. Setting it brand-wide would move every ring inside its control, which is a different look, not a fix.
