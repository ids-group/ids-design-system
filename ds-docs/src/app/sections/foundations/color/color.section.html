Three layers: raw ramps (50–950) → semantic role tokens (surface, border, text, status) → component tokens. Components only consume role tokens, so a brand re-skin propagates without code changes.

Secondary role

The --secondary family is the DS's secondary colour role — a complementary tone for non-interactive emphasis (active rails, decorative indicators, accent pills). Defaults at :root alias --secondary to --primary so unbranded apps render unchanged; per-brand overrides introduce a true secondary hue. Secondary is not a second CTA — primary action stays on --primary . Opt-in adoptions: <ds-tabs class="secondary"> , <ds-badge variant="secondary"> , sidenav active rail, stat delta neutral.

ds-card — CSS override

No dedicated variant. If a consumer needs an accent stripe, style it inline — single-rule override, no new API surface:

<ds-card style="border-top: 3px solid var(--secondary)">

All adoptions are opt-in (use a class or variant input). Default theme aliases --secondary to --primary so unbranded apps see no visual difference. Under [data-brand="manage-my"] , --secondary is Coral (#FF6156) — these examples then render in the brand accent.
