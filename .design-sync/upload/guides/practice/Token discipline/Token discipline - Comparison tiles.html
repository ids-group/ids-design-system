Token discipline - comparison tiles

The six recurring cases. Each pair shows the value a component should write next to the value it should never write.

Spacing

Density change or rebrand should propagate without code edits.

Good 
padding: var(--space-2) var(--space-3);
Bad 
padding: 8px 12px;

Colours

Dark mode and theme swaps work through semantic roles — literals bypass the contract.

Good 
color: var(--text-secondary);
border-color: var(--border-default);
Bad 
color: #555;
border-color: #ccc;

Radii

Sharp-vs-soft rebrand requires every radius configurable from one place.

Good 
border-radius: var(--radius-md);
Bad 
border-radius: 12px;

Borders

Width and colour both move through tokens — keeps the system coherent under hi-DPI.

Good 
border: var(--border-width-default) solid var(--border-default);
Bad 
border: 1px solid #ddd;

Typography

The type ramp is governed centrally — a one-line edit re-tunes every component.

Good 
font: var(--font-weight-medium) var(--font-size-m)/var(--line-height-base) var(--font-sans);
Bad 
font: 500 16px/1.5 -apple-system, sans-serif;

Motion

Motion taste varies per client; one set of curves keeps the product feeling like one product.

Good 
transition: opacity var(--duration-fast) var(--ease-standard);
Bad 
transition: opacity 200ms cubic-bezier(.4, 0, .2, 1);
