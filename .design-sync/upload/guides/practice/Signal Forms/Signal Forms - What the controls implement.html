Signal Forms - what the controls implement

Signal forms binds these by input NAME, so a control takes part in whichever of them it happens to expose. This is the measured state, not the intended one.

value / checked bound The one required member of the contract. Every DS control already exposes it as a model(), which is why binding works without an adapter.
disabled bound A disabled() rule disables the control and its inner element.
readonly bound Text controls only — input, textarea, select. The DS also spells it readOnly for hand-binding; either sets it.
hidden bound A hidden() rule removes the control from the layout. Every control that carries a value accessor has it.
required bound Drives the required marker beside the label and the native attribute.
errors / touched bound Errors show once the field is touched, so a required error does not greet an untouched form. Give the validator a message or map the kind — see below.
invalid bound Applies the error styling and sets aria-invalid.
min / max / minLength / maxLength / pattern bound Forwarded to the native element as attributes on input and textarea; min and max also bound on the number stepper.
focus() bound focusBoundControl() reaches the control that actually holds the value — the stepper’s number box rather than its minus button, the tabbable radio rather than the first one, a picker’s trigger rather than an input inside its closed panel.
dirty / pending / disabledReasons not yet Not implemented, and blocked on a visual decision rather than wiring: nothing in the library renders "edited" or "validating" today, so there is no established look to bind these to.
