Form layout - validation & messages

Layout is only half a form — this is when feedback appears and where it goes. These rules keep the happy path unblocked and errors legible.

  • Gate submit on presence + not-in-flight only, never on format validity — a half-typed email must not disable the button, or the user faces a dead control with no explanation.
  • Judge validity inside the submit handler; that attempt is what reveals the messages. An early return from the handler that renders nothing is the silent-no-op bug.
  • Field errors live in the field's own message row. On a form that validates, turn on reserveMessage — off by default — so the first error does not shift the controls below it, and stack those fields with <ds-stack gap="none"> , since a reserved row already carries ~23px of trailing rhythm. Whole-request failures go in a ds-alert after the submit button — an error region above the inputs pushes every control down.
  • A rule checklist must change its icon, not only its colour — colour alone fails colour-blind users and forced-colors mode.
