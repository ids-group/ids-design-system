Form layout - validation & messages

  • Submit is enabled until the first error: before the first submit the button is live and no error shows, not on blur, not while typing.
  • Check validity in the submit handler; a failed attempt shows the errors inline, focuses the first invalid field and disables the button while the form stays invalid. An early return that renders nothing is a silent no-op.
  • From then on validation is live until the form is reset: a fix enables the button at once, a new error disables it at once, with no second submit.
  • [disabled]="submitted() && invalid()" , with submitted = signal(false) set at the start of the submit handler and reset with the form.
  • In flight: [loading], never the loading flag inside [disabled]; a loading button keeps focus and blocks presses.
  • Field errors go in the field's message row; on validating forms turn on reserveMessage so the first error shifts nothing: [reserveMessage] > form dsReserveMessages > DS_CONFIG.field.reserveMessage > false
  • Stack reserved fields in <ds-stack gap="none"> : a reserved row carries ~23px of trailing rhythm
  • Whole-request failures go in a ds-alert after the submit button, not above the inputs.
  • A rule checklist changes icon, not only colour: colour alone fails colour-blind users and forced-colors mode.
