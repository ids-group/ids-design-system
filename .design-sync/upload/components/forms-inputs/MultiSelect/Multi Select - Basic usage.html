Multi-select - basic usage

<MultiSelect />

Chip-based multi-value selector with search filtering, keyboard navigation, and optional overflow collapse. For a set too large to scan — where typing is how you narrow it — reach for autocomplete instead; this one shows the options as a checkbox list, so a reader sees the whole choice at once and what is not selected.

Chips expand horizontally; all selected values are always visible. [selectAll] adds a row that toggles every filter-matching option at once (shows an indeterminate state on a partial selection).

error string '' Error text. Shown immediately — binding it says the consumer has already decided this is in error. Takes precedence over `errors`.
warning string '' Advisory text, shown when there is no error.
reserveMessage boolean | null null Reserve the message-row height even when empty, so the control doesn't shift the layout below it when a hint/error appears. Falls back to `DS_CONFIG.field.reserveMessage`, then off.
messageIcon IconName | false | null null Glyph on the message line, overriding what the state resolves to. Unset follows `DS_CONFIG.field.stateIcons`; `false` removes the glyph here alone.
errors readonly DsFieldError[] [] Validation errors, shown once the user has interacted. Bound automatically by signal forms; reactive and template-driven forms are read through `NgControl` and need nothing here. Accepts a string, one error, or an array.
invalid boolean false Paints the error state and sets `aria-invalid`, WITHOUT a message of its own — for when the text lives elsewhere, such as a form-level error summary or one message covering a whole field group. Use `error` to show text.
touched boolean false Whether the user has interacted with the field. Bound by signal forms; gates `errors`, so a `required` error does not greet an untouched form.
hidden boolean false Hides the control. On the base so signal forms reaches every control at once. Inline `display`, not the `hidden` attribute — each control sets its own `:host` display, which the attribute's weaker UA rule would lose to.
value two-way string[] [] Selected values, two-way bound.
options readonly MultiSelectItem[] [] Options, groups, or both mixed — rendered in the order given.
placeholder string 'Select…' Placeholder shown in the trigger when nothing is selected.
searchPlaceholder string 'Filter…' Placeholder for the in-panel filter input.
searchable boolean | number | null null Whether the panel carries a filter row. `true` always, `false` never, and a NUMBER is a threshold — the row appears once there are at least that many options. Unset falls back to `DS_CONFIG.picker.searchable`, then `true`. Hiding it moves the panel's keyboard model onto the trigger: the arrows, Enter, Escape and `aria-activedescendant` are the filter input's today.
name string | null null Native `name` attribute forwarded to the trigger.
readOnly boolean false Prevents opening the panel while still allowing focus.
readonlyBinding boolean false The contract spelling of `readOnly`, a second input because signal forms binds by NAME — a `readonly()` rule was reaching nothing before this existed.
clearable boolean false Shows a clear affordance once there is something to clear.
filterWith ((option: MultiSelectOption, query: string) => boolean) | 'none' (option, query) => option.label.toLowerCase().includes(query) How the typed query narrows the list. The default matches a case-insensitive substring of `label`. Pass a predicate to match on anything else — a second field, ignoring diacritics, a fuzzy score. Pass `'none'` when the list arrives already filtered, which is what a server-side search needs: the query is reported through `filterChange` and every option given is rendered.
loading boolean false Options are still being fetched. The panel shows a spinner instead of the empty row — which would otherwise claim there are no matches — and the list reports `aria-busy`.
scrollActiveIntoView boolean true Scrolls the keyboard cursor's row into view. On by default: a list longer than the panel otherwise walks the cursor out of sight. Set `false` only if you are driving the scroll position yourself.
maxVisibleChips number | 'fit' | 'all' | null null How the chips collapse when they outgrow one line. `"fit"` (the default) measures and shows as many as the trigger is wide, the rest behind "+N more". A NUMBER is a CEILING, not a promise: the row still measures, so you get at most that many and fewer when the trigger is narrow. `"all"` shows every chip and lets the trigger grow a line per selection. Unset (`null`) means "not deciding", as it does on every other input in the library — it resolves to `"fit"`. It does NOT mean "show all": that is `"all"`, which is the loudest of the three modes and has to be asked for.
disabled boolean false Disables the trigger and blocks all interaction.
success string '' Confirmation text, shown when there is no error or warning — and it paints the field's success border. A string like `warning`: the text IS the state.
ariaLabel string | null null Accessible name for the trigger — falls back to `placeholder`.
width fill content 'fill' Trigger width — `fill` stretches to the container and pins the panel to the trigger's width; `content` hugs the trigger's own content and takes that width as the panel's FLOOR, so a compact trigger does not force an unreadable panel.
size sm md lg null Trigger height — sm/md/lg. Unset falls back to `DS_CONFIG.control.size`, then `'md'`.
triggerDisplay full count labels 'full' What the trigger shows. `count` is a caption plus a selected-count badge at intrinsic width; `labels` names the selection instead, cut to the width with the rest behind "+N". A projected `dsPickerTrigger` template WINS over this — the input is then not read at all.
label string '' Field label above the control — the same meaning it has on `ds-select`, and the caption a `count`/`labels` trigger uses when it needs one.
required boolean false Marks the field required: a `*` beside the label and `aria-required` on the trigger.
optional boolean false Marks the field optional in words, for a form where most fields are required.
selectAll boolean | 'group' | 'both' false Where a "select all" row appears. `false` nowhere, `true` one row over the whole panel, `'group'` one row per group, `'both'` for either. Group rows need groups in `options` — with a flat list they have nothing to head.
Outputs 3
Name Type Emits Description
filterChange string event The query the user typed, on every change. The input for a server-side search; pair it with `filterWith="none"` so the list is not narrowed twice.
opened void event The panel opened. The moment to fetch options for a picker whose list is loaded on demand.
closed void event The panel closed, for any reason — a pick, Escape, an outside click, a scroll.
