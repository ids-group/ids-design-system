Name Type Default Description
hint string '' Helper text shown below the control.
error string '' Error text. Shown immediately — binding it says the consumer has already decided this is in error. Takes precedence over `errors`.
warning string '' Advisory text, shown when there is no error.
reserveMessage boolean | null null Reserve the message-row height even when empty, so the control doesn't shift the layout below it when a hint/error appears. Falls back to `DS_CONFIG.field.reserveMessage`, then off.
messageIcon IconName | false | null null Glyph on the message line, overriding what the state resolves to. Unset follows `DS_CONFIG.field.stateIcons`; `false` removes the glyph here alone.
errors readonly DsFieldError[] [] Validation errors, shown once the user has interacted. Bound automatically by signal forms; reactive and template-driven forms are read through `NgControl` and need nothing here. Accepts a string, one error, or an array.
invalid boolean false Paints the error state and sets `aria-invalid`, WITHOUT a message of its own — for when the text lives elsewhere, such as a form-level error summary or one message covering a whole field group. Use `error` to show text.
touched boolean false Whether the user has interacted with the field. Bound by signal forms; gates `errors`, so a `required` error does not greet an untouched form.
hidden boolean false Hides the control. On the base so signal forms reaches every control at once. Inline `display`, not the `hidden` attribute — each control sets its own `:host` display, which the attribute's weaker UA rule would lose to.
value two-way string '' Text value, two-way bound.
type text email password number tel url search 'text' Native input type — also affects the default clear button and password toggle.
size sm md lg null Field height — sm/md/lg. Unset falls back to `DS_CONFIG.control.size`, then `'md'`.
label string '' Label shown above the field.
placeholder string '' Placeholder shown when empty.
disabled boolean false Disables the field and blocks all interaction.
readOnly boolean false Prevents editing while still allowing focus and selection.
readonlyBinding boolean false The contract spelling of `readOnly`, a second input because signal forms binds by NAME — a `readonly()` rule was reaching nothing before this existed.
success string '' Confirmation text, shown when there is no error or warning — and it paints the field's success border. A string like `warning`: the text IS the state.
loading boolean false Shows a trailing spinner — e.g. async validation in flight. The input stays editable; pair with a `hint` like "Checking availability…".
required boolean false Marks the field required — shows an asterisk and sets `aria-required`.
optional boolean false Shows an "(optional)" marker next to the label (ignored when `required`).
name string | null null Native `name` attribute.
min number | null null Native `min` attribute — applies when `type="number"`.
max number | null null Native `max` attribute — applies when `type="number"`.
step number | null null Native `step` attribute — applies when `type="number"`.
autocomplete string | null null Native autocomplete token (e.g. "email", "current-password").
autofocus boolean false Focuses the field automatically on render.
ariaLabel string | null null Accessible name when no visible `label` is provided (falls back to the placeholder so the control is never unnamed).
ariaDescribedBy string | null null Extra element ids to describe the control with — a password-rule list, a policy note. MERGED with the field's own message id rather than replacing it, and it has to be an input because the attribute belongs on the inner `<input>`: set on the host it lands on a wrapper no screen reader reads.
maxLength number | null null Hard character cap — applies the native maxlength attribute and shows a live "{current}/{max}" counter below the field.
minLength number | null null Native `minlength` attribute.
pattern readonly RegExp[] [] Native `pattern` attribute — signal forms sends the schema's RegExp list.
enterKeyHint enter done go next previous search send null Mobile keyboard hints — forwarded to the native input as attributes.
inputMode none text decimal numeric tel search email url null Native `inputmode` attribute — hints the on-screen keyboard layout.
clearable boolean | null null Show an inline clear (×) button when the input has a non-empty value. Mirrors the Material/PrimeNG pattern: explicit button (not native search cancel) so the affordance is consistent across browsers and styled with DS tokens. Defaults to true when type='search', false otherwise — pass an explicit boolean to override.
passwordToggle boolean false Shows a show/hide button when `type="password"`.
passwordVisible two-way boolean false Whether the password is currently shown as plain text, two-way bound.
