Name Type Default Description
hidden boolean false Hides the control, as every other DS control does. Inline `display`, not the attribute: the host sets its own, which the weaker UA rule would lose to.
value two-way string '' Search text, two-way bound.
placeholder string 'Search' Placeholder shown when empty.
shortcut string '' Keyboard shortcut hint rendered in a trailing `<kbd>` badge.
showIcon boolean true Shows the leading search icon.
clearable boolean false Show an inline clear (×) button on the right when there's a value.
ariaLabel string '' Accessible name for the input (placeholder is not a reliable label).
disabled boolean false Disables the input and the clear button.
size sm md lg null Control height. `md` (default) keeps the 36px search-row height; `sm` (32px) aligns search with dense toolbars beside `sm` inputs/buttons; `lg` is touch. Unset falls back to `DS_CONFIG.control.size`, then `'md'`.
debounce number 0 Milliseconds to hold each keystroke back before `value` updates — 0 (default) writes on every keystroke, exactly as this control always has. Clearing the field BYPASSES the delay, which is the part a plain `debounceTime` gets wrong: emptying a search is a deliberate act, and making the user wait 200ms to see the full list back reads as a hang. Enter flushes for the same reason. What the input SHOWS is never delayed.
