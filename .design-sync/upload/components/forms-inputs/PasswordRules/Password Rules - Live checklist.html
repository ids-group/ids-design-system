Password rules - live checklist

<PasswordRules />

Live requirement checklist under a new-password field.

Each row carries its own predicate, because the POLICY has to mirror your server — the component owns the tri-state glyph, the colours and the type scale, nothing else. A rule that is not yet met reads as pending — an empty circle , the unticked counterpart of the check it becomes — fills into that check when it passes, and only becomes a failure once [showUnmet] is true — bind that to "the user has tried to submit", or a half-typed password scolds someone who is still typing.

Inputs 5
Name Type Default Description
value string '' The password being typed.
rules readonly DsPasswordRule[] [] The rule set, in the order it should read.
showUnmet boolean false Whether an unmet rule may read as FAILED. Bind it to "the user has tried to submit": before that an unmet rule is merely pending, because marking a half-typed password with errors scolds someone who is still typing.
columns 1 | 2 1 Lay the rows out in two columns — for a checklist beside a wide form.
listId string nextControlId('ds-password-rules') Id put on the rule list, for the field's `aria-describedby`. Defaults to a generated one; set it explicitly and both sides can name the same string, which avoids threading a template ref between two siblings.
