Two axes: color (brand/status hue family) × variant (solid · tonal · outline · ghost). Loudness is the variant (solid > tonal > outline/ghost); colour is orthogonal. Plus sizes, states, leading icon, subtext, full-width and toggle. For icon-only actions see the Icon button component; for a link-styled action use the global .link class on a button.

Every color × variant combination — all of them render. Defaults are color="primary" variant="solid" . Cells marked ⚠ are UX-discouraged: they work (and emit a dev-mode warning), but read poorly — grey solid looks disabled; quiet success/warning (outline/ghost) is too low-contrast — prefer solid/tonal there.

The whole text column is marked ⚠ on purpose: variant="text" is a no-chrome, underlined, link-styled button, which is exactly what the global .link class already gives any <a> /<button>. For a link-styled action prefer .link (lighter, no component) — reach for variant="text" only when you genuinely need the ds-button API on a link look (loading, fullWidth, the typed (pressed) output, leading/trailing icons). It's kept, not removed — just not the default choice.

secondary and tertiary are brand hue roles , not fixed colours — they ship distinct default hues (a warm orange, a cool violet), independent of --primary , so the three brand rows read apart out of the box. Changing --primary alone won't recolour them — a brand reskins each by overriding --secondary-h/s/l / --tertiary-h/s/l .

Name Type Default Description
hint string '' Helper text shown below the control.
error string '' Error text. Shown immediately — binding it says the consumer has already decided this is in error. Takes precedence over `errors`.
warning string '' Advisory text, shown when there is no error.
reserveMessage boolean | null null Reserve the message-row height even when empty, so the control doesn't shift the layout below it when a hint/error appears. Falls back to `DS_CONFIG.field.reserveMessage`, then off.
messageIcon IconName | false | null null Glyph on the message line, overriding what the state resolves to. Unset follows `DS_CONFIG.field.stateIcons`; `false` removes the glyph here alone.
color primary secondary tertiary neutral error success warning 'primary' Brand/status hue family.
variant solid tonal ghost outline text 'solid' Fill pattern: solid | tonal | ghost | outline | text. All color×variant pairs render; some are UX-discouraged and emit a dev-mode warning naming the reason — they work, but read poorly. `text` is discouraged for ALL colours — prefer the global `.link` class; it stays for cases needing the ds-button API (loading/fullWidth/typed pressed).
size sm md lg null Button height — sm/md/lg. Unset falls back to `DS_CONFIG.control.size`, then `'md'`.
type button submit reset 'button' Native `<button>` `type`; defaults to `'button'` (not `'submit'`) so it never submits an ancestor form by accident.
disabled boolean false Disables the button and blocks `pressed`.
loading boolean false Busy state — disables interaction and sets `aria-busy`.
fullWidth boolean false Stretch the button to fill its container — the host becomes block-level and 100% wide (the inner control is already full-width). Use for mobile primary CTAs and full-bleed form submit buttons.
ariaLabel string | null null Accessible name — forwarded to the inner <button> as aria-label. Use when the visible label is absent or non-descriptive.
icon IconName | null null Leading icon, before the projected content.
trailingIcon IconName | null null Trailing icon, after the projected content.
ariaHasPopup true menu listbox tree grid dialog null ARIA `aria-haspopup`, forwarded to the inner <button> — set when this button triggers a menu/dialog/listbox overlay.
ariaExpanded boolean | null null ARIA `aria-expanded`, forwarded to the inner <button> — bind to the overlay's open state on a trigger button.
ariaControls string | null null ARIA `aria-controls`, forwarded to the inner <button> — the id of the panel this button opens, e.g. `ds-app-layout`'s `railId`.
disabledReason string '' Why the button is refused, shown as its second line. Read only while `disabled` — a greyed control that does not say why is a dead end. Setting it also changes HOW the button is disabled: it takes `aria-disabled` instead of the native attribute, because a natively disabled button cannot be focused and the reason would never be announced. The click is swallowed in `onClick` instead. Leave it unset and nothing changes. Length is deliberately not capped: the text wraps and the button grows. Same name and meaning as `TableRowAction.disabledReason`.
ariaDescribedBy string | null null ARIA `aria-describedby` — point the button at a description the app renders itself, such as a `ds-field-message` under a form. Merged with the id of `disabledReason` when both are present.
