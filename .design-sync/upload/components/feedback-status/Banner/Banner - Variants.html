Banner - variants
Truncation
  • Title Single line, ellipsis at row width. Tooltip on hover when clipped.
  • Body Wrap, no clip. No clamp — banners are page-level and must stay fully readable.
  • Inline link in body Wraps with the body text. Underlined; never clipped.
  • Dismiss icon Always visible. Never overlapped by title or body — body min-width: 0 keeps wrap correct.

<Banner />

Inline page-level message. Six severities — info, success, warning, severe, error, neutral — each with a default icon, optional title, and optional dismiss control.

Every banner severity as a permanent specimen.

Inputs 8
Name Type Default Description
variant info success warning severe error neutral 'info' Severity — drives colour, the default icon and the ARIA role/live.
title string '' Optional bold heading above the message.
dismissible boolean false Show a close button that emits `closed`.
icon IconName | null null Override the variant's default icon.
compact boolean false Tighter padding, centred items, single-line title.
layout stacked row 'stacked' `'stacked'` wraps actions onto their own line; `'row'` keeps them inline.
accentRail boolean true Coloured accent rail on the leading edge; set false to hide it.
announce boolean false Announce this banner to a screen reader when it appears. Off by default: an `alert` region fires on INSERTION, so a banner that is page furniture would interrupt the reader on every route into the page. Turn it on for one the app raises in response to an event; for anything transient prefer `ToastService`, which owns a live region built for the purpose.

Name Type Emits Description
closed void event Fires when the user dismisses the banner.
