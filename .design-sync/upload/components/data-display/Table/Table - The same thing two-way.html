sortKey and sortDir each have a matching Change output, so [(sortKey)] and [(sortDir)] work: the table writes the host's state and the host reads it back, with no handler to write. Below is the demo above with the handler deleted and nothing else changed.

What you give up is the third click. Clearing a sort sets sortDir to null and the rows come back unsorted, because there is nowhere left to say "then fall back to Owner descending". Prefer two-way where any sort state is equally valid — a saved view, a URL you round-trip — and the one-way pair plus (sortChange) where the host owns a default it has to be able to restore.
