'overlay' — re-fetch indicator; existing rows stay visible behind a translucent overlay with a centred spinner. Pin either one only to override the rule deliberately.

'ascending' : 'descending'}` : `Sorting cleared` Wording for the sort announcement, so it can be translated. Receives the column's label and the new direction; return an empty string to say nothing.

Off by default so non-navigating tables don't advertise a false click affordance. Also the gate for the hover/pressed row tints.

reorderableColumns boolean false Enables drag + up/down reordering in the column panel.
columnOrder two-way string[] | null null Two-way column order as a list of keys. `null` (default) keeps declaration order; the column panel owns it once the user reorders. Keys absent from the list fall back to declaration order after the listed ones.
persistLayout boolean false Round-trip `columnOrder`, `columnWidths` and `hiddenKeys` through `localStorage`, so a reader's column layout survives a reload. Needs `storageKey` — without one there is nothing to key a screen by, and two tables would overwrite each other. Off by default.
storageKey string '' Screen id the persisted layout is stored under. Pick something stable per table, not per route instance.
exportButton boolean false Render an export button in the table's toolbar row. Off by default. Leave it off and drive `runExport()` from your own button — in a page header, a filter bar, the `[toolbar]` slot — reading `exporting()` for its loading state.
exportFilename string 'table.csv' Filename the export button downloads as.
exportFetcher (() => Promise<readonly T[] | Blob | string>) | null null Where the export button gets its data. A server-paged table only HAS the current page, so exporting without this silently exports one page. Return ROWS and the table serializes them the same way it serializes its own. Return a `Blob` (or a URL string) and the table just downloads it — which is what you want when the backend already formatted the file with its own number formats, its own columns, or a sheet the table never held.
stickyScrollbar boolean | null null Keeps the horizontal scrollbar reachable on tall tables: the scroll container's native bar is hidden and a proxy stuck to the bottom of the nearest scroll ancestor mirrors it both ways. Off by default. Unset falls back to `DS_CONFIG.table.stickyScrollbar`, then `false`.
pageSize two-way number | null null Rows per page. `null` (default) disables pagination — all rows render.
page two-way number 1 Current 1-based page. Only meaningful when `pageSize()` is set.
pageSizeOptions number[] [10, 25, 50, 100] Selectable page-size choices shown in the pagination control.
showPageSize boolean true Shows the page-size picker in the footer pager. Set false for a table whose page size is fixed — the standalone `ds-pagination` has always taken this.
showLabel boolean true Shows the "N of M" range label in the footer pager.
total number | null null Server-side total row count. `null` (default) = client paging: the table slices `data()` itself and the pager counts the rows in hand. When set, the host has already sliced to one page — the pager uses this count and the table renders `data()` as-is (no internal slice).
scrollToTopOnPageChange boolean false Scroll the table into view on a page change (opt-in) — keeps a bottom pager from leaving the viewport on the previous page's last rows.
sortMode client server none null Who sorts — see `TableSortMode`. Unset resolves to `'server'`: the table emits `(sortChange)` and reorders nothing, which is what a paged table needs. Declare `'client'` when the table holds every row, or `'none'` to drop the affordance entirely.
filterMode client server none null Who filters — see `TableFilterMode`. Unset resolves to `'server'`: the table tracks the selection in `columnFilters` for the host to turn into a request, and runs no local pass. Declare `'client'` when the table holds every row and should filter them itself.
columnFilterOptions ReadonlyMap<string, readonly string[]> new Map() The full value domain per column key, for a header filter the table cannot derive itself. Without it the checklist is built from the rows in hand, which on a server-paged table offers only the values that happen to be on the current page.
stickyFirstColumn boolean false Pin the first data column (and the select column) on horizontal scroll.
virtualScroll boolean false Render only the rows in view, padding the rest with two spacer rows. Opt-in, and it needs `maxHeight` — without a bounded scroller there is no viewport to window against, so nothing is virtualized (dev-warned). Every row must be the same height, which is `virtualRowSize`: the arithmetic that decides what is in view has no other way to know where a row starts. So virtual mode forces `table-layout: fixed` and single-line cells, and the expansion panel is suppressed — a row that can grow breaks the maths.
virtualRowSize number 44 Row height in px in virtual mode. Must match what the rows actually measure, so it drives the CSS height rather than merely describing it.
lazy boolean false Fetch rows as they scroll into view instead of receiving them all. `data` becomes a SPARSE array `total` long: put each fetched row at its absolute index and leave the rest empty. Every gap inside the window renders a skeleton row, and `(lazyLoad)` asks for the range covering it. Needs `virtualScroll` — without a window there is nothing to load lazily AGAINST — and `total`, which is what the scrollbar is sized from.
rowActions readonly TableRowAction<T>[] [] Row-action menu items rendered as a trailing kebab (⋮) column. Empty (default) — no column. Menu clicks never trigger `rowClicked`.
cellTemplateMap Record<string, TemplateRef<{ $implicit: unknown; row: unknown }>> {} Cell templates supplied as an explicit map instead of (or in addition to) projected `dsCellTemplate` directives. Lets a wrapper component collect the directives itself and pass them down, since content projected through a wrapper's `<ng-content>` is not seen by this component's content query. Entries here override projected ones.
emptyTemplate TemplateRef<unknown> | null null Empty-state template, as an alternative to the `[empty]` content slot — again for wrappers that can't rely on slot re-projection.
expandableRows boolean false When true, each row renders a leading chevron button that toggles an inline expansion panel below it.
expandedIds two-way Set<string> new Set<string>() Two-way set of currently expanded row ids.
expandMode multiple single 'multiple' `'single'` collapses the open row when another expander is clicked. Enforced on interaction only: a set seeded with several ids is left alone (and warned about in dev) rather than silently rewritten under the host.
expandAllToggle boolean false Renders an expand-all/collapse-all chevron in the expander column header, page-scoped when paginating, like select-all. Suppressed under `expandMode="single"`, which it would contradict.
rowExpandTemplate TemplateRef<{ $implicit: unknown; row: unknown; }> | null null Template rendered inside an expanded row's panel. Context: `$implicit` = row, `row` = row.
