Auth layout - two-tone wordmark, flat card

<AuthLayout />

The scaffold for the screens in front of the login — counterpart to ds-app-layout , which only ever covers what sits behind it.

Project [dsBrandName] when one slice of the wordmark carries the brand colour. The layout never splits your brand string for you, because a split has to guess where the accent belongs. The tagline is optional, and a flat card suits a canvas that is already tinted.

Inputs 6
Name Type Default Description
brand string | null null Wordmark beside the letter-mark tile. For a logo image/SVG, project it into the `[brand]` slot instead; for a two-tone wordmark use `[dsBrandName]`. Unset falls back to `DS_CONFIG.brand.name`. Each field resolves on its own, so `brand=""` drops the wordmark but a `logoLetter` in the config still paints its tile; clear both to give one screen no brand row.
logoLetter string | null null Letter-mark glyph when it differs from the brand's first letter (e.g. an "A" tile beside the "MyAdmin" wordmark). Empty = first letter of `brand`; unset falls back to `DS_CONFIG.brand.logoLetter`.
tagline string | null null One line under the wordmark naming the product or audience. Unset falls back to `DS_CONFIG.brand.tagline`.
cardElevation flat raised hover interactive 'raised' Card treatment. `flat` suits a screen that already sits on a tinted canvas.
cardPadding none sm md lg 'lg' Card padding, passed through to `ds-card`. `md` tightens a short form.
landmark main none 'none' Announce the card as the page's `main` landmark. `ds-card` renders an `<article>`, which is NOT a landmark, so by default a screen-reader user has nothing to jump to — set `'main'` on a standalone auth page. Opt-in because the layout is also embedded inside pages that already own a `main`, and two `main`s is its own violation.
