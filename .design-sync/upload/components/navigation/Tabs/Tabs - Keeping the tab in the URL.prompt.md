# Tabs - keeping the tab in the URL

Set urlParam and the strip keeps the active tab in a query parameter, so it survives F5, a shared link and the Back button. The input both switches the behaviour on and names the parameter; leave it out and the URL is untouched.

The names come from each tab's value, falling back to a SLUG of its label — kebab, lowercased, diacritics dropped, so "License Verification Status" gives ?tab=license-verification-status rather than a percent-encoded sentence. That is not the identifier tabClosed emits: closing still carries the raw label, because a host matches it against its own list. And a slug is still derived from copy, so renaming a tab still breaks saved links — value is the only fix for that. Three decisions are baked in. Names, not indices: ?tab=1 would silently repoint every old link the moment a tab is inserted. The first tab writes no parameter and every write replaces: a pristine screen keeps a clean address, and flipping tabs does not fill the Back button with entries to walk one at a time. An unknown or missing name lands on the first tab rather than throwing — a URL is user input, and a stale bookmark should still open the screen.

Outside a routed context the input is inert, and a strip that never sets it costs exactly what it did before the input existed: nothing router-shaped is resolved until you set it — no DI lookup, and no subscription to the query parameters. Setting it later switches both on; clearing it drops the subscription again. It also pairs with ds-app-layout — the write is query-only, and that layout's pathChanged ignores query-only navigations, so switching tabs cannot trip its scroll reset. There is deliberately no live demo here: it would write ?tab= into the docs' own address while the sidebar rewrites the path from the scroll position, and the two would read as fighting.

One strip per parameter name. Two ds-tabs sharing a name on the same screen erase each other — both write the same parameter, and a reload restores whichever wrote last. It is the easy mistake to make when turning this on across an app, because "tab" is the obvious name every time, so a dev-mode warning names the clash. Nested or sibling strips need distinct names — tab and subtab.

Full API: `Tabs.d.ts`. How to use the component anywhere: `Tabs.prompt.md`.
