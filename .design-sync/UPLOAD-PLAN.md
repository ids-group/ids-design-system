**The deletions did NOT land, and only Misha can make them.** `delete_files` refuses every path on
this project — one at a time as readily as in bulk:

```
HTTP 403 permission_denied
bulk delete requires project ownership when called without a turn fence;
this project is owned by another user
```

The durable constraint: **`delete_files` only works for the project OWNER.** Removing a stale entry
is not something a collaborator can do from here at all, one path or many, so a rename or a dropped
component leaves its old files behind until the owner deletes them — and a card whose preview script
still names an export the current bundle dropped reads as broken rather than absent. Plan a rename
as "upload the new name, ask the owner to remove the old one".

## Order the tool enforces

```
list_projects → get_project → list_files      # the diff above
finalize_plan { writes, deletes, localDir }   # Stas approves the path list
write_files { planId, files: [{ path, localPath }] }   # max 256 per call
delete_files { planId, paths }
```

`finalize_plan` shows the user the exact write/delete list independent of any narration, and a
path outside it is rejected. Prefer `localPath` over inline `data` so file contents never enter
the model context.

## Before uploading

- `config.json` points at `.design-sync/elements/dist/ds-bundle.js`. The React port was deleted,
  so there is one route and an upload publishes the elements bundle. The bundle has been proved
  to LOAD in a local copy of the host's script chain (React 18.3.1 from `_vendor`, then the
  bundle) — `window.IdsDs` resolves and overlays render their projected content.
- Run the full chain first: `gen.mjs` → `ng build ds-elements` → `build-bundle.mjs`. `gen/` and
  `dist/` are gitignored, so the chain has to run in whichever account performs the upload — a
  build from another checkout does not travel. `bootstrap.mjs` first if `.ds-sync` is absent, and
  `bun install` if `node_modules` predates the `@angular/elements` dependency.
- **Fonts are handled — upload `dist/ds-bundle.css`, not `dist/browser/styles.css`.** Angular emits
  the faces as `./media/*.woff2`, which is correct beside its own output and wrong in the project,
  where the eight files already sit at `fonts/` from the July upload. `build-bundle.mjs` writes an
  upload copy with those URLs rewritten to `fonts/`, so a sync ships one CSS file and no binaries;
  `cssEntry` points at it. Verified 2026-09-01 against a local copy of the project's layout: served
  unrewritten every face 404s, rewritten there are none and the page renders in Mulish.
- **The per-component `<Name>.d.ts` is hand-shaped, not tsc output.** The live `Button.d.ts` opens
  with `Button — from @ids-group-ltd/ids-design-system@0.6.2.` and `@replaces button` — a header no
  compiler can produce — and its unions are inlined flat with no imports. `build-cards.mjs`
  reproduces that shape from `surface.json`; the aggregate `build-bundle.mjs` emits under
  `dist/types/` is a type-CHECK by-product (its first pass found four generator bugs), not the
  artefact that ships.
- The AGENT's compositions must set state as INITIAL props, never toggle it after mount — see
  `COMMANDS.md`. A modal passes `staticPreview`; a table showing `[bulk-actions]` passes
  `selectedIds`. Cards are exempt: a card is an Angular section, not a wrapper composition.
