Icon button architecture — options

standalone artifact · prototypes/icon-button-options.html · research spike for ghost/outline icon-only inconsistency

Проблема: в текущем ds-button варианты ghost и outline ведут себя ОДИНАКОВО в text-режиме (оба с обводкой), но РАЗНО в iconOnly (ghost становится бесхромным, outline держит рамку). Mode-dependent семантика варианта — это «запах». Ниже — проблема и два пути решения. Industry split: Material 3 / Atlassian = отдельный IconButton; Carbon / Polaris / shadcn = режим Button.

Текущее поведение PROBLEM

Один и тот же вариант выглядит по-разному в зависимости от режима. Сравни ghost: слева (text) с рамкой, справа (icon) без рамки.

ghost · TEXT (bordered)
ghost · ICON (chromeless!)
outline · TEXT (bordered)
outline · ICON (bordered)
ghost text ≡ outline text, but ghost icon ≠ outline icon → variant meaning depends on iconOnly. Confusing.

A · Один ds-button, консистентные варианты SMALL CHANGE

Оставляем единый ds-button с iconOnly. Вариант выглядит ОДИНАКОВО в обоих режимах — убираем mode-зависимый override. Для «бесхромной» tool-кнопки заводим явный отдельный вариант (напр. variant="bare" / quiet), а не магию ghost-в-icon-only. Модель Carbon / Polaris / shadcn. Минимум миграции.

primary
ghost (=text ghost)
outline (=text outline)
bare (new, chromeless)
API: <ds-button iconOnly variant="bare|ghost|outline|primary"> — same look as text. No mode-dependent surprises.

B · Отдельный ds-icon-button BIG CHANGE

Выносим icon-кнопки в ds-icon-button со СВОЕЙ таксономией (Material 3): standard (бесхромная), filled, tonal, outlined + [selected] toggle. ds-button теряет iconOnly вовсе. Чистая семантика, но новый компонент + миграция всех [iconOnly] (≈19 мест в field/admin).

standard
filled
tonal
outlined
selected (toggle)
danger
API: <ds-icon-button variant="standard|filled|tonal|outlined" [selected] icon="edit" aria-label="…">
