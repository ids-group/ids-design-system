How the deploy works mirrors the pinkmoon prototype architecture

  1. Build — npm run build:docs produces dist/ds-docs/browser/ with <base href="/"> and relative assets.
  2. Upload — aws s3 sync to s3://ids-prototypes/ids-ds/ (immutable cache for hashed assets, must-revalidate for index.html).
  3. Route — CloudFront maps the ids-ds.proto.ids-group.co.uk host to the /ids-ds S3 prefix, so the app is served at root.
  4. Invalidate — aws cloudfront create-invalidation on the entry point so the new index.html is picked up immediately.
Ask DevOps for, essentially, one thing:

the values of IDS_DOCKER_AWS_ACCESS_KEY_ID / IDS_DOCKER_AWS_SECRET_ACCESS_KEY (if not already workspace-shared), and confirmation of the CloudFront distribution ID that serves ids-ds.proto.ids-group.co.uk. No new bucket, certificate, DNS record or distribution is needed.
