Правило

Хост dsTooltipWhenClipped получает tabindex="0", пока обрезан, если: сам не фокусируемый; вокруг нет нативного контрола (a[href], button, поле), виджетной роли (button, link, tab, option, menuitem, row, gridcell, combobox, checkbox, radio, switch, treeitem) или tr с tabindex; внутри нет фокусируемого; не внутри aria-hidden="true" или inert. Стал влезать - атрибут снимается, но только если хост не в фокусе (иначе после blur). Чужой tabindex не трогается; tabindex="-1" на хосте - способ убрать значение из Tab.

Отличие от брифа: фокусируемый контейнер (tabpanel, область прокрутки, диалог с tabindex="-1") не мешает остановке, потому что фокус на нём тултип не открывает. Опции списков (role=option) не получают остановку: фокус там ведёт listbox.

Роль на хост не ставится. Так делает пример обрезанного текста в Brio: focusable span с tabindex="0" без роли, тултип с role=tooltip. Правило axe focus-order-semantics такой span отметило бы, но оно помечено experimental. aria-describedby как раньше: не ставится, когда тултип повторяет текст хоста.

Наблюдение: один общий ResizeObserver и один MutationObserver на все хосты. В директиве своего ResizeObserver не было, проверка обрезки шла только при открытии.

Источники

  • WCAG 2.2 Understanding 1.4.13: «Content which can be triggered via pointer hover should also be able to be triggered by keyboard focus», ссылка на 2.1.1 Keyboard.
  • APG Tooltip pattern: тултип по фокусу или наведению, Escape закрывает, триггер ссылается через aria-describedby.
  • Brio tooltip: «Wrap the truncated text in a focusable span so keyboard users can reach it too».
  • axe-core focus-order-semantics: tags best-practice, experimental.
