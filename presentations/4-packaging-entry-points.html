Рекомендация: D

73 entry point, корень остаётся фасадом. Потребитель не переписывает ни одного импорта, а настоящее приложение получает вдвое меньший стартовый бандл. F даёт тот же результат только на синтетике; на ds-docs он не помогает.

Сверху D даёт то, чего нет ни у кого: глубокие специферы — единственное, что заставляет работать @defer, и Material-подобный публичный API.

Во что D обошёлся на самом деле

Собрано настоящим ng-packagr из копии src/, репозиторий не тронут:

Циклов разорвано переносом папок3 — icons → core/icons, radio → radio-group/radio, time-columns → time-picker/time-columns
Правок в SCSS1 — глубина пути у перенесённого файла
Время сборки библиотеки120 с
Дублей классов в пакете0

Соседние папки «со-локировать» нельзя: entry point — это директория. Цикл core ↔ icons ломается только физическим переносом. Первая попытка без переноса дала ровно ту криптическую ошибку, ради которой написано правило entry-point-boundary: Cannot destructure property 'pos'.

Единственное, что D даёт сверх F

Этот код компилируется без предупреждений и ничего не откладывает — при любой упаковке:

import { TableComponent } from '@ids-group-ltd/ids-design-system';   // ← через корень

@defer (on viewport) { <ds-table [columns]="cols" [data]="rows" /> }

Одна строка — и откладывается по-настоящему:

import { TableComponent } from '@ids-group-ltd/ids-design-system/table';
через корень 154 КБ · 1 файл
глубокий специфер 123 КБ · 4 файла

Обратная сторона F, и её надо знать

Приложению, которое рисует почти всё сразу, F делает хуже — откладывать нечего, а обёртки модулей стоят места. Собрал ds-docs обеими формами:

сплющено 239 КБ
F 248 КБ · +3,8%

То есть F — не бесплатное улучшение для всех, а сдвиг в пользу тех, у кого ленивые роуты. Для потребителя вроде mm-broker это ровно цель; для витрины — небольшой минус.
