Button API: variant × tone

Сейчас ButtonVariant смешивает три оси в одном enum: иерархию (primary/secondary/tertiary), стиль (outline/text) и семантику (error/success/warning). Статусные кнопки существуют только как сплошная заливка — «тихое» деструктивное действие (тональный Delete рядом с primary Save) сделать нельзя.

Предложение (модель Polaris): variant: primary | secondary | tertiary | outline | text — паттерн заливки и уровень акцента, как сегодня минус статусы. tone: neutral | error | success | warning — переключает цветовое семейство, не трогая паттерн. Дефолт neutral. Hard rename, без алиасов: старый variant="error" → variant="primary" tone="error".

API

Было → станет

<!-- сегодня: статус — только «громкий» -->
<ds-button variant="error">Удалить</ds-button>

<!-- станет: семантика и громкость независимы -->
<ds-button variant="primary" tone="error">Удалить</ds-button>     <!-- = старый error -->
<ds-button variant="secondary" tone="error">Удалить</ds-button>   <!-- НОВОЕ: тихий destructive -->
<ds-button variant="text" tone="error">Удалить черновик</ds-button>

Реализация: tone-класс ремапит «слоты» семейства (--t-fill / --t-tonal / --t-subtle / --t-strong …) с primary-семейства на статусное; вариантные правила потребляют слоты и не дублируются. CSS этой страницы — рабочий эскиз (см. исходник). Слой публичных --ds-button-* остаётся поверх без изменений. Disabled одинаков для всех тонов (--surface-disabled).

Вопросы

Открытые решения

  1. Имя второй оси: tone (Polaris) vs intent (Blueprint) vs status. Рекомендую tone — не конфликтует со статус-компонентами (status-dot) и читается как «окраска», а не «состояние».
  2. outline × tone — какая рамка? В сетке вариант A (цветные рамка и текст). Альтернатива B — нейтральная рамка, цветной только текст:
    A · цветная рамка B · нейтральная рамка
  3. Дырка в теме: для hover тональной кнопки нужен шаг «muted-strong»; у primary-семейства он есть (--primary-muted-strong), у статусных — нет. Прототип берёт --error-border (тот же шаг рампы, red-200). Рекомендую добавить роли --error/success/warning-muted-strong в тему, а не перегружать смысл border-токена.
  4. Focus-ring: --focus-ring-error существует (tone="error" его берёт), success/warning-колец нет — в сетке у них нейтральное синее кольцо (Tab по кнопкам, чтобы посмотреть). Добавлять роли или оставить нейтральное?
  5. warning-колонка: жёлтое семейство слабоконтрастно в тихих уровнях (yellow-700 текст на yellow-50/100), underline-ссылка читается как «сломанная». Поэтому предзаполнено ✗/? — смотрите глазами.
  6. text × tone hover: у neutral — ручной --primary-pressed, у тонов — формула color-mix(*-text 76%, black). По нашему правилу hand-tuned > формулы — если тон легализуем, подобрать ручные пики?
  7. Спиннер loading уже в todo (прокинуть через --_button-fg) — после этого tone подхватится автоматически, отдельной работы нет.
