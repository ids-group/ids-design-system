Button API: color × fill

primary / secondary / tertiary — это цветовые решения, а не уровни иерархии: тема держит три брендовые роли (--primary, --secondary, --tertiary — полные семейства на h/s/l-каналах; по умолчанию secondary и tertiary = primary, бренд переопределяет каналы — например, оранжевый secondary). Кнопки одного вида заливки могут отличаться цветовым решением, и наоборот.

Поэтому две оси: color: primary | secondary | tertiary | neutral | error | success | warning — какое семейство; fill: solid | tonal | ghost | outline — вид заливки. Дефолты: color="primary" fill="solid". Вариант text уходит совсем — его роль выполняет глобальный класс .link (карточка ниже).

Бренд

Цветовые роли темы — живые ручки

В дефолтной теме secondary/tertiary = primary, колонки были бы неотличимы. Здесь они сразу перекрашены (оранжевый / фиолетовый) через override каналов --secondary-h/s/l — ровно так это сделает бренд. Семейство (hover, тональная, subtle, текст) пересчитывается само.

API

Было → станет

<!-- старый enum смешивал цвет и заливку в одной оси -->
variant="primary"    →  color="primary"  fill="solid"   (оба дефолты — можно не писать)
variant="secondary"  →  color="primary"  fill="tonal"   ← старый «secondary» был НЕ secondary-цветом,
variant="tertiary"   →  color="primary"  fill="ghost"      а тональной заливкой primary
variant="outline"    →  color="neutral"  fill="outline"
variant="error"      →  color="error"    fill="solid"   (так же success/warning)
variant="text"       →  <button class="link">           (компонентного варианта больше нет)

<!-- новое: настоящий secondary-ЦВЕТ, любой заливкой -->
<ds-button color="secondary">В корзину</ds-button>
<ds-button color="error" fill="tonal">Удалить</ds-button>  <!-- тихий destructive -->

Реализация: color-класс ремапит слоты семейства (--c-base / --c-muted / --c-subtle / --c-strong …), fill-класс потребляет слоты — правила заливок не дублируются по цветам. CSS страницы — рабочий эскиз (см. исходник). Публичные --ds-button-* остаются поверх. Disabled одинаков для всех (--surface-disabled).

Accent-скоуп

А остальные 36 компонентов? Перекраска без нового API

Инпут color получают только button/icon-button. Остальные компоненты (checkbox, switch, tabs, pagination, поля, степперы…) красят свой акцент токенами primary-семейства — checked-заливку, активную вкладку, focus-кольцо. Значит, им не нужен новый API: достаточно обёртки, которая внутри себя переназначает primary-семейство на другую брендовую роль. Всё внутри перекрашивается само — hover, тональные оттенки, фокус.

<!-- ни один компонент не менялся — перекрашен КОНТЕЙНЕР -->
<div class="ds-accent-secondary">
  <ds-switch />  <ds-checkbox />  <ds-tabs />  <ds-pagination /> …
</div>
без обёртки — primary (как сейчас)
<div class="ds-accent-secondary">
<div class="ds-accent-tertiary">

Контролы в трёх панелях — один и тот же HTML, реплики наших компонентов на тех же токенах; отличается только класс контейнера. Всё живое: щёлкайте свитчи/чекбоксы/табы/страницы, Tab в поле — focus-кольцо тоже цвета роли (его пришлось переобъявить в скоупе: --focus-ring композится на :root и сам за ремапом не следует — детали в исходнике). Свотчи в карточке «Бренд» наверху перекрашивают и эти панели.

text vs link

Зачем кнопке variant="text", если есть .link?

Незачем — это дубль. Текущий variant="text" рисует то же, что глобальный класс .link (подчёркнутый --text-link); класс вешается и на <button>, не только на <a>. Предлагаю удалить вариант из компонента и документировать паттерн ниже. Что теряем у link-вида: loading, fullWidth, типизированный (pressed) — если когда-то понадобится «ссылка с лоадером», вернёмся, но это редкость.

действие, выглядящее ссылкой → <button class="link">
навигация → <a class="link"> (как и сейчас)

Вопросы

Открытые решения

  1. Имена осей: color + fill (модель MUI/Chakra) vs tone + variant. Рекомендую color + fill — «color = цветовое решение» совпадает с вашей формулировкой, fill буквально описывает заливку.
  2. Дырка в теме №1: нет шага -muted-strong (hover тональной) у secondary/tertiary — прототип считает формулой hsl(h, 90%, 89%); у статусов беру *-border (тот же шаг рампы). Рекомендую добавить роли --secondary/tertiary/error/success/warning-muted-strong в тему.
  3. Focus-ring: есть нейтральное кольцо и --focus-ring-error; для secondary/tertiary/success/warning — нейтральное (Tab по сетке). Добавлять кольца на каналах ролей или оставить?
  4. Neutral-строка: solid neutral (серая кнопка) предзаполнен ✗, tonal ? — нужны ли серые кнопки вообще, или neutral живёт только как outline/ghost?
  5. Иерархия страницы теперь конвенция дока: «громкость» = выбор fill (solid > tonal > ghost/outline), цвет — отдельно. Зафиксировать в design-system.md примером (CTA solid-primary, рядом tonal, тихие — ghost).
  6. warning/success в тихих заливках: жёлтый слабоконтрастен (yellow-700 на yellow-50/100), зелёные тихие уровни редко нужны — потому ✗/?. Смотрите глазами.
  7. Формулы vs ручные пики: primary-семейство в теме — ручные пики рамп (blue-50/100/200/700), secondary/tertiary — формулы от каналов. По нашему правилу hand-tuned > формулы — при легализации secondary/tertiary-кнопок откалибровать формульные шаги глазами (или дать брендам переопределять пики).
  8. Accent-скоуп: класс .ds-accent-secondary vs атрибут [ds-accent="secondary"]; и нужны ли статусные скоупы (.ds-accent-error для «опасной зоны» формы)?
