Opt-in-шов — 31 КБ и три решения

Проблема. Код опциональной фичи отгружается, даже если фича выключена. Это удержание, а не размещение, — поэтому ничего здесь не ждёт решения по entry points.

18,9 КБ №1 grid-фичи таблицы → директивы
11,3 КБ №2 строка сообщения у кнопки
1 055 B №3 CSS порталов → opt-in-импорт
1,6 КБ уже в кармане: dev-варнинги, тот же паттерн

Риск один: не съест ли машинерия больше, чем фича даёт

Размер фичиВнутри, input offЗа директивой, не импортированаНакладные шва
1,6 КБ34 59233 888923
5,9 КБ38 90133 888923

Колонка «не импортирована» побайтово одинакова при обоих размерах фичи — накладные фиксированы, а возврат растёт 1:1. Для реальной таблицы оценка 1–2,5 КБ, то есть шов удерживает ~87–95% приза. Обратная сторона: кто фичу использует, платит ~1 КБ больше.

Решение №1 — форма opt-in для таблицы

1a — директивы1b — input features1c — провайдеры
Как пишет потребитель <ds-table dsResizable dsExport> [features]="[withResize()]" provideDsTable(withResize())
Скоуп на экземплярна экземпляр на роут — две таблицы на странице не смогут отличаться
Ловит неверные комбинации нетв рантаймеда

Размер у всех трёх одинаковый — неимпортированная директива, невызванная фабрика и несосланный провайдер равно мертвы. Выбор про эргономику. Грабли общие для всех трёх и неустранимы: привязал фичу, которую не импортировал — получил тишину, без ошибки. У TanStack это лечится сужением типов; в Angular инпуты заданы на классе, так что скопировать нельзя.

Рекомендую 1a

Контроль на экземпляр, идиома самого Angular, естественно читается в шаблоне. 1c — если важнее валидация комбинаций и роут-широкий скоуп приемлем.

Почему реестр, а не «перенести методы». Абляция всё время натыкалась на общие вычисления: clipWidth обслуживает и обрезку, и ресайз; visibleColumns — цепочку, в которую пишет пикер; filteredData сворачивает фильтры в поиск. Один паттерн: таблица владеет производным значением, фича хочет внести в него вклад. Отсюда DsTableLayout — реестр вкладов на экземпляр, и таблица нигде не называет фичу.

Два сложных места, известны заранее: директива не может вставить разметку (кнопка фильтра, ручка ресайза, поповер пикера — это разметка, нужны слоты под ng-template), и clipWidth распутывается только после переноса разрешения ширины в шов.

Решение №2 — строка сообщения у кнопки

ButtonComponent тянет FieldMessageComponent, чтобы кнопка могла показать hint/warning/error под собой. 11 295 B gzip — 35% цены кнопки, платит каждый, кто рисует хоть одну. Entry points это не чинят: ребро button → field-message статическое. Два выхода: выбросить фичу или спрятать за DsButtonMessage — тот же шов.

Решение №3 — CSS порталов

Из глобального листа унести можно только портальную группу (dropdown-overlay, overlay-motion, toast-overlay) — 1 055 B. Остальное не двигается: link, page-grid, layout-utils — публичные классы, то есть API; scrollbar стилизует html; skeleton-shimmer держит все скелетоны в такт одной :root-анимацией.

Платит только потребитель без пикеров, тостов и модалок — редкость. Самое мелкое из трёх и самое разумное отклонить. Способ AG Grid (CSS внутри кода) отклонён: Angular инжектит стили рантайм-тегами, под строгим CSP + SSR они блокируются, и это бремя падает на каждого потребителя.
