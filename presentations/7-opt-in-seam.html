Шов стоит фиксированные ~1 КБ — и это весь риск

Очевидное возражение против выноса фичи из компонента: машинерия съест больше, чем фича даст. Замерено на специальной фикстуре — компонент с производным значением, per-instance реестром вкладов и одной опциональной фичей в трёх формах:

Размер фичиУдалить совсемВнутри, input offЗа директивой, не импортированаНакладныеВозвращено
1,6 КБ gzip32 96534 59233 888923704
5,9 КБ gzip32 96538 90133 8889235 013

Колонка «не импортирована» побайтово одинакова при обоих размерах фичи. Накладные фиксированы — сервис, запись в providers, точка композиции, — а возврат растёт 1:1 с фичей. 923 B — это пол простейшего шва, а не константа: у реального реестра таблицы несколько видов вкладов, оценка 1–2,5 КБ. Даже по верхней границе шов удерживает ~87% приза. Честная обратная сторона: потребитель, который фичу использует, платит примерно на 1 КБ больше, чем сегодня.

Решение 1 — grid-фичи таблицы

ds-table сегодня 31 428 B
grid-фичи вынесены 12 125 B

Удалили: ресайз колонок, переупорядочивание + пикер видимости (вместе с импортом @angular/cdk/drag-drop), фильтры по колонкам, CSV-экспорт, сохранение раскладки, truncate + поповер ячейки — 1 063 строки. 18,9 КБ — это пол, а не потолок: row actions и инлайн-редактирование такие же «продвинутые» и остались. Жёсткий потолок — 31,0 КБ, потому что сортировка, выделение, пагинация, загрузка, липкая шапка и рендер ячеек обязаны остаться.

Почему реестр, а не «перенести методы»

Абляция всё время натыкалась на общие хелперы: clipWidth/fitsContent обслуживают и truncate, и ресайз; orderedColumns/visibleColumns — та же вычисляемая цепочка, в которую пишет пикер; filteredData сворачивает фильтры по множествам в подстрочный поиск; statusMessage сворачивает состояние экспорта в live-регион. Все четыре — один паттерн: таблица владеет производным значением, а опциональная фича хочет внести в него вклад. Отсюда реестр вкладов на экземпляр: 

@Injectable() // providers: [DsTableLayout] на самом ds-table
export class DsTableLayout<T> {
  readonly columnTransforms = signal<readonly ColumnTransform<T>[]>([]); // порядок, видимость, ширина
  readonly rowFilters       = signal<readonly RowFilter<T>[]>([]);
  readonly statusParts      = signal<readonly Signal<string | null>[]>([]);
  readonly headerAdornments = signal<readonly HeaderAdornment[]>([]);
}

visibleColumns становится columns(), пропущенным через columnTransforms() — пустой массив есть тождество, то есть ровно то поведение из абляции, которое уже компилируется и меряется в 12,1 КБ. Таблица нигде не называет фичу — никаких if (resizable).

1c — самый идиоматичный для Angular и единственный, кто валидирует комбинации, но EnvironmentProviders намеренно нельзя использовать в скоупе компонента, поэтому он роут-широкий: две таблицы на одной странице не смогут отличаться. 1a сохраняет контроль на экземпляр и естественно читается в шаблоне. 1b — тот же контроль одним инпутом вместо N атрибутов, но без сужения типов TanStack его преимущество перед 1a в основном косметическое.

<!-- продакшен: фича приезжает вместе с директивой -->
imports: [DsTable, DsTableResizable, DsTableExport]

Два по-настоящему сложных места, известны заранее

  1. Директива не может вставить разметку, а кнопка фильтра, ручка ресайза и поповер пикера — это разметка. Таблица держит крошечные слоты @if (headerAdornments().length), рендерящие ng-template от директивы; остаточную цену слотов надо померить, а не предположить.
  2. clipWidth/fitsContent распутываются только после переноса разрешения ширины в шов.

ButtonComponent наследует DsMessageBase и импортирует FieldMessageComponent, чтобы кнопка могла отрисовать hint / warning / error под собой. 11 295 B gzip — 35% предельной цены кнопки, платит каждый, кто рисует хоть одну, независимо от того, привязывает ли он hint.

Entry points это не чинят: даже при точке на компонент ребро button → field-message остаётся статическим, и 11 КБ приезжают с любой кнопкой. Два выхода: выбросить фичу из ds-button или спрятать за opt-in-директиву (DsButtonMessage) — тот же шов, один вид вклада.

Почему не как у AG Grid

Они держат CSS в коде, чтобы он делился по модулям: стиль приезжает с фичей и исчезает без неё, без всякого opt-in-импорта. Счёт приходит от Content Security Policy. Angular инжектит стили рантайм-тегами <style>; строгий CSP требовал unsafe-inline до Angular 16, а 16+ добавил nonce — но под SSR статические теги в index.html nonce не несут, и строгий CSP их блокирует. Потребитель не управляет тем, как библиотека обращается со стилями, поэтому инжект глобального CSS из нашего кода перекладывает бремя CSP и SSR на каждого. Ради 1 КБ — не стоит.
