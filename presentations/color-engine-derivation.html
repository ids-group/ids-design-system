Цвет-движок: все подходы 2026

Один публичный токен на роль (--primary: #2E54FF) → ДС выводит всё семейство (subtitle/muted/muted-strong/strong/hover/pressed/halo) в light+dark. Каналы h/s/l вытаскиваются из одного hex через relative color — руками не задаются. Ниже все способы деривации рядом (реши глазами), стресс-тест статусов по всем методам, сравнение state-слоёв и живые демо динамики (@property, light-dark(), contrast-color(), P3).

⚠ Браузер не поддерживает oklch(from …) — часть демо не пересчитается. Открой в свежем Chrome/Edge 125+ / Firefox 128+ / Safari 18+.

1Все способы деривации — светлая тема

Все колонки живут от одной ручки бренда выше (кроме «сегодня» — эталон ручных пиков, не следует за ручкой). У каждой колонки — объяснение простыми словами. Колонка с пометкой ⬅ — это буквально «вытащить каналы из одного цвета и работать как раньше». Крути ручку (Orange/Violet/Magenta) и смотри, какой метод держит нарисованный лук и не разъезжается.

⭐ рекомендация — идентично (Δ0) + просто○ тонкий плюс — перцептивно ровнее на любом бренде△ для сравнения — не дефолтэталон — текущие ручные пики
Словарик: HSL vs OKLCH. Оба описывают цвет тройкой — тон · насыщенность · светлота. Разница в светлоте: в HSL «L 50%» у жёлтого выглядит ярко, а у синего тускло — т.е. равные шаги L перцептивно неравномерны, и фикс-L% тинты у светлых тонов вымываются почти в белый. В OKLCH светлота равномерная: шаги ровные, тинты читаются как свой тон на любом бренде. ВАЖНО (проверено математикой): расхожий миф «HSL при затемнении мутит жёлтый в болото» здесь НЕ работает — состояния считаются srgb-mix (пропорц. затемнение), тон сохраняется (дрейф ≤1.2°). Поэтому разница HSL↔OKLCH тут тонкая (ровность + насыщенность тинтов), а не «чисто vs грязь».
Точная математика (значения из репы, не пипетка). HSL hue-only = Δ0 — идентично по построению (та же формула, что генерит --blue-*; hue из --primary при blue = 229°). OKLCH hue-only = Δ≤6/255, и это неустранимо, а не подбор: светлые тинты в OKLCH сидят на hue ≈276°, а base на 267° (в HSL все шаги держат 229°, но OKLCH-hue дрейфует +9° при осветлении). Загнав все шаги на один seed-hue, математика даёт ≤6. OKLCH с точным hue каждого шага = Δ0, но тогда hue — литерал per-step → это уже «не из одного токена». Итого: идеально идентично И из одного токена → HSL; OKLCH-hue-only жертвует ≤6/255 ради ровности на произвольном бренде.

Ещё два метода — build-time, не чистый CSS (поэтому не в живых колонках): HCT / Material 3 (алгоритмический tonal через material-color-utilities) и Adobe Leonardo (рампа по целевым контраст-коэффициентам). Дают точный контроль контраста, но требуют JS-генерации на билде и не переопределяются одним CSS-токеном на лету — против нашей идеи «single-source в рантайме». Годятся как генератор значений для ручных L/C.

2Все способы деривации — тёмная тема

Правило исследования: light↔dark = двигать только L, hue/chroma фиксированы. OKLCH делает это чисто (перцептивный L). «Сегодня (dark)» — реальные значения themes/dark/_theme.scss.

3Статусы — честное сравнение HSL vs OKLCH

Поправка к тому, что я говорил раньше: «HSL мутит жёлтый в болото» — миф, здесь не подтвердился (посчитал: дрейф тона ≤1.2°, состояния — пропорциональный srgb-mix). Ниже 4 статуса × 2 метода (верх — HSL, низ — OKLCH). Разница тонкая: у HSL светлые тинты вымываются к белому, OKLCH чуть ровнее — вывод словами под каждым. primary — секции 1–2; secondary/tertiary наследуют hue primary.

4State-слои: srgb vs oklab vs oklch

Hover/pressed/tint = смешать базу с чёрным/белым/прозрачным. Исследование: color-mix(in oklab …) — победитель (не мутит как srgb, не крутит hue как oklch у чёрного/белого). Либо без микса — relative oklch(from base calc(l ± Δ) c h).

5Динамика: @property — плавная смена бренда

Без @property кастом-проперти — непрозрачная строка, transition щёлкает. Регистрируем @property --demo { syntax:"<color>" } — токен плавно перетекает, и все выведенные из него relative-color оттенки вместе с ним. Жми пресеты.

Чипы = subtitle / muted / strong / hover из --demo. Все анимируются, т.к. токен типизирован. Гейт: @supports; без поддержки — мгновенный свап.

6Остальной арсенал 2026 (закладываем все)

light-dark() — одна декларация на тему

Нужен color-scheme: light dark. Оставляем [data-theme] для user-override и >2 тем.

contrast-color() — авто on-text

Возвращает только чёрный/белый, мид-тоны могут провалить AA → hand-tuned --*-on остаётся фолбэком за @supports.

P3 wide-gamut + sRGB-фолбэк

Двойной guard: @supports + @media (color-gamut: p3). sRGB-safe chroma ~0.10–0.15, богаче только на P3.

Контраст-гейт: WCAG 2.2 AA

APCA пропускаем — убрана из черновика WCAG 3 (2023), Rec не раньше ~2030, замена WCAG 2 сегодня = юр. риск. Гейт всех пар — WCAG 2.2 AA; APCA только как вспомогательный тюнинг.

✅ Рекомендация для этого проекта — HSL hue-only

  • Δ0 — байт-в-байт как сегодня (та же формула, hue из --primary) и из одного токена
  • минимальный diff, проще всего; «муть на жёлтом» — миф (проверено математикой)
  • каждый оттенок — named-токен с дефолтом-выводом (escape hatch на ручной пик)
  • OKLCH — задокументировать опцией: перцептивно ровнее на произвольном бренде ценой Δ≤6 от текущего лука; переключаемо per-роль без переписывания

⚠ Фичи за guard (закладываем все)

  • ядро: @supports (color: rgb(from red r g b)) + статический sRGB-фолбэк
  • @property <color> — плавные переходы
  • light-dark() inline + [data-theme] источник истины
  • contrast-color() поверх hand-tuned --*-on
  • P3 двойной guard; forced-colors — системные цвета для критичного

✖ Не берём

  • APCA как гейт (юр. риск) → WCAG 2.2 AA
  • чистая формула/mix как дефолт (флэттит/мутит рампу)
  • браузерный gamut-mapping как гарантия
  • голые каналы через @property вне анимации
