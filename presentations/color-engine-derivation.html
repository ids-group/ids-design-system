Цвет-движок: какой способ деривации?

Решение из docs/todo.md → «Single-source colour engine»: из одного токена на роль (--primary, --error…) вывести всё семейство (subtitle/muted/muted-strong/strong/hover/pressed/halo). Два способа — выбери глазами. Обе колонки живут от одной ручки бренда ниже; третья — сегодняшние ручные пики как эталон. Все семейства выводятся единообразно (твой выбор).

⚠ Браузер не поддерживает oklch(from …) — колонка B не пересчитается. Открой в свежем Chrome/Edge/Safari/Firefox.

Primary (brand) — рампа и UI-кит в трёх вариантах

A воспроизводит сегодняшний blue пиксель-в-пиксель при бренде = IDS blue (S/L шагов скопированы с рампы --blue-*). При другом бренде A держит «нарисованную кривую» (S/L фиксированы, тянется только hue) — смотри, не разъезжается ли. B — единая перцептивная формула в oklch (плавнее, но от эталона отступает).

A · hue-onlyhsl(from --brand h <ручной S> <ручной L>) + color-mix для hover/pressed/halo
B · oklchoklch(from --brand <calc L> <calc C> h) — одна перцептивная формула на все шаги
сегодняручные пики --blue-50/100/200/600/700 — НЕ следуют за ручкой (для сверки с A при бренде = blue)

Статусные семейства — честный стресс-тест

Сегодня green/yellow рампы — hex-пики без HSL-каналов, а --warning-on — тёмный ink (жёлтый проваливает контраст с белым). Если движок выводит ВСЕ семейства единообразно из одного токена, именно здесь видно, держит ли формула: warning — самый сложный (жёлтый при затемнении уходит в зелёный/грязь), success — средний. Для каждого: A слева, B справа, от их собственного базового токена (бренд-ручка их не трогает).

Сводка для решения

A · hue-only (hsl from + ручные S/L)

  • + при дефолтном бренде воспроизводит нарисованную рампу точно — лук не меняется
  • + совпадает с правилом «hand-tuned > формулы»: тянем только hue, S/L рукотворные
  • + srgb-mix для hover/pressed — ровно как сейчас в теме
  • − S/L каждого шага надо прописать руками (8 ролей × 7 семейств)
  • − при «чужом» бренде (тёмном/блёклом) фикс-S/L шагов могут разъехаться с базой — нужна сверка глазами
  • − hsl-затемнение жёлтого сдвигает hue (warning) — может потребовать пер-семейного твика

B · oklch perceptual (одна формула)

  • + одна формула на всё — минимум ручного кода, любой бренд «просто работает»
  • + перцептивно равномерно: затемнение не мутит и не сдвигает hue (жёлтый остаётся жёлтым)
  • + base-L бренда участвует в выводе — светлый/тёмный бренд авто-адаптируется
  • − отступает от сегодняшних пиков — нужен ребейзлайн всего лука + проверка AA
  • − противоречит «hand-tuned > формулы», если не оставить пер-шаговые override
  • − oklch C для очень насыщенных брендов может выйти за gamut (клампится)

Можно и гибрид: hue-only (A) как дефолт для brand-семейств (точный лук), а формула — только для hover/pressed/halo (срабатывает там, где сегодня уже color-mix). Скажи, какой берём (A / B / гибрид), и я зашиваю это в спеку фазы 1.
