Цвет — единственный канал, и это провал WCAG 1.4.1. Сегменты прячут свои .label и ds-field-message через display: none — иначе строка сообщения разорвала бы склеенный ряд, — а групповой строки не существует. aria-invalid не ставится нигде, так что скринридер на любом сегменте не скажет ничего. Проверено в коде сегодня: _field-group-segment.scss:10-13, и grep aria-invalid по компоненту пуст.

Визуальная половина дефекта уже починена (2026-09-10): красная рамка пропадала под курсором и под фокусом, потому что :hover и :focus-within весили больше .invalid. Сейчас держится, и гало берёт цвет ошибки. Эта дека — про то, что осталось.

Чем платим

ВариантРаботаЦена
A ноль кода, дописать в доку ловушка остаётся: invalid выглядит полноценным состоянием, а даёт четверть
B одна строка в host галочка для автотестов; человеку ноль — и опаснее, чем ничего, если после неё пункт закроют
C одно поле в DsFieldGroupContext, по строке в шести полях механизм уже есть (им передаётся sizeResolved); 1.4.1 не закрыт — текста по-прежнему нет
D C + слот сообщения в шаблоне группы, id раздаётся сегментам группа перестаёт быть одной строкой по высоте; следом попросят hint — это уже небольшая фича, а не фикс
E D, но invalid: boolean заменяется на error: string ломающее для каждого потребителя, и теряется случай «рамку хочу, текст свой снаружи»

Рекомендую D, с входом error из E, но сохранив invalid. Только D закрывает то, из-за чего пункт вообще в P2: сегодня об ошибке группы нельзя узнать иначе как увидев цвет. error: string делает текст условием состояния — включить ошибку и не сказать, в чём она, становится невозможно, и это совпадает с полями, где error уже строка. invalid: boolean остаётся ровно для одного реального случая: текст живёт снаружи, а от группы нужна только рамка.

ВопросВарианты

Если да — hint тем же слотом сразу · потом, по запросу
Если да или C — aria-invalid на сегментах на всех (буква ARIA21) · только на первом (одно объявление на группу)
