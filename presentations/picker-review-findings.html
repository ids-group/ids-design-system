§1

Блокеры — функционально сломано

5

Каждый пункт ломает работу пользователя сейчас, на отгруженном коде. Три из пяти сломала ровно эта ветка.

F1

Enter на триггере закрывает панель вместо выбора

сломала ветка

multi-select.component.ts:502

Ветка Enter/Space делает return до делегации на строке 516. При searchable="false" Enter уходит в onTriggerClick(), видит overlayRef и закрывает панель. Ветка Enter в onSearchKeydown (531-538), которая переключает активную опцию, недостижима с триггера.

Итог: открыл панель, стрелками дошёл до опции, Enter — панель закрылась, значение не изменилось. Выбрать опцию с клавиатуры нельзя вообще. Сломано тем самым скрываемым поиском, который добавила §4.

Правка: Пропускать Enter/Space в делегацию, когда панель открыта и !showsSearch(): перенести проверку ниже блока делегации либо добавить в него условие.

F2

dsChipTemplate на автокомплите объявлен и не рендерится

сломала ветка

autocomplete.component.ts:193

contentChild(DsChipTemplateDirective) объявлен, но в autocomplete.component.html не читается ни разу — грепом ноль вхождений. Чип печатает {{ selectedOption.label }} безусловно (:57-64).

Слот обещан в трёх местах: CHANGELOG, docs/picker-contract.md:26-27 и док самой директивы. Плюс showcase (multi-select.section.html:254-262) прямо говорит «honoured by ds-select, ds-multi-select и ds-autocomplete». Консюмер копирует сниппет — получает ничего, без ошибки и без предупреждения.

Правка: Отрисовать слот в чипе автокомплита по образцу multi-select.component.html:108, с тем же контекстом { $implicit: option, option }.

F3

showsPanelSelectAll() написан и не подключён

сломала ветка

multi-select.component.ts:412

Computed существует ровно для того, чтобы selectAll="group" не рисовал панельную строку — и не используется нигде (грепом только объявление). Шаблон гейтит сырым selectAll() (:174), а 'group' — истинная строка.

Значит 'group' рисует и панельную строку, и групповые, то есть 'both' неотличим от 'group'. На плоском списке без групп selectAll="group" тоже рисует панельную строку, хотя док входа обещает обратное.

Правка: @if (showsPanelSelectAll() && filteredOptions().length) вместо @if (selectAll() && …).

F4

Опции отключённой группы теряют идентичность

сломала ветка

core/option.ts:47-51

filteredItems уже спредит опции отключённой группы в { ...option, disabled: true }, а flattenDsOptions спредит их второй раз, потому что { ...item } сохранил item.disabled. Шаблон рендерит первые копии, flatIndexOf ищет во вторых → −1.

Проверено на [{disabled: true, options:[a,b]}, c]: flatIndexOf(a) = −1, flatIndexOf(b) = −1, flatIndexOf(c) = 2.

Последствия: дубль id="…-opt--1" на всех строках группы; aria-activedescendant указывает на элемент, которого в документе нет (мульти-селект ставит activeIndex = 0 на открытии); в автокомплите при полностью отключённой группе activeIndex тоже −1, и -1 === -1 красит все строки активными сразу.

Правка: flattenDsOptions только сплющивает, без трансформации. Проставление disabled остаётся за вызывающим — оба вызывающих это уже делают осознанно, с комментарием почему.

F5

labels меряет то, что сам же меняет

сломала ветка

multi-select.component.scss:36

:host(.compact-trigger) { width: fit-content }, а labels рендерит #chipRow с data-chip (:61-83) — значит chipFit меряет trigger.clientWidth бокса, чью ширину задаёт результат его же обрезки.

Это дословное нарушение INVARIANT в шапке chip-overflow.ts:13: «nothing here may measure something the cut itself changes». Guard по lastWidth/lastCount не даёт зависнуть, поэтому получается не повисшая страница, а неверное сошедшееся значение — одна метка и «+N» независимо от свободного места.

width="fill" не спасает: :host(.content-width) (:29) и :host(.compact-trigger) (:36) равны по специфичности, второй объявлен позже.

Правка: Развилка, нужен твой выбор. (а) labels не берёт fit-content — тогда компактный след теряется. (б) Мерять родителя триггера, а не сам триггер. (в) labels считать не компактным режимом и не давать ему compact-trigger.

Что меняю в методе

1. Каждый новый слот и каждый новый computed — грепать НА ЧТЕНИЕ, не на объявление. Объявленное и неиспользованное — отдельный класс дефекта, и он у меня повторился трижды (F2, F3, F25).
2. Аудит на API-поверхность не считается проверкой поведения. Разделить их явно: picker-parity отвечает «имя есть», и это всё.
3. Утверждение в нотах = проверяемое обещание. Пятнадцать ошибок в прозе нашлись сверкой каждой цитаты с кодом — этот проход должен быть обязательным, а не финальным бонусом.
4. Клавиатурный путь проверять прохождением, а не чтением: открыть, стрелка, Enter. Ровно эти три шага вскрывают F1.
