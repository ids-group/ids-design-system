Migration manifest audit

Forty agents read every published manifest, the lint that guards them and the plugin that executes them, then tried to refute their own findings. Twenty-four survived. Every one was re-verified against the shipped code before it was touched — five had wrong evidence and one would have destroyed two legitimate entries. All twenty-three are now fixed.

The honest verdict

On format this is ahead of the field. Nothing in Angular CDK's VersionChanges, Nx's migrations.json, Primer's deprecated.json or Polaris's migration guide carries the equivalent of detect + verify + deleteList plus a per-version freeze rule. The “what you can now delete” half is genuinely novel — the industry documents what broke, not what became redundant.

What is missing is everyone else's enforcement posture. The rest of the ecosystem gates on a declared marker — ESLint meta.deprecated, Vue DeprecationTypes, Ember deprecation ids, OpenRewrite Preconditions — or on executable code. Here the contract rests on 306 lines of bespoke regex whose three judgment rules cannot fire on the exact cases they are named after, and on a selftest that manufactures the only input that makes them fire.

The result: 186 items where the format is excellent and the data is not. Five shipped items instruct a consumer to make an edit that is wrong or regressive. Four class-member entries are miscounted or incomplete. The release gate is green on all of it.

What the format is missing

Every row came from a primary source — official docs or repository source, not blog summaries. The verdict column is a judgement about this repo, not about the practice.

Three of the thirteen have shipped since — checked against the code on 2026-09-01, not against this page. The other ten are still unratified, and they are the whole of what this deck is still open for: docs/todo.md carries them as one P3 line.

The findings above were re-verified by hand the same day, against the manifests, the lint, the plugin contract and the source at each tag. Eighteen held. Five carried a “Fixed” tag that the code did not support — 02, 06, 10, 14 and 18, each now marked in place and each now actually fixed. Two things this page cannot know about itself: its scope line reads 22 manifests · 186 items and the folder now holds 24 and 204, so 0.11.0 and 0.11.1 have never had an adversarial pass — one reader checked them by these criteria and found no tier-1 defect, which is not the same assurance the other 22 have.
