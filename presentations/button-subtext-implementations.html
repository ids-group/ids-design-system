ds-button subtext · варианты реализации

Фича одна и та же визуально: у заблокированной "Mark Truck as Completed" появляется вторая строка с причиной. Ниже - живые кандидаты и их цена (отвергнутые - директива-маркер, querySelector, стилизация на стороне потребителя - убраны).

Две независимые задачи, которые решает каждый вариант:
1) Детекция - как кнопка узнаёт, что subtext есть, и переключается в колонку (input / :has() / ручной класс / contentChild по ref).
2) Стилизация спана - спроецированный элемент несёт скоуп-атрибут потребителя, стили кнопки его не видят. Это не зависит от способа детекции: любой селектор из button.component.scss компилируется со скоупом кнопки и не матчит чужой спан - даже анонимный :last-child. Достать спан можно только через ::ng-deep или глобальный партиал.

1 · Input-строка было закоммичено (babd8db1)

Спан рендерит сам компонент - никакой проекции, никакого скоуп-вопроса.

Потребитель

<ds-button
  [disabled]="locked()"
  [subtext]="locked() ? 'All kits must be…' : ''"
>
  Mark Truck as Completed
</ds-button>

Внутри DS

readonly subtext = input<string>('');
// classes: subtext() ? 'has-subtext' : ''

<ng-content/>
@if (subtext()) {
  <span class="subtext">{{ subtext() }}</span>
}
  • Проще всех: ни проекции, ни ng-deep, ни :has - спан свой, стили обычные
  • Детекция тривиальна (строка пустая/нет)
  • Только плоская строка: ни иконку, ни ссылку, ни разметку в subtext не вставить
  • Длинный текст с тернарником в атрибуте - шумно в шаблоне потребителя
  • Не "ангулярный" способ для контента - контент принято проецировать

2 · Слот + :has(::ng-deep) в стилях компонента закоммичено (f667950, текущий HEAD)

Ноль TypeScript: select-слот проецирует, :has() детектит, ::ng-deep пробивает скоуп.

Потребитель

<ds-button [disabled]="locked()">
  Mark Truck as Completed
  @if (locked()) {
    <span dsButtonSubtext>All kits must be…</span>
  }
</ds-button>

Внутри DS (button.component.scss)

<ng-content/>
<ng-content select="[dsButtonSubtext]"/>

&:has(::ng-deep [dsButtonSubtext]) {
  flex-direction: column; height: auto; …
  ::ng-deep [dsButtonSubtext] { font: …; }
  &[disabled] ::ng-deep [dsButtonSubtext] { color: …; }
}
  • Ноль TS, ноль импортов у потребителя, условие в одном месте
  • Стили кнопки и subtext живут в одном файле
  • ::ng-deep на каждом селекторе, включая аргумент :has() - выглядит страшно
  • ::ng-deep "deprecated since forever" - каждое использование надо оправдывать

3 · Слот + глобальный партиал DS в рабочем дереве

Те же селекторы, но в styles/_button-subtext.scss - там нет инкапсуляции, ::ng-deep не нужен. Прецедент в DS уже есть: _dropdown-overlay.scss и _toast-overlay.scss глобальные ровно по той же причине.

Потребитель (идентично 2)

<ds-button [disabled]="locked()">
  Mark Truck as Completed
  @if (locked()) {
    <span dsButtonSubtext>All kits must be…</span>
  }
</ds-button>

Внутри DS (styles/_button-subtext.scss)

// глобальный, как _dropdown-overlay.scss
ds-button .button:has([dsButtonSubtext]) {
  flex-direction: column; height: auto;
  min-height: var(--hit-cozy); …
  [dsButtonSubtext] { font: …; }
  &[disabled] [dsButtonSubtext] { color: …; }
}
// ds.scss: @forward 'button-subtext';
  • Всё из варианта 2, но селекторы чистые - ни одного ::ng-deep
  • Прецедентный паттерн DS, приложения получают через существующий @use 'styles/ds'
  • Стили кнопки разъезжаются по двум файлам (смягчено комментарием-указателем)
  • Глобальный селектор обходит инкапсуляцию - дисциплина только через неймспейс ds-button

4 · Класс на host + ручная синхронизация возможен, не делали

Детекция руками: потребитель сам говорит кнопке "ты двухстрочная".

Потребитель

<ds-button
  [disabled]="locked()"
  [class.with-subtext]="locked()"  // условие #1
>
  Mark Truck as Completed
  @if (locked()) {                // условие #2
    <span dsButtonSubtext>All kits must be…</span>
  }
</ds-button>

Внутри DS

:host(.with-subtext) .button {
  flex-direction: column; height: auto; …
}
// детекция без :has, НО спан всё равно чужой:
// его стили - опять ::ng-deep или глобальный
// партиал. От главной проблемы не спасает.
  • Детекция без :has() - работает даже в старых браузерах
  • Одно условие в двух местах: забыл класс - кнопка с текстом но без layout, забыл @if - пустая раздутая кнопка
  • ::ng-deep / глобальный партиал для стилей спана всё равно нужен
  • Класс на host - это контракт "потребитель знает про внутренний режим кнопки"

5 · Автокласс через template ref + структурный селектор возможен, хрупкий

contentChild умеет искать по имени template reference (строка = имя ref; голый атрибут для query API невидим). Потребитель помечает спан рефом, кнопка сама ставит класс - автодетекция без директивы. Но #ref не оставляет следа в DOM: спан анонимен для CSS, стилить приходится по позиции. И помни: даже :last-child из стилей компонента скоупится и не матчит чужой спан - структурный селектор всё равно живёт в ::ng-deep или глобальном партиале.

Потребитель

<ds-button [disabled]="locked()">
  Mark Truck as Completed
  @if (locked()) {
    <span #dsButtonSubtext>All kits must be…</span>
  }
</ds-button>
// импортов нет - ref работает сам

Внутри DS

private readonly subtext =
  contentChild('dsButtonSubtext');
// classes: subtext() ? 'has-subtext' : ''

// партиал или ng-deep, по ПОЗИЦИИ:
ds-button .button.has-subtext > :last-child {
  font: …;
}
  • Автокласс без директивы и без импортов, отслеживает @if
  • Детекция без :has() - не зависит от поддержки браузера
  • :last-child молчаливо ломается, если после subtext спроецируют что-то ещё (иконку, бейдж)
  • ng-content select по ref не умеет - именной слот теряется, позиция = authored-порядок
  • TS в DS появляется (contentChild), а партиал/ng-deep для стилей всё равно остаётся

6 · Автокласс через ref + атрибут (двойной маркер) возможен, многословный

Гибрид: ref - для contentChild-детекции, атрибут - как CSS-хук и селектор слота. Каждый маркер делает то единственное, что умеет.

Потребитель

<ds-button [disabled]="locked()">
  Mark Truck as Completed
  @if (locked()) {
    <span dsButtonSubtext #dsButtonSubtext>
      All kits must be…
    </span>
  }
</ds-button>

Внутри DS

private readonly subtext =
  contentChild('dsButtonSubtext');
// classes: subtext() ? 'has-subtext' : ''
<ng-content select="[dsButtonSubtext]"/>

// партиал или ng-deep, по атрибуту:
ds-button .button.has-subtext [dsButtonSubtext] {
  font: …;
}
  • Надёжный CSS-хук (атрибут) + надёжная детекция (ref), слот работает
  • Без :has() и без директивы
  • Два маркера на одном спане с одним именем - выглядит как дубль, и забыть один из двух легко (то же "условие в двух местах", только маркеры)
  • TS в DS появляется, а партиал/ng-deep для стилей всё равно остаётся

7 · Слот-обёртка: свой элемент вокруг ng-content рекомендую

Ответ на вопрос "может ли компонент сам увидеть контент в слоте и стилизовать его без маркеров на чужом DOM". Кнопка оборачивает именной слот в собственный спан. Обёртка - элемент компонента: её стили скоупятся штатно, без ng-deep и глобальных партиалов. Типографика (font/color/text-align) наследуется внутрь спроецированного спана - стилизовать сам спан не нужно вообще. Детекция - CSS :empty по своей же обёртке (якорь-комментарий от @if на :empty не влияет). Вешать id на чужой контент через Renderer2 можно, но незачем - наследование делает это бесплатно.

Потребитель (идентично 2/3)

<ds-button [disabled]="locked()">
  Mark Truck as Completed
  @if (locked()) {
    <span dsButtonSubtext>All kits must be…</span>
  }
</ds-button>

Внутри DS - всё в одном component.scss

<ng-content/>
<span class="subtext-slot"><ng-content
  select="[dsButtonSubtext]"/></span>

.subtext-slot:empty { display: none; }
&:has(.subtext-slot:not(:empty)) {  // всё своё, скоуп ок
  flex-direction: column; height: auto; …
}
.subtext-slot { font: …; }  // наследуется в спан
&[disabled] .subtext-slot { color: …; }
  • Ноль TS, ноль ng-deep, ноль глобальных партиалов - все стили в component.scss
  • Один маркер у потребителя, одно условие, @if отслеживается (CSS видит живой DOM)
  • Чужой DOM не трогаем: ни id, ни классов на спроецированном спане
  • :has() остаётся (но аргумент - свой элемент, без ng-deep внутри)
  • Контент под @if попадает в именной слот по корню ветки - с ОДНИМ уровнем @if работает, вложенные @if имеют известные баги слоттинга (angular#55194, #59330); лечится ng-container ngProjectAs
  • Обёртку нельзя случайно "зашуметь" пробелами в шаблоне кнопки - :empty чувствителен к текстовым узлам
