ds-button subtext · все варианты реализации

Фича одна и та же визуально: у заблокированной "Mark Truck as Completed" появляется вторая строка с причиной. Ниже - все способы это устроить внутри DS, которые мы перебрали, и их цена.

Две независимые задачи, которые решает каждый вариант:
1) Детекция - как кнопка узнаёт, что subtext есть, и переключается в колонку (input / contentChild / :has() / ручной класс).
2) Стилизация спана - спроецированный элемент несёт скоуп-атрибут потребителя, стили кнопки его не видят. Достать можно только через ::ng-deep, глобальный стиль или отдать потребителю.

1 · Input-строка было закоммичено (babd8db1)

Спан рендерит сам компонент - никакой проекции, никакого скоуп-вопроса.

Потребитель

<ds-button
  [disabled]="locked()"
  [subtext]="locked() ? 'All kits must be…' : ''"
>
  Mark Truck as Completed
</ds-button>

Внутри DS

readonly subtext = input<string>('');
// classes: subtext() ? 'has-subtext' : ''

<ng-content/>
@if (subtext()) {
  <span class="subtext">{{ subtext() }}</span>
}
  • Проще всех: ни проекции, ни ng-deep, ни :has - спан свой, стили обычные
  • Детекция тривиальна (строка пустая/нет)
  • Только плоская строка: ни иконку, ни ссылку, ни разметку в subtext не вставить
  • Длинный текст с тернарником в атрибуте - шумно в шаблоне потребителя
  • Не "ангулярный" способ для контента - контент принято проецировать

2 · Директива-маркер + contentChild отвергнут (не хотим директиву)

Слот + детекция через query. Жил в дереве минут десять.

Потребитель

imports: [ButtonComponent, ButtonSubtextDirective]

<ds-button [disabled]="locked()">
  Mark Truck as Completed
  @if (locked()) {
    <span dsButtonSubtext>All kits must be…</span>
  }
</ds-button>

Внутри DS

@Directive({ selector: '[dsButtonSubtext]' })
export class ButtonSubtextDirective {}

private readonly subtext =
  contentChild(ButtonSubtextDirective);
// classes: subtext() ? 'has-subtext' : ''
// scss: ::ng-deep [dsButtonSubtext] для спана
  • Детекция надёжная, отслеживает @if автоматически
  • Маркер типизирован - опечатка в атрибуте = ошибка компиляции
  • Потребитель обязан импортировать директиву в каждый компонент
  • Целый публичный класс в API ради пустого маркера
  • ::ng-deep для стилизации спана всё равно остаётся

3 · Слот + :has(::ng-deep) в стилях компонента закоммичено (f667950, текущий HEAD)

Ноль TypeScript: select-слот проецирует, :has() детектит, ::ng-deep пробивает скоуп.

Потребитель

<ds-button [disabled]="locked()">
  Mark Truck as Completed
  @if (locked()) {
    <span dsButtonSubtext>All kits must be…</span>
  }
</ds-button>

Внутри DS (button.component.scss)

<ng-content/>
<ng-content select="[dsButtonSubtext]"/>

&:has(::ng-deep [dsButtonSubtext]) {
  flex-direction: column; height: auto; …
  ::ng-deep [dsButtonSubtext] { font: …; }
  &[disabled] ::ng-deep [dsButtonSubtext] { color: …; }
}
  • Ноль TS, ноль импортов у потребителя, условие в одном месте
  • Стили кнопки и subtext живут в одном файле
  • ::ng-deep на каждом селекторе, включая аргумент :has() - выглядит страшно
  • ::ng-deep "deprecated since forever" - каждое использование надо оправдывать

4 · Слот + глобальный партиал DS рекомендую (в рабочем дереве)

Те же селекторы, но в styles/_button-subtext.scss - там нет инкапсуляции, ::ng-deep не нужен. Прецедент в DS уже есть: _dropdown-overlay.scss и _toast-overlay.scss глобальные ровно по той же причине.

Потребитель (идентично 3)

<ds-button [disabled]="locked()">
  Mark Truck as Completed
  @if (locked()) {
    <span dsButtonSubtext>All kits must be…</span>
  }
</ds-button>

Внутри DS (styles/_button-subtext.scss)

// глобальный, как _dropdown-overlay.scss
ds-button .button:has([dsButtonSubtext]) {
  flex-direction: column; height: auto;
  min-height: var(--hit-cozy); …
  [dsButtonSubtext] { font: …; }
  &[disabled] [dsButtonSubtext] { color: …; }
}
// ds.scss: @forward 'button-subtext';
  • Всё из варианта 3, но селекторы чистые - ни одного ::ng-deep
  • Прецедентный паттерн DS, приложения получают через существующий @use 'styles/ds'
  • Стили кнопки разъезжаются по двум файлам (смягчено комментарием-указателем)
  • Глобальный селектор обходит инкапсуляцию - дисциплина только через неймспейс ds-button

5 · Класс на host + ручная синхронизация возможен, не делали

Детекция руками: потребитель сам говорит кнопке "ты двухстрочная".

Потребитель

<ds-button
  [disabled]="locked()"
  [class.with-subtext]="locked()"  // условие #1
>
  Mark Truck as Completed
  @if (locked()) {                // условие #2
    <span dsButtonSubtext>All kits must be…</span>
  }
</ds-button>

Внутри DS

:host(.with-subtext) .button {
  flex-direction: column; height: auto; …
}
// детекция без :has, НО спан всё равно чужой:
// его стили - опять ::ng-deep или глобальный
// партиал. От главной проблемы не спасает.
  • Детекция без :has() - работает даже в старых браузерах
  • Одно условие в двух местах: забыл класс - кнопка с текстом но без layout, забыл @if - пустая раздутая кнопка
  • ::ng-deep / глобальный партиал для стилей спана всё равно нужен
  • Класс на host - это контракт "потребитель знает про внутренний режим кнопки"

5b · Автокласс через template ref возможен, хрупкий

Автоматическая детекция без директивы: contentChild умеет искать по имени template reference (строка = имя ref, не CSS-селектор - голый атрибут для query API невидим). Потребитель помечает спан рефом, кнопка сама ставит класс.

Потребитель

<ds-button [disabled]="locked()">
  Mark Truck as Completed
  @if (locked()) {
    <span #dsButtonSubtext>All kits must be…</span>
  }
</ds-button>
// импортов нет - ref работает сам

Внутри DS

private readonly subtext =
  contentChild('dsButtonSubtext');
// classes: subtext() ? 'has-subtext' : ''

// ПРОБЛЕМА: #ref не оставляет следа в DOM.
// Спан анонимен для CSS - стилить его можно
// только по .has-subtext > :last-child (хрупко)
// или держать ВТОРОЙ маркер-атрибут для стилей.
  • Автокласс без директивы и без импортов, отслеживает @if
  • Детекция без :has() - не зависит от поддержки браузера
  • Ref невидим для CSS: либо хрупкий :last-child, либо два маркера на одном спане (ref + атрибут)
  • ng-content select по ref тоже не умеет - именной слот теряется
  • Стили спана: всё равно ::ng-deep или глобальный партиал

5c · Автокласс через querySelector отвергнут по конвенциям

В afterContentInit спросить у DOM, есть ли внутри [dsButtonSubtext], и поставить класс.

Внутри DS

ngAfterContentInit() {
  this.hasSubtext.set(
    !!this.host.nativeElement
      .querySelector('[dsButtonSubtext]'),
  );
}

Почему нет

// 1. Проектная конвенция: no querySelector,
//    только ViewChild/template refs.
// 2. Снимок один раз: @if потребителя меняет
//    DOM позже - класс не обновится. Лечится
//    только MutationObserver'ом - несоразмерно
//    задаче.
  • Без директивы, без :has(), маркер - тот же атрибут
  • Нарушает правило "no querySelector"
  • Не отслеживает @if - нужен MutationObserver, что хуже самой проблемы
  • Стили спана: всё равно ::ng-deep или глобальный партиал

6 · Subtext красит сам потребитель отвергнут концептуально

DS отвечает только за layout (через любую детекцию), а шрифт/цвет спана - стили страницы: спан создан в её шаблоне, её scoped-стили его видят без ::ng-deep.

Потребитель (event-kits.page.scss)

[dsButtonSubtext] {
  font: 500 12px/1.4 var(--font-sans);
  color: var(--text-secondary);
}
// …и так на каждой странице, где есть subtext

Почему нет

// Каждая страница изобретает вид subtext
// заново. DS перестаёт гарантировать
// консистентность - ровно то, ради чего
// DS существует.
  • Технически ноль проблем со скоупом - страница красит свой элемент
  • Вид subtext не централизован: дрейф шрифтов/цветов между страницами неизбежен
