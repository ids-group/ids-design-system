Брейкпоинты в @media: токены есть — а внутрь не пускают

DS определяет шкалу брейкпоинтов как CSS-переменные --bp-*. Но custom property нельзя использовать в условии @media — поэтому каждый медиа-запрос в либе хардкодит пиксели вручную, и они уже разъехались с токенами. Решение — добавить compile-time Sass-алиасы $bp-* (резолвятся на сборке). Чисто additive, ничего не ломается.

статус · реализовано 2026-07-07

Что сделано, а что пропущено

  • Модуль _breakpoints.scss — $breakpoints-map (один источник) → --bp-* + $bp-* + up()/down(); дубль --bp-* из _tokens убран. Шипнуто 902c4b1.
  • page-grid мигрирован — @use 'breakpoints' as bp + up(sm)/up(lg)/up(xl); 641/1025→640/1024 (снап, 1px ок), 1441=xl. 260f800.
  • off-scale 720 / 820 / 1100 — пропущено намеренно (вердикт: оставить компонентными). Это content-fit пороги, не ступени шкалы → up()/down() их не выражают; @use в page-header/layout-utils не добавлен. Итог: мигрировано 3 из 6 @media.
  • down() есть как API, но потребителя пока нет (все max-width — те самые off-scale). Задел на будущее.
проблема

var(--bp-*) в @media — мёртв

/* условие @media вычисляется браузером ДО резолва custom properties */
@media (width >= var(--bp-md)) { … }   // ✗ игнорируется, не работает

Из-за этого --bp-* (заданы в _tokens.scss:178-183) фактически декоративны: их видно из обычных правил и из JS, но не в медиа-запросах — там, где они нужнее всего. Итог по факту в либе: 6 медиа-запросов с захардкоженными числами, часть из которых вне шкалы токенов.

Токены говорят 640 / 768 / 1024, а медиа-запросы используют 641 / 720 / 820 / 1025 / 1100 / 1441. Единого источника нет ровно там, где он критичнее всего — отсюда «+1»-привычка и off-scale значения 720 / 820 / 1100. Статус 2026-07-07: page-grid ✅ пофикшено (на шкале, 640/1024); off-scale 720/820/1100 оставлены компонентными (намеренно, не дрейф).

решение

Sass-переменные $bp-* — резолвятся на сборке

@use 'breakpoints' as bp;

@media (width >= bp.$bp-md) { … }   // → компилируется в  @media (width >= 768px)

Sass резолвит $bp-md на этапе компиляции, поэтому его можно подставить в условие. $bp-* и --bp-* не конфликтуют (разные пространства имён); --bp-* остаются для рантайма/JS. Появляется чем переписать те 6 захардкоженных запросов на одну шкалу.

развилки для спеки

Почему это не «просто 6 строк» — три решения

  1. Механизм подключения. В отличие от --bp-* (глобальны через :root-каскад, доступны везде даром) Sass-переменные модульно-скоупленные. А в стилях либы сейчас ноль @use/Sass-переменных/map — всё на CSS-custom-props. Нужен партиал _breakpoints.scss + @use в каждом файле с @media.
  2. DRY: один источник или два? Значения задвоятся (--bp-* + $bp-*):

Дёшево дрейф возможен

// два списка, синхронить руками
$bp-md: 768px;
/* и отдельно в :root */
--bp-md: 768px;

Без дрейфа один источник

$breakpoints: (md: 768px, …);
// --bp-* генерятся из map
:root { @each $n, $v in $breakpoints
  { --bp-#{$n}: $v; } }
  1. Сахар сверху (опционально). Чтобы не помнить range-синтаксис и «+1»-трюк — миксины: @include bp.up(md) → width >= 768px, @include bp.down(sm) → width < 640px.
что делать

План — кратко

  • Завести _breakpoints.scss: Sass-map $breakpoints как единственный источник → @each эмитит --bp-* в :root + экспорт $bp-* и миксинов up()/down().
  • @use его в файлах с @media: _page-grid.scss, page-header.scss, _layout-utils.scss.
  • Аудит off-scale значений 720 / 820 / 1100 — оставить как компонентные или подтянуть к шкале? ✅ Вердикт 2026-07-07: оставить компонентными (не дрейф, а content-fit пороги).
  • Additive: --bp-* живут дальше, ничего не переименовано/удалено; build:deck-css и сборка не затронуты.

Стоимость/риск: низкий. Реальные решения — только три развилки выше; миграция 6 существующих @media — отдельный опциональный шаг с одним спорным местом (off-scale).
