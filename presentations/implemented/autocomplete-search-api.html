ds-autocomplete: ведущая иконка и шеврон

Сегодня слота под иконку нет вообще, а шеврон рендерится безусловно. Три способа это закрыть. Разница видна на третьем ряду примеров — там, где нужны иконка и шеврон одновременно.

Что пишет консюмер и что получает

вариант 1

Слоты + [showChevron]

<ds-autocomplete
  [showChevron]="false">
  <ds-icon dsAutocompletePrefix
           name="search" />
</ds-autocomplete>
поиск в топбаре
Поиск…
иконка И шеврон — работает
Город
хвостовой слот тоже
Валюта USD
Две независимые ручки. Повторяет `dsInputPrefix`/`dsInputSuffix`, которые уже есть в `ds-input` — консюмер не учит второй стиль API. Любая иконка, не только лупа.
вариант 2

variant="search"

<ds-autocomplete
  variant="search" />
поиск в топбаре
Поиск…
иконка И шеврон — недостижимо
только или/или
хвостовой слот — недостижимо
—
Один атрибут, ноль работы у консюмера. Но жёсткая связка: иконка и отсутствие шеврона включаются вместе. Иконка — всегда лупа.
вариант 3

Слоты + [showChevron] + пресет

<ds-autocomplete variant="search" />
<!-- или вручную -->
<ds-autocomplete [showChevron]="false">
  <ds-icon dsAutocompletePrefix … />
</ds-autocomplete>
поиск в топбаре
Поиск…
иконка И шеврон — работает
Город
хвостовой слот тоже
Валюта USD
Умеет всё, что первый, плюс короткая запись для частого случая. Цена — два способа получить один и тот же результат и лишняя строка в доках.

Почему рекомендую первый. Прецедент уже есть: `ds-input` закрывает ровно эту задачу слотами `dsInputPrefix`/`dsInputSuffix`. Второй вариант вводит в библиотеку второй, несовместимый стиль решения той же задачи — и не покрывает случай «иконка и шеврон вместе», который в комбобоксе нормален (шеврон честно говорит, что есть список).

Против третьего. Пресет можно добавить в любой момент поверх слотов, если частый случай станет надоедать. Обратно — нельзя: убрать `variant="search"` из публичного API уже будет breaking. Дешевле начать с малого.

Замечание про `[showChevron]`. По домашнему правилу новые возможности выключены по умолчанию — здесь это значит `showChevron` со значением `true`, то есть текущее поведение не меняется, а консюмер явно его отключает.
