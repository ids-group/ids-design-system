В чём диагноз

103 раза автор вбил в текст ALL-CAPS маркер — ACTION, NO ACTION, TRAP, SCOPE, DECISION RULE, INVERTED VALUE. Это и есть копипаста: каждый такой маркер — место, где поля не хватило, и структуру пришлось изображать заглавными буквами внутри абзаца.

Для человека это читается. Для агента — нет: он разбирает items[] по полям, а маркер в середине 189-словного текста для него такой же символ, как остальные. Ровно так прошла мимо инструкция на удаление, из-за которой мы завели M034.

Один настоящий пункт, до и после

migrations/0.10.0.json#max-visible-chips-zero-inverted — не выдуманный пример. Четыре маркера в одной записке.

Сейчас note — 189 слов

INVERTED VALUE, silent: maxVisibleChips of 0 used to mean 'show every chip' (the old code read 'max && max > 0 ? slice(0, max) : all', and 0 is falsy) and now means 'show NO chips'… DECISION RULE, not a find/replace: replace every 0 that can reach this input — a literal, or an expression that evaluates to 0 — with the BINDING [maxVisibleChips]="null"… TRAP, verified in source: a STATIC maxVisibleChips="null" is NOT equivalent and reintroduces the bug… ALSO SCOPED HERE: Applies identically to ds-multi-select[maxVisibleChips].

После note — 44 слова

action
Заменить каждый 0, который может дойти до maxVisibleChips, на привязку [maxVisibleChips]="null" — литерал или выражение, дающее 0. Читать выражение, питающее вход, а не текст шаблона: греп по литералу пропускает вычисляемые случаи.
pitfall
Статический maxVisibleChips="null" не эквивалентен и возвращает баг: строка 'null' не == null, уходит в numberAttribute → NaN → снова ноль чипов. Настоящий null передаёт только привязка.
appliesWhen
ds-autocomplete и ds-multi-select одинаково.
note
Остаётся только «почему»: 0 раньше значил «показать все чипы», потому что старый код читал max && max > 0, а 0 ложен. Теперь значит «не показывать ни одного». Ничего не падает — триггер просто пустеет.

Три поля

action

Только императив — то, что агент выполняет. Человек читает note, агент читает action. Сюда же уходят те 2 случая «это решение, а не find/replace».

Способ применить пункт механически верно и всё равно получить сломанное приложение. Самый дорогой класс потерь: правка выглядит выполненной, а баг вернулся.

Три правила — без них поля прозу не сократят

Поле само по себе ничего не заставляет: рядом с ним место найдётся, и текст останется прежним.

  • M039 Actionable-пункт без action — ошибка. То, что агент исполняет, не может быть необязательным.
  • M040 ALL-CAPS маркер внутри note — ошибка: значит поле не заполнено. Это и есть прямой запрет на копипасту.
  • M041 note длиннее 120 слов — ошибка. Сейчас таких 64; после выноса трёх полей «почему» обязано укладываться.

Что отверг и почему

  • author Тот же класс, что source, который ты уже отверг: консьюмер не полезет в нашу историю коммитов, ему нужен готовый ответ.
  • place Покрыто трижды — surface, detect, searchHints. Четвёртый локатор это ровно та ошибка, которую отчёт отметил у ESLint: ось уже несётся дважды.
  • outcome / unchanged По твоему слову. Манифест остаётся плоским списком пунктов, без уровня версии.
  • schemaVersion Развернули: у нас нет legacy-уровня, каждый манифест бэкфиллится до текущего контракта, значит поле держит одну константу и ничего не сообщает.
