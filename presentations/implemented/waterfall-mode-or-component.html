Водопад: режим или компонент

Картинка одна и та же — она уже реализована и снята с живой страницы. Отличается только то, как её попросить, и что при этом происходит с API колоночного чарта.

решено 2026-09-24 дека 10, §2

Решено: свой тег

ds-waterfall-chart остаётся отдельным компонентом на общем контейнере и общей серии. Режим stack="waterfall" не вводится: четыре добавки водопада бессмысленны в остальных режимах колонки. Так и отгружено, кода эта дека не требует.

Две разметки

A · Свой тег — как сделано сейчас

Датум несёт kind, три цвета назначает сам компонент. 

<ds-waterfall-chart
  caption="Settlement"
  [data]="[
    { label: 'Billed',     value: 1200, kind: 'total' },
    { label: 'Commission', value: -320 },
    { label: 'Refunds',    value: -210 },
    { label: 'Adjustment', value:  130 },
    { label: 'Net',        value:    0, kind: 'total' },
  ]" />
Колоночный чарт остаётся про сравнение категорий. Переиспользование уже есть: тот же ds-chart, та же dsColumnSeries.
Ещё один тег в каталоге и ещё одна страница в доках.

B · Режим колоночного чарта

stack="waterfall" плюс kind на точке. 

<ds-column-chart
  caption="Settlement"
  stack="waterfall"
  [data]="[
    { label: 'Billed',     value: 1200, kind: 'total' },
    { label: 'Commission', value: -320 },
    { label: 'Refunds',    value: -210 },
    { label: 'Adjustment', value:  130 },
    { label: 'Net',        value:    0, kind: 'total' },
  ]" />
Одним компонентом меньше. Три куска из шести уже бесплатны: смещения { from, to }, цвет на точку и накопление через stackOffsets.
В API колоночного чарта появляются kind, связки, подписи со знаком и трёхцветная семантика — и все они бессмысленны в остальных четырёх режимах stack.

Первые четыре строки говорят «то же самое». Последние четыре говорят «другая вещь». Дека 10 писалась до того, как контейнер ds-chart появился, и утверждала, что водопад не может быть режимом вообще — это оказалось сильнее, чем есть на самом деле: код уже переиспользован, спор остался только про тег и про то, чей API растёт.

Рекомендация — оставить своим тегом (A). Четыре последние строки таблицы не нужны ни одному из четырёх режимов stack, а вход, который бессмысленен в четырёх случаях из пяти, читается как ловушка. Выигрыш варианта B — минус один тег в каталоге; он уже оплачен тем, что реализация сидит на общем контейнере и общей серии.
