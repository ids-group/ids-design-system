Обрезка значения ds-stat

.value живёт с white-space: nowrap и без правила про переполнение: «Feb 1 – Feb 28, 2026» на 36px это 348px в плитке с внутренними 190px — 158px за краем, поверх соседа. Прошлая версия этой деки предлагала выбрать один из пяти дефолтов. Три из пяти описаны в ней неверно, и выбирать надо не из пяти вариантов, а из трёх независимых ручек — а обрезку DS уже реализовал в 11 компонентах одним миксином.

Три ошибки прошлой версии — все перемерены

1. Вариант 3 срезал выносные элементы. overflow: hidden при --line-height-flat: 1 режет глиф снизу: строчный бокс 36px, Mulish меряет 1.257em. Снято по пикселям с плиток выше — хвост «руб.» уходит на 4px ниже бокса при visible и при clip, и только на 1px при hidden: три четверти хвоста нет. Дека рекомендовала hidden вторым номером.

2. Вариант 5 не подгоняет кегль под текст. clamp(0.875rem, 9cqw, …) следит за шириной контейнера, а не за длиной строки. В контейнере 140px кегль упирается в пол 14px, и длинное значение всё равно уходит 340px за край. Чистого CSS-механизма «ужать шрифт под текст» не существует. Плюс само число в деке было неверным: она рендерила 21.6px / 96px, а в таблице стояло 17.1px / 92px.

3. Вариант 2 не удерживает текст в карточке. Слово шире плитки выходит за неё и при white-space: normal: «Северо-Западный» уходит 69px за край. Держит только overflow-wrap: anywhere — ценой 8 строк вместо 6.

DS это уже решил — 11 компонентов, один миксин

text-clip.single-line-ellipsis из src/lib/styles/_text-clip.scss подключён в autocomplete, banner, breadcrumbs, multi-select, page-header, select, sidenav-item, sidenav-footer, table, topbar, tree и _dropdown-overlay. ds-stat — единственный компонент с длинным текстовым значением, который его не использует. 

@mixin single-line-ellipsis {
  overflow: clip;                        /* не hidden: см. срез выносных */
  overflow-clip-margin: var(--space-1);
  text-overflow: ellipsis;
  white-space: nowrap;
}

Чем держать по горизонтали ничего · ellipsis · anywhere Ellipsis нужен и при 1 строке, и при N. anywhere нужен отдельно — он единственный держит слово длиннее плитки.

Комбинации складываются, и «перенос с эллипсисом» — это строки = N плюс ellipsis, то есть -webkit-line-clamp. Отдельной формы у него нет: text-overflow работает по инлайну, поэтому многоточие на последней из N строк даёт только clamp. Префикс обязателен — line-clamp без -webkit- в Chrome 153 не парсится вообще (getPropertyValue возвращает пустую строку), и display: -webkit-box с -webkit-box-orient по-прежнему обязательны: без них clamp не срабатывает, проверено.

Как это меряется. Высота строки ровно 36px, поэтому число видимых строк — это clientHeight / lineHeight, а не рамки Range: при --line-height-flat: 1 глиф выше строчного бокса, рамки перекрываются и дают на строку больше — первый прогон так и посчитал у clamp 1 две строки вместо одной. scrollHeight > clientHeight истинно у всех комбинаций по той же причине и как детектор не годится вообще.

Что покажется при наводке

Сегодня — ничего. CSS-обрезка не даёт никакого тултипа: ни text-overflow, ни clamp не показывают полное значение ни по ховеру, ни по фокусу. Но в DS механизм уже есть, и он не сводится к title: ds-table ставит title (нативный тултип по ховеру) и открывает ds-popover с полным текстом по клику, а вешает это на гейт isClipped() — scrollWidth > clientWidth на самом элементе и на потомках. Таб-стоп на ячейку она сознательно не добавляет.

КомбинацияДетектор scrollWidth > clientWidthСравнение числа строк

Это аргумент за «одну строку» как дефолт. При обрезке в одну строку факт обрезки виден из одного сравнения на самом элементе — тот самый гейт, который уже написан в таблице. При clamp он молчит: чтобы понять, что строка спрятана, нужен скрытый двойник и ResizeObserver. overflow: clip детектору не мешает — проверено здесь и записано в table.component.scss.

Рекомендация

Дефолт — одна строка миксином DS. Высота плитки не меняется (111px, как сегодня), выносные целы, ряд KPI остаётся ровным, и ds-stat перестаёт быть единственным компонентом со своей обрезкой. Обрезка оптическая: текст остаётся в DOM целиком, скринридер читает всё.
Больше строк — опция: --ds-stat-value-lines поверх clamp. Второй хук --ds-stat-value-wrap: anywhere для значений, где одно слово шире плитки — он нужен отдельно и ни из чего не следует.
Раскрытие — забрать из таблицы, а не писать заново. Это второе место в DS с той же задачей: title + ds-popover по клику, гейт по scrollWidth. Без таб-стопа внутри плитки.
Кегль по контейнеру — не как «подгонка». Он не решает переполнение; если хук и нужен, то под честным именем и без обещания, что после него ничего не вылезет.
