Как второй серии попасть в чарт

Две модели композиции, и место, где между ними видна разница: не в обычном случае, а во втором марке на том же плоте.

Решено публичный API пяти чартов не меняется

Решено: Проецируемые дети, а не массив серий

Марк - это атрибут на настоящем <svg:g>, который инжектит контейнерные шкалы и сам сообщает свой домен. Контейнер не знает, какой марк он держит, - поэтому опорная линия, колоночная серия и линия делят одну ось, ничего друг о друге не зная.

Вот что надо уметь нарисовать

Одна карточка панели: объём столбцами, план линией, целевой уровень и коридор SLA. Четыре разных вида элемента в одном плоте — это и есть вся задача.

Объём — столбцы План — линия Цель — референсная линия SLA — полоса

Две модели

A · Проецируемые дети

Observable Plot (массив марок), Recharts (ComposedChart с детьми JSX)

<ds-chart [categories]="months">
  <ds-column-series [data]="volume" />
  <ds-line-series [data]="plan" />
  <ds-reference-line [value]="800" />
  <ds-reference-band [from]="900" [to]="1050" />
</ds-chart>
Референсная линия — такой же ребёнок, как серия. Добавить её стоит ноль нового механизма.

B · Массив серий с type

ECharts, Highcharts, AG Charts, Chart.js, MUI X

<ds-chart
  [categories]="months"
  [series]="[
    { type: 'column', data: volume },
    { type: 'line',   data: plan }
  ]"
  [annotations]="[{ value: 800 }]"
  [plotBands]="[{ from: 900, to: 1050 }]" />
Референсная линия не серия, поэтому ей нужен второй вход, свой тип и своя отрисовка.

Разница не в красоте разметки. В модели A референсная линия, полоса и вторая серия — один вид вещи, поэтому пятый элемент добавляется тем же механизмом, что четвёртый, и никто потом не строит TargetLineChart. В модели B аннотации прикручиваются отдельно — и это ровно то, что видно у каждой библиотеки, которая её выбрала.

Механизм уже есть в доме

Родитель, делающий contentChildren, и ребёнок, инжектящий родителя, импортировали бы друг друга по кругу. InjectionToken с интерфейсом контракта — то, как этот репозиторий уже решает эту задачу: см. radio-group.token.ts. 

export interface ChartScales {
  readonly plot:        Signal<ChartPlot>;
  readonly xPosition:   Signal<(index: number) => number>;
  readonly yPosition:   Signal<(value: number) => number>;
  readonly activeIndex: Signal<number>;
  reportDomain(id: string, values: readonly number[]): void;
}

export const CHART_SCALES = new InjectionToken<ChartScales>('CHART_SCALES');

Прецеденты той же формы в библиотеке: ds-table, ds-filter-bar, ds-tabs, ds-accordion, ds-select. Новой идеи здесь нет — есть перенос той, которой уже пять применений.

Чем платим

ЧтоЦена
Пять существующих чартов Становятся пресетами над контейнером. ds-bar-chart — это ds-chart с одной ds-bar-series и горизонтальной ориентацией. Ни один публичный вход, выход или токен не меняется — это доказывает check:public-api, а не обещание.
Порядок работ Контейнер идёт вторым, сразу после дефектов, и до него ничего из фазы 2 строить нельзя. Это самая ранняя и самая крупная задача плана.
Риск Рефакторинг пяти работающих компонентов без тест-раннера. Страховка — скриншот каждой карточки до и после, и check:public-api без диффа.
Контрольная точка После контейнера и до новых марок: контейнер либо удешевил остальное, либо нет, и ответ записывается до начала следующей стадии. В фазе 1 эту точку пропустили, поэтому оговорку про «если займёт втрое дольше» никто не проверил.

Рекомендация — модель A, проецируемые дети. Не потому, что разметка красивее, а потому что после неё референсная линия из §3.3 плана стоит ноль дополнительного механизма, а комбинированный чарт и аннотации перестают быть отдельными задачами.
