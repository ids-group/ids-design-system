Should state default a glyph?

ds-field-message takes state (which sets the colour) and icon (which nothing sets by default). The question is whether each state should bring its own glyph — error, warn, success, info are already in the icon set, drawn below from their real paths. Every colour here is the shipped token value, measured in the browser: --error-text #BA1717 / #F58484, --warning-text #8A7400 / #F5CA47, --success-text #156822 / #69D37E, --text-tertiary #6B7388 / #8A93A6.

The whole case in one row: in the light theme warning is an olive #8A7400 and success a green #156822. Look at the two without glyphs and ask which is which at a glance, then look again with them. That is the reason four of the six systems audited for the fill question carry a per-state icon, and why WCAG 1.4.1 exists.

What each option costs

OptionWhat changesCost
A · nothing (today) Only icon, set by hand. The docs already say state decides the colour and nothing else. Warning and success stay a hue apart and nothing else — the case WCAG 1.4.1 names. No consumer has asked, and no field ships an icon today.
B · glyph on all four Every message row in the library grows a 14px glyph, hint included. Breaking by appearance on 14 components at once, and section 3 is what a settings form then looks like. Also a per-state glyph choice to defend.
C · glyph on error / warning / success, none on hint The three states that carry meaning gain one; the default row is untouched. Still breaking by appearance, but only where a state is actually set — which is the minority of rows on any screen. One inconsistency to explain: why hint is bare.
D · opt-in per app A DS_CONFIG.field.stateIcons switch, off by default; C's behaviour when on. Nothing breaks, and every app has to know the switch exists to get the accessible default. Postpones the decision rather than making it.

Recommendation: C. Reasons, in order:

  • It buys the distinctness exactly where the deck shows it missing — warning against success — and nowhere else.
  • The busy column in section 3 is entirely hint, and C leaves it alone. Hint is not a state; it is the resting text.
  • The glyphs already exist in the icon set (error, warn, success), so there is no new drawing to defend.
  • It is still a visual breaking change on the fields where a state IS set, so it belongs in the same release as the other queued ones rather than as a drive-by.

Against it, honestly: Spectrum and Carbon put the glyph on every row including help text, so C is our own line rather than a copied one. And nobody has asked for this — it came out of our own audit, which is a weaker signal than a consumer report.
