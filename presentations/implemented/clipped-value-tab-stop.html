Почему C, цена каждого, источники

Почему C: одна остановка на таблицу, весь текст виден сразу, без новой модели клавиш; A остаётся по умолчанию там, где кнопки нет.

A - ветка как есть. Паттерн таблицы APG: в статичной таблице все фокусируемые элементы в порядке Tab. Цена: в таблице на 25 строк с двумя обрезанными колонками - 50 остановок без действия (замер выше).

B - roving tabindex: одна ячейка с tabindex="0", остальные -1, стрелки между обрезанными. APG описывает это для composite-виджетов, то есть таблица должна стать role="grid"; иначе скринридер в режиме чтения сам забирает стрелки. В ds-table (652 строки шаблона, 1742 строки класса) это клавиатурная модель грида: стрелки, Home/End, PageUp/PageDown, сосуществование с кнопками сортировки, чекбоксами выбора, редактируемыми ячейками и фокусируемыми строками. Плюс отдельная директива-группа для своих таблиц потребителя (Delta Review - не ds-table). Оценка, не замер: 300-600 строк в библиотеке плюс документация и пробы, по размеру ds-table и списку клавиш APG grid.

C - моё предложение; готового образца в чужих DS не нашёл, ближе всего ICDS («See more/see less» на ячейке, в порядке Tab). Кнопка у таблицы снимает обрезку у всей таблицы; пока такая кнопка есть, обрезанные значения внутри не получают своих остановок. В ds-table - вход у колонок с truncate, для своих таблиц - директива на контейнере. Оценка, не замер: 100-200 строк в библиотеке.

  • APG: Developing a Keyboard Interface - «the tab sequence should include only one focusable element of a composite UI component»; roving tabindex.
  • APG: Grid pattern - «Only one of the focusable elements contained by the grid is included in the page tab sequence»; grid «particularly useful if the tabular information is editable or interactive»; в обычной таблице «All focusable elements contained in a table are included in the page tab sequence».
  • WCAG 2.2 Understanding 1.4.13 - то, что открывается наведением, должно открываться и фокусом.
  • ICDS data table accessibility - без лишних остановок в таблице; обрезка через тултип или «See more/see less».
  • Nord Truncate - тултип по наведению и фокусу; без тултипа только если полный текст есть на странице.
  • PatternFly #8758 - VoiceOver фокусирует содержимое ячейки; скринридер и так читает полный текст.

Правило, источники, замеры, проверки

Правило

Хост dsTooltipWhenClipped получает tabindex="0", пока обрезан, если: сам не фокусируемый; вокруг нет нативного контрола (a[href], button, поле), виджетной роли (button, link, tab, option, menuitem, row, gridcell, combobox, checkbox, radio, switch, treeitem) или tr с tabindex; внутри нет фокусируемого; не внутри aria-hidden="true" или inert. Стал влезать - атрибут снимается, но только если хост не в фокусе (иначе после blur). Чужой tabindex не трогается; tabindex="-1" на хосте - способ убрать значение из Tab.

Отличие от брифа: фокусируемый контейнер (tabpanel, область прокрутки, диалог с tabindex="-1") не мешает остановке, потому что фокус на нём тултип не открывает. Опции списков (role=option) не получают остановку: фокус там ведёт listbox.

Роль на хост не ставится. Так делает пример обрезанного текста в Brio: focusable span с tabindex="0" без роли, тултип с role=tooltip. Правило axe focus-order-semantics такой span отметило бы, но оно помечено experimental. aria-describedby как раньше: не ставится, когда тултип повторяет текст хоста.

Наблюдение: один общий ResizeObserver и один MutationObserver на все хосты. В директиве своего ResizeObserver не было, проверка обрезки шла только при открытии.

Источники

  • WCAG 2.2 Understanding 1.4.13: «Content which can be triggered via pointer hover should also be able to be triggered by keyboard focus», ссылка на 2.1.1 Keyboard.
  • APG Tooltip pattern: тултип по фокусу или наведению, Escape закрывает, триггер ссылается через aria-describedby.
  • Brio tooltip: «Wrap the truncated text in a focusable span so keyboard users can reach it too».
  • axe-core focus-order-semantics: tags best-practice, experimental.
