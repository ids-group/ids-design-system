§1

Компактный триггер фильтра

G1, A5

Тулбару доски нужен триггер с фиксированным следом: подпись, счётчик, признак активности. Такого режима нет ни у одного пикера — из-за этого консюмер написал app-filter-select на ~250 строк под четыре фильтра.

КомпонентЧто в триггереЧипыСвоя ширинаСлот триггераПресет «метка + счётчик»
ds-selectодна метканетнетдане нужен
ds-multi-selectчипы + «+N more»данетдада
ds-autocompleteзначение, а в multiple чипыдада · width="content"дада · только в multiple

Слот — всем трём, пресет — только где есть счётчик. Слот ничем не привязан к числу значений: компонент отдаёт свой элемент триггера с ARIA и клавиатурой, внутрь проецируется чужая разметка — цена одинаковая для всех трёх. Пресет «метка + счётчик» осмыслен там, где значений много: мульти-селект и автокомплит в multiple. У одиночного ds-select считать нечего, и пресет вырождается в «метка + значение» — это и есть его нынешний триггер.

Чипы и у мульти-селекта, и у автокомплита — одинаковые ds-tag в общем chip-row. Высота триггера у обоих уже фиксирована: maxVisibleChips по умолчанию 'fit' обрезает чипы, а не переносит.

multi-select.component.html:67–90 рендерит строку поиска всегда — даже над четырьмя опциями, которые целиком видны. Убрать строку = перенести это на триггер.

O4Один вход, три значения: searchable: boolean | numberрекомендую

true — всегда показывать, false — никогда, число — порог прямо здесь. Отдельного 'auto' не нужно: число само означает «считай». 

<ds-multi-select />                        <!-- true, как сейчас -->
<ds-multi-select [searchable]="false" />   <!-- четыре опции -->
<ds-multi-select [searchable]="8" />       <!-- порог виден в разметке -->

Значение по умолчанию берётся из provideDsConfig, поэтому приложение может один раз сказать «везде считай от восьми», а конкретная панель — перебить это числом или выключить совсем.

Цена: у входа три типа значений вместо двух — это надо описать в документации одной строкой.
O1Два входа: searchable: boolean | 'auto' и searchThreshold

searchable: boolean | 'auto'. В режиме 'auto' библиотека считает сама, а порог берёт из provideDsConfig — один на приложение, задаётся там же, где размер контролов. Нужен другой порог на конкретной панели — вход searchThreshold перекрывает конфиг. 

provideDsConfig({ picker: { searchThreshold: 8 } })

<ds-multi-select searchable="auto" … />
<ds-multi-select searchable="auto" [searchThreshold]="20" … />

Библиотека считает по умолчанию, консюмер может вмешаться — без выбора между этими двумя.

Цена: порог типового случая живёт в конфиге, а не в разметке — чтобы узнать, почему поиск появился, надо посмотреть конфиг приложения.
O2Только boolean

Порог считает консюмер сам.

Цена: одна и та же проверка в каждом консюмере, разные пороги в одном приложении.
O3Только вход searchThreshold, без конфига

Порог задаётся на каждой панели отдельно.

Цена: в одном приложении панели начинают вести себя по-разному, потому что порог никто не свёл к одному.

Варианты унификации

U1Один вход, union — форма ds-select для всехвыбрано

options принимает и опции, и группы: DsOption | DsOptionGroup. Второй вход у автокомплита исчезает, вместе с правилом «один молча побеждает».

Это ровно то, что 0.10.0 уже сделал с самой опцией: три почти одинаковых интерфейса свели к общему DsOption, оставив каждому своё имя. Здесь то же самое для группы.

  options: DsOption<T>[];
  disabled?: boolean;
}
Цена: у автокомплита меняется способ передачи групп — миграция. Плюс союзный тип надо разбирать type guard'ом в трёх местах вместо одного.
U2Два входа везде — форма ds-autocomplete для всех

options и optionGroups у всех трёх. Типы проще: никакого union и никакого guard'а.

§7

Панель автокомплита

A4, X1

Выпадающая панель живёт не внутри компонента: CDK вставляет её в конец <body>. Обычные стили компонента туда не достают, поэтому в библиотеке есть один общий файл стилей для всех таких панелей, и подключается он тем, что панель получает класс ds-dropdown-panel.

ds-select и ds-multi-select этот класс получают. ds-autocomplete — нет: ему передают 'ds-overlay-pane', и этот аргумент не добавляется к списку, а заменяет его целиком. Одна строка кода — autocomplete.component.ts:479.

Что из этого следует. У автокомплита своя копия стилей опций, отбивка панели 0 вместо 4px, углы строк квадратные — и четыре публичных токена темы (--ds-option-selected-*) до него не доходят. Перекрасит бренд выбранную строку — у select и multi-select перекрасится, у автокомплита нет.

Он не «недопилен»: он был написан отдельно и разошёлся с остальными двумя.
