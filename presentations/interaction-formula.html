Интеракции по формуле v2: калибровка по нарисованной рампе

v1 глушила цвета, потому что смешивала с чёрным. v2 — та же единая формула, но направление смешивания зависит от контекста: светлые брендовые тинты темнеют в сторону бренда, нейтральные поверхности — в сторону холодных «чернил» hsl(215, 35%, 45%), тёмные базы — к белому. Проценты откалиброваны так, что формула попадает в нарисованные стопы рампы почти точно (pressed-чернила = ровно neutral-150, tertiary = ровно blue-50/100). Наводи мышь, зажимай для pressed, сравнивай триады «база / hover / pressed».

Формула одна, контексты задают направление и шаг

/* styles/_interaction.scss — формула живёт ровно один раз */
.ds-interactive {
  --interactive-hover:  var(--interactive-hover-set,  color-mix(in srgb, var(--interactive-base) calc(100% - var(--state-step-hover)),   var(--state-into)));
  --interactive-active: var(--interactive-active-set, color-mix(in srgb, var(--interactive-base) calc(100% - var(--state-step-pressed)), var(--state-into)));
}
/* --interactive-*-set — слот ручного override: где формула груба, дизайнер
   задаёт точный цвет, формула остаётся fallback (см. вопрос В4 ниже) */
/* контекст        база          куда темнеем        hover/pressed   попадание в рампу */
/* заливка         primary       black               12% / 24%       = текущая тема    */
/* тинт            blue-100      бренд               14% / 28%       blue-200 точно    */
/* бренд-чернила   transparent   бренд                7% / 14%       blue-50/100 точно */
/* нейтр. чернила  transparent   hsl(215,35%,45%)   6.5% / 13%       n-100 ~, n-150 =  */
/* тёмная база     n-900         white              6.5% / 13%       n-800 ~           */
/* текст/ссылки    text-link     black               20% / 35%       = текущие         */
Брендовый --primary: Меняется ТОЛЬКО --primary: брендовые чернила и тинт-направление следуют сами.

Как делают лучшие (проверено по первоисточникам, полный отчёт — docs/interaction-states-research.md)

Система Механизм состояний pressed vs hover Против «грязных» цветов
Material 3 формула в рантайме: state layer с фикс. opacity ≈ 1.25–1.5× слой цветом on-color (родственный hue), не чёрным
Fluent 2 ручные ступени рамп (alias-токены) немонотонно: в dark hover светлее, pressed темнее направление к контрасту с фоном
Carbon ступени рамп + рукописные half-steps для hover active ≈ 4× hover переворот направления на середине шкалы (Gray 70/60)
Radix фикс. индексы 12-шаговой рампы (3/4/5, 9/10) 2× (дискретно) кураторская chroma шага 9
Spectrum генерация на сборке (Leonardo, contrast ratios) + ручная курация равные шаги (+1 / +1) CIECAM02-UCS + ручная кривая lightness

Выводы для v2: наши пресеты направления (к бренду / к чернилам / к белому) совпадают с приёмами M3 и Carbon; «pressed = 2×hover» — у всех лишь калиброванный дефолт, не закон (у нас шаги тоже свои на контекст); Spectrum от первого лица: чистый алгоритм без калибровки эстетически провалился — поэтому v2 калибрована по нарисованной рампе. Carbon сам признал рукописные half-steps техдолгом и хотел заменить вычисляемым затемнением (issue #4049) — прецедент нашего подхода.

7. Концерны и ограничения

К1. Рантайм color-mix в проде не делает никто из проверенных систем — все запекают значения на этапе дизайна/сборки; ближайший аналог нашего подхода — state layers Material 3. Митигация: override-слоты (В4) + прецедент Carbon #4049 (сами хотели заменить рукописные half-steps вычисляемым затемнением).

К2. Поддержка браузеров: color-mix — baseline с 2023 (Chrome 111+, Safari 16.2+, Firefox 113+); у нас он уже в проде в теме (--primary-hover) — риск не новый.

К3. Класс в шаблоне: контракт вешается классом ds-interactive (+ пресет) на каждый интерактивный элемент. При миграции старые state-правила компонента удаляются — иначе они перекроют контракт по специфичности.

К4. Тёмная тема — отдельная калибровка: у всех проверенных систем в dark mode другие направления и шаги (Fluent даже немонотонен: hover светлее, pressed темнее). Токены v2 это умеют (--state-into, шаги), но числа надо вывести заново, не переиспользовать светлые.

К5. Прозрачные слои зависят от подложки: для tinted-фонов это фича (карточка 3), но перед массовой миграцией прогнать реальные экраны ds-docs — особенно вложенные поверхности (меню на карточке на канвасе).

Что остаётся в компоненте

/* button.component.scss — токен-блок наверху, только необходимое */
.button            { --interactive-base: var(--primary); }            /* заливка */
.button.error      { --interactive-base: var(--error); }
.button.secondary  { --interactive-base: var(--primary-muted); }      /* + класс tint */
.button.tertiary   { /* класс accent-ink — даже базы не нужно */ }
.menu-item         { /* класс surface — и всё */ }

/* уходит: --ds-*-bg-hover / -active на каждый вариант, локальные color-mix,
   ramp-пики состояний. Калибровочные проценты живут в _tokens.scss. */

Проверка калибровки: tint hover = blue-200 (Δ 0.5), tertiary hover/pressed = blue-50/100 (Δ 0.4 / 1.1), чернила pressed = neutral-150 (Δ 0.5), чернила hover ≈ neutral-100 (Δ 2.7), inverted ≈ neutral-800 (Δ 3.1). Δ — расстояние в RGB-каналах, ниже ~4 глазом не отличить.
