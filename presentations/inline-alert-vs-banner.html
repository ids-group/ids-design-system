ds-banner vs inline alert — нужен ли отдельный компонент?

Это разные работы (Carbon / Atlassian / BC gov). Banner (уже в либе, ds-banner) — системный/страничный нотис: заметный, во всю ширину, сверху области, с иконкой + заголовком + действиями + dismiss + accent-bar; сообщает про страницу/систему в целом. Inline alert — контекстное сообщение В ПОТОКЕ контента, рядом с тем, к чему относится (валидация над формой, заметка в карточке): легче, компактнее, без заголовка/действий по умолчанию, по ширине контента.

В контексте — где живёт каждый

Banner — «шапка» области. Inline alert — внутри контента, привязан к конкретному месту.

Вывод (проверено в либе и ds-docs): отдельного inline-alert компонента нет, но ds-banner уже близок — у него есть [compact] (узкие паддинги, одна строка), layout="row" (иконка + текст + actions в строку), [accentRail]="false" (без левой рейки) и 6 статусов (вкл. neutral) + dismissible + проекция actions. В самих доках банера уже есть подсекция «Inline» — банер без карточной обводки внутри панели — но она сделана docs-only через ::ng-deep, и в комментарии секции прямо стоит: «DS itself has no inline mode». Итого: строительные блоки есть, первоклассного inline-режима в либе — нет.
Варианты решения: (A, реком.) поднять docs-рецепт до первоклассного режима ds-banner — флаг [inline] (убирает фон/обводку/паддинги → лёгкая in-flow заметка); снимает ::ng-deep-хак, без нового компонента; (B) отдельный лёгкий ds-alert (иконка + текст, по ширине контента, без title/actions/dismiss по умолчанию) — чистое разделение ролей, но дублирует banner; (C) ничего не добавлять — задокументировать compact + layout="row" + [accentRail]="false" как официальный inline-паттерн.
