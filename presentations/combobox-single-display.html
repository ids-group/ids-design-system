V2 · single-combobox с выбранным значением — 5 вариантов, все живые

Вопрос: как должен выглядеть и вести себя single-ds-combobox, когда значение уже выбрано. Кликайте и табайте в каждый — поведение настоящее (CSS/мини-JS, как будет в компоненте). Панель со списком тут мокнута только в варианте E, в остальных представьте её открытие как сейчас.

Варианты

0 · Сегодня baseline Значение + вечно развёрнутый пустой инпут (cursor: text). Читается как поле свободного ввода — исходная жалоба PIN-475.
A · Инпут схлопнут рядом Закрыт — как select. Клик/Tab → пустой инпут разворачивается рядом со значением: старое значение остаётся видно, пока печатаешь. Минус: два элемента, каретка «около» значения.
B · Инпут ВМЕСТО значения идея Stas · Ant/react-select Закрыт — как select. Клик/Tab → значение заменяется инпутом, старое значение остаётся серым «призраком» (placeholder), пока не начнёшь печатать. Blur/Esc — значение возвращается.
C · Значение живёт В инпуте MUI Autocomplete Никакого отдельного «спана»: текст значения — это текст инпута. Клик → текст выделяется целиком, печатаешь — заменился (фильтр с нуля). Esc/blur — значение восстанавливается. Ноль layout shift; cursor: text (честное «можно печатать»).
E · Поиск в панели PrimeNG / Select2 / shadcn

Триггер — чистая кнопка-select всегда (и пустой, и заполненный). Поле фильтра живёт сверху открытой панели. Значение в триггере видно всё время, пока ищешь замену.

Заметки ui-ux-pro-max

Input Affordance: контрол должен выглядеть тем, чем является — «выбрано одно значение» ≠ «введи текст»; это довод против 0 и наполовину против C (C честен, но по-другому: он говорит «можно печатать», а не «выбери из списка»). Content Jumping: избегать layout shift при взаимодействии — сильная сторона C и E, слабое место A. Focus States: во всех вариантах кольцо фокуса на триггере сохраняется (:focus-within не трогаем). Cursor: закрытое состояние — pointer (A/B/E), у C — text.
