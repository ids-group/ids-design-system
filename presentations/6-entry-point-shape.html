Проблема. Дека 4 решила что строить. Здесь — как. Ключевой факт: ng-packagr называет entry point по пути папки, дословно, и опции переименовать нет. Значит структура папок становится публичным API навсегда.

307 переписанных импортов — одинаково во всех вариантах. Импорту, ставшему публичным специфером, всё равно, как глубоко лежит файл. Поэтому C дороже только на 71 механический git mv плюс дом для 23 свободных файлов.

корень пакета уезжает в src/lib, ng-packagr перестаёт читать корневой package.json, а cut-release.sh:75 читает его. Релиз поднимет одно число, опубликует другое — молча неверная версия в npm		 естьестьнет
typesVersions нужен
короткий алиас не имеет папки на диске, а node10 игнорирует exports и ищет папку		 нетнетда, обязателен

Ловушка с версией лечится генерацией src/lib/package.json из корневого в prebuild — репозиторий уже так делает для tokens.generated.ts. typesVersions — это одно генерируемое поле в том же шаге сборки, что пишет точки.

Рекомендация: E

Специферы как у Material, ноль перемещений файлов, корень пакета на месте, релизный конвейер не трогаем. Проверено на настоящем node_modules (не через paths, иначе карта exports не участвует): резолвится, размещение верное — ленивый компонент в стартовом бандле 0 раз, и одна идентичность класса через короткий и длинный путь.

Шероховатость E: собственные импорты библиотеки придётся писать длинными специферами, пока потребитель видит короткие. Два словаря — некрасиво внутри, чисто снаружи. C — если важнее, чтобы диск совпадал со специферами.
