Disabled, on a button with no fill

The report: a ghost Clear in a list toolbar reads as enabled, just quieter — the label stays fully legible and only the tint moves. Two things in the filed item turned out to be wrong, and both matter for the fix.

It is not opacity. ds-button and ds-icon-button never read --opacity-muted — their disabled state is a set of oklch(from accent …) colours. So the consumer override that retunes --opacity-muted on those two selectors changes nothing at all; it is a no-op, like the table-head background before it.

And it is not every button. The recipe pins the disabled label at 58% lightness, which is roughly where a saturated accent already sits — so the two states differ in chroma alone. On color="neutral", where the enabled label is nearly black, the same recipe is fine.

How to read a cell. Two words: the label enabled, then disabled. The swatches under them are those same two colours painted as gradients, so a force-dark browser cannot rewrite them. The last line is how far apart the two states are — under 1.8:1 the state is a guess.

What each choice means.
  1. B — neutral label where there is no fill. One rule, and it says the honest thing: disabled is a STATE, not a shade of the brand. It has to be scoped to the fill-less variants (ghost, text) — the solid column above shows why applying it everywhere would be wrong.
  2. C — keep the hue, raise the lightness. Reads as the smaller change, one number in one place, and it keeps the family feel. But it moves every variant at once, including the solid label on its 92% tint, which is the pairing to check before shipping it.
  3. A — today. Correct on neutral, indistinguishable once the accent is saturated. That is exactly the case that was reported, so leaving it means telling the consumer to override per colour.
