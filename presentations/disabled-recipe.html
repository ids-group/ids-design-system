Disabled, across every variant and state

The real case, read out of the consumer today. projects/common/components/src/lib/list-search/list-search.component.html renders <ds-button variant="ghost" size="sm" icon="x" [disabled]="!canClear()">Clear</ds-button> — ghost, and no color, so it takes the default primary. That is the pairing with the smallest gap in the whole matrix below.

Their fix does nothing, and their own comment says why they wrote it. _ds-overrides.scss sets --opacity-muted: var(--opacity-text-disabled) on ds-button and ds-icon-button, explaining that "the DS dims a disabled control to --opacity-muted (0.6)". It does not: neither component reads that token anywhere. The disabled state is three oklch(from accent …) colours, so the override is inert — the button they were trying to fix is unchanged to this day.

How to read a row. The second column is the button ALIVE — rest, hover, active — so you can judge the disabled box against what it is supposed to differ from. Then one column per candidate. Every box is painted with background-image gradients and inline colours, so a force-dark browser cannot rewrite them. vs rest is the contrast between the disabled label and the enabled one: under 1.8:1 the state is a guess, which is exactly the complaint.

What each candidate is. A is today. B changes only the two variants that have no fill, replacing the accent-derived label with the neutral --text-disabled. C keeps the accent HUE and only lifts lightness/chroma — one number, every variant.

What the matrix says, and it is not what I first reported.
  1. Four of the five variants fail on a coloured accent, not one. I had assumed the box carried the state wherever a fill existed. Read the bg moved figure: solid repaints from primary to a 92% tint — 4.32:1, unmistakable. Tonal moves 1.09:1 and outline 1.07:1, which is nothing. So on primary and error, tonal, outline, ghost and text all say "off" with a label that barely moves: 1.24 / 1.24 / 1.60 / 1.60 against rest, and worse on error. Only solid is healthy, and only color="neutral" is healthy throughout.
  2. Which kills B as a complete answer. Restricting a neutral label to the fill-less pair fixes the Clear button (1.60 → 2.70) and leaves tonal and outline exactly as broken as they are today.
  3. C fixes all four — every cell reaches 2.40 or better — at one cost: the disabled label on a SOLID button drops from 3.38:1 to 2.11:1 against its own pale fill. Legible, but thinner than it needs to be, and solid was never the problem.
  4. D is C without that cost. Solid keeps today's 58% (label 3.38:1, box moving 4.32:1); every variant whose box cannot speak goes to 70%. That is one rule stated the way the components are actually built: the lighter label is for buttons whose fill cannot carry the state.

Still worth deciding separately, whichever wins: tonal and outline barely repaint their fill when disabled (1.07–1.09:1). Even with D's label, the box lies. Either move those fills properly toward --surface-disabled, or accept that the label is the whole signal — but then it is colour alone, which is the rule we hold every other component to.
