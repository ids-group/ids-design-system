PIN-475 · combobox / select / search — варианты решений

Четыре гэпа из Kit Movement. Контролы воссозданы 1:1 по lib-scss. Фокус показан статически (класс .is-focused), чтобы сравнивать кольца без кликов. Отметь предпочтение в каждой секции — сводка справа внизу. Выбранное я внедрю в библиотеку.

1 · Один контур фокуса search · select · combobox

Сейчас на фокусе видно ДВА концентрических кольца: 1px-бордер контрола + отдельное кольцо box-shadow. Хуже всего у combobox — он на --focus-ring (2px canvas-зазор + сплошной primary = явный двойной контур); select/search на мягком --focus-field. Ниже — как свести к одному контуру. Затрагивает также input / dropdown / link (выбранное распространю на них).

Как реализовано сейчас (baseline)

Три поля рисуют фокус тремя разными способами — отсюда разнобой. Все перекрашивают бордер в --primary, но кольцо берут из разных токенов: combobox — жёсткий --focus-ring (с зазором), select/search — мягкий --focus-field. Поля сфокусированы статически (класс .is-focused), код — дословно из lib-scss.

ds-combobox → --focus-ring

Жёсткое 2px-кольцо primary + зазор цветом фона (--surface-canvas) между ним и бордером → читается как двойной/тройной контур.
Active
// combobox.component.scss
.combo-trigger:focus-within {
  border-color: var(--primary);
  box-shadow: var(--focus-ring);
  outline: 0;
}

ds-select → --focus-field

Мягкое полупрозрачное гало 3px (primary 22%) + бордер primary. Без зазора. То же и на .open.
Warehouse A
// select.component.scss
.dropdown:focus-visible,
.dropdown.open {
  border-color: var(--primary);
  box-shadow: var(--focus-field);
}

ds-search → --focus-field

Так же мягкое гало, но через приватные резолверы (read-with-fallback паттерн DS) — переопределяемо консьюмером.
🔍
// search.component.scss — :host резолверы
--_search-border-focus: var(--ds-search-border-focus, var(--primary));
--_search-focus-shadow: var(--ds-search-focus-shadow, var(--focus-field));

.search:focus-within {
  border-color: var(--_search-border-focus);
  box-shadow: var(--_search-focus-shadow);
}

Анатомия токенов — почему combobox выбивается

Из чего собрано кольцо (схема слоёв, не в масштабе — реальные толщины подписаны). Значения дословно из themes/default/_theme.scss.
--focus-ring · combobox
бордер 1px--primary зазор 2px--surface-canvas кольцо 2px--primary 
--focus-ring:
  0 0 0 2px var(--surface-canvas),   /* зазор */
  0 0 0 4px hsl(primary);        /* кольцо */
− зазор цветом фона светится белым на тёмной подложке (см. строку ниже)
--focus-field · select / search
бордер 1px--primary гало 3pxprimary · 22% 
--focus-field:
  0 0 0 3px hsl(primary / 22%);  /* мягкое гало */
+ без зазора, мягко; но бордер + гало всё равно две линии

Варианты «один контур» (A / B / C)

Сейчас

Как вживую: combobox — двойное кольцо с белым зазором; select/search — бордер + мягкое гало.

A — единое мягкое гало РЕКОМЕНДУЮ

Все три на --focus-field: бордер→primary + одно мягкое гало 3px, без белого зазора. Минимальный риск, ровно совпадает с input.

B — чёткий offset-outline

На фокусе outline: 2px primary; outline-offset: 2px, без box-shadow и без перекраски бордера. Одно чёткое отделённое кольцо (нативный/Figma-вид).

C — слитный primary-кант

Бордер→primary + плотный 1px primary вплотную = единый 2px primary-кант, без гало и зазора. Самый «жёсткий» один контур.

На тёмном фоне (как в твоём Kit Movement) — слева текущий двойной контур с белым зазором, дальше те же A / B / C. Тут видно, кто реально читается как одно кольцо:

2 · Ширина combobox (multi) combobox

Multi-combobox всегда тянется на ширину хоста — один короткий чип оставляет широкий пустой триггер справа, в тулбаре выглядит сломанным. Предлагаю режим fit-content: триггер обнимает чипы + минимальное поле ввода. API: новый инпут widthMode: 'full' | 'fit' (дефолт full, обратно совместимо).

3 · Single-select: вид «как select» combobox

Сейчас single-ds-combobox рендерит лейбл выбранного + пустой текст-инпут + шеврон одновременно (combobox.component.html: <span.combo-value> рядом с <input.combo-input>). Из-за пустого инпута контрол выглядит как «можно печатать» — неотличим от multi/typeahead и от ds-select. Ниже — что сейчас рисует DS, и 4 проработанных варианта single-вида с реализацией (контролы 1:1 по lib-scss: chevron-SVG, панель с --shadow-popover, check-иконка, hover --surface-secondary).

Что DS рисует сейчас

Слева — корректные «полюса»: ds-select single (лейбл+шеврон) и ds-combobox multi (чипы+ввод). Справа — проблема: single-combobox тащит и лейбл, и пустой инпут.

Закрытый single-combobox = чистый select (лейбл + шеврон, одна строка, без инпута). При открытии лейбл заменяется на поле поиска — typeahead сохраняется. Multi не трогаем.

Реализация (combobox.component.html + scss) 
<!-- trigger: single сворачивается в select-вид, инпут только при открытии -->
@if (!multiple()) {
  @if (isOpen()) {
    <input #filter class="combo-input" [value]="query()"
           (input)="onFilter($event)" (keydown)="onKeydown($event)"/>
  } @else {
    <span class="combo-value" [class.ph]="!displayLabel()">
      {{ displayLabel() || placeholder() }}
    </span>
  }
}
<ds-icon name="chevronDown" class="combo-chevron"/>

/* combobox.component.scss — host-флаг для single */
:host(.single) .combo-trigger { flex-wrap: nowrap; height: var(--hit-cozy); min-height: 0; }
// onTriggerClick() уже фокусит filterInput + openPanel(); close() вернёт span
