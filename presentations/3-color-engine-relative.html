Цвет-движок: один источник вместо канал-дубля

Сегодня «primary» в DS живёт в двух расцепленных видах: ручные пики рампы (--primary = --blue-600, оттенки тоже пики) и HSL-каналы (--primary-h/s/l). Из-за этого нет одного рычага перекраски, а консьюмерский --primary-h/s/l-override красит halo полей, ссылки и тёмные тинты, но не заливку. Современный CSS (color-mix() + relative color) позволяет держать один токен на роль и выводить остальное математически — сохраняя ручную калибровку.

⚠ Твой браузер не поддерживает relative color syntax (hsl(from …)) — свотчи ниже не пересчитаются. Открой в свежем Chrome/Edge/Safari/Firefox.
проблема сегодня

Два расцепленных представления одного «primary»

/* themes/_base-palette.scss:37-50 - рампа генерится из ОДНОГО hue-канала --blue-h */
--blue-h: 229;  --blue-600: hsl(var(--blue-h) var(--blue-s) var(--blue-l));

/* themes/_semantic.scss:62,77,193 - но «primary» = ПИК рампы, а каналы - отдельный набор */
--primary:    var(--blue-600);          // (a) через --accent читают заливки: checkbox, button…
--primary-h:  var(--blue-h);            // (b) читают halo полей, ссылки, серые, тёмные тинты
--focus-field: …hsl(var(--primary-h) var(--primary-s) var(--primary-l) / .22);

Связи нет: --primary зависит от --blue-h, а не от --primary-h. Заливка галочки читает var(--accent), кольцо фокуса - outline цвета --focus-ring-color, и оба указателя разрешаются на :root (themes/_semantic.scss:170,221). Поэтому консьюмерский ds-checkbox { --primary-h: 5; … } не перекрашивает ни заливку, ни кольцо, а тот же override на :root красит halo полей, ссылки и тёмные тинты, но заливка остаётся синей. Чтобы перекрасить когерентно, нужно лезть и в каналы, и пере-собирать --primary — те самые 3–4 токена.

инструмент

color-mix() + relative color — нарезать любой цвет на лету

--primary: #2E54FF;                                  /* один источник (hex/var) */
--primary-hover:  color-mix(in srgb, var(--primary) 88%, black);   // DS уже так делает
--primary-pressed:color-mix(in srgb, var(--primary) 76%, black);
--focus-halo:     color-mix(in srgb, var(--primary) 22%, transparent); // вместо hsl(h s l / .22)
--primary-strong: hsl(from var(--primary) h 85% 42%);          // hue из --primary, S/L — ручные
--primary-subtitle: hsl(from var(--primary) h 100% 97%);

Relative color — Baseline (Chrome 119 / Safari 16.4 / Firefox 128, с 2023–24), color-mix() ещё раньше. hsl(from var(--primary) h … …) вытаскивает только hue из одного токена — S/L каждого шага остаются рукотворными, так что дизайнерская рампа не превращается в формулу.

живое демо

Одна ручка --primary → всё следует

Меняй источник — все оттенки, halo, кнопка, чекбокс и бейдж пересчитываются в чистом CSS (никакого JS-пересчёта, только смена одной переменной):

primaryисточник
hovermix 88% black
pressedmix 76% black
strongfrom h 85% 42%
mutedfrom h 95% 90%
subtitlefrom h 100% 97%
Чекбокс + halo Badge (subtitle + strong)

Заливка чекбокса = var(--primary), halo = color-mix(… 22%, transparent) — оба следуют за одной ручкой. Это и есть то, чего сегодня нельзя одной строкой.

выгода

Перекраска на scope — одна строка (и это разблокирует --accent)

Сегодня

[data-theme='dark'] ds-checkbox {
  --primary-h: 5;
  --primary-s: 92%;
  --primary-l: 64%;
  /* + ещё пере-собрать --primary, --accent
     и --focus-ring-color, иначе синие */
}

Предложение

[data-theme='dark'] ds-checkbox {
  --primary: hsl(5 92% 64%);
  /* fill + border + hover +
     halo — всё следом */
}

Когда компоненты выводят оттенки из одного токена, --accent-indirection уже тривиальна: зона/атрибут ds-color флипает один указатель, всё каскадит (_ds-color.scss, cc8612a3).
