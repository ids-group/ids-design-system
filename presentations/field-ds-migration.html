Design system · migration explained

Field prototype → @ids-group-ltd/ids-design-system

The pinkmoon field app used to consume a vendored copy of the design system (libs/design-system). We migrated it to the published npm package. The package had moved on from that copy — renamed components, restructured tokens — so the migration was not just a path swap. This page explains every change and why it happened.

1. How the design system is layered palette ≠ theme ≠ component

The DS has three tiers. The golden rule that drives everything below: components consume the semantic + scale tiers — never the palette directly.

Tier 1
Palette Raw, concrete colours. --blue-600, --red-500, --pm-color-primary. The "paint tins" — no meaning on their own.
Tier 2
Semantic Roles that map palette → purpose. --primary, --text-primary, --surface-default, --success, --border-default. ← components use these.
Tier 3
Scale Theme-independent geometry/type. --space-*, --radius-*, --font-size-*. ← components use these too.
Why it matters: re-skinning (brand, dark mode) happens by remapping Tier 2 in one place. A component that hardcodes a Tier-1 colour (--blue-600) silently escapes the theme — exactly the bug we hit with the brand below.

2. Component API changes renamed in the published DS

The published components changed names/variants. These were caught by the build (type errors), so they were loud, not silent.

Button variants fixed

variant="ghost"→variant="outline"
variant="danger"→variant="error"

Material-3 naming. outline = bordered neutral (the old ghost had a border), error = destructive fill.

Icon-only buttons fixed

<ds-button iconOnly>→<ds-icon-button>

Icon-only actions moved to a dedicated component (icon + required ariaLabel). Back / close / help / edit buttons migrated.

Tag variant fixed

variant="ghost"→variant="neutral"

Tag taxonomy is now solid | neutral.

Import specifier fixed

from 'ds'→from '@ids-group-ltd/ids-design-system'

31 files repointed from the in-workspace alias to the npm package. Admin still uses the vendored copy — untouched.

3. Token vocabulary rename the silent one

The DS renamed every scale token from short-form to long-form. Sass compiles either way, so the build stayed green — but var(--old-name) resolved to nothing at runtime. Result before the fix: collapsed layout (zero padding, zero radius, default fonts). ~500 references across 44 files.

Values are identical — only the names changed (--s-5 and --space-5 are both 20px). So spacing/sizing matches the original design pixel-for-pixel once the names are fixed.

4. The brand went blue palette-vs-semantic, in practice

was (DS default)
→
fixed (brand)

Why buttons turned blue root cause

The old DS drove the brand through --brand-* tokens. The published DS has no --brand-* — it drives the brand role through --primary*.

Field overrode --surface-* / --text-* (role names that still match → worked) but set the brand colour via --brand — which the published DS ignores. So buttons/links/focus fell back to the DS default --primary = --blue-600.

--brand: pink+--primary: var(--brand)

Fix: map the pinkmoon brand onto the DS --primary* ramp in field's theme. Hover/secondary/tertiary derive automatically.

5. Full-width buttons a default flipped

What changed DS contract

Old ds-button stretched to fill its container by default. The published one is :host { width: fit-content } — it opts out of the stretch.

So form / bottom-bar buttons (Sign In, Continue, Cancel, Scan QR Code) shrank to content width.

The fix fixed

Full-width is now an explicit, intentional API: the fullWidth input.

<ds-button fullWidth>

Added to 15 action buttons (bottom bars + forms). Inline / toolbar buttons left content-width on purpose.

6. The rule, and where field still breaks it answer to "palette or semantic?"

Components should use semantic + scale tokens, never palette primitives directly. Direct palette use is what makes a colour escape theming / rebrand.

Field is mostly compliant after the migration. A handful of components still reach into the palette — minor, worth a cleanup pass:

Used directly (Tier 1)Should be (Tier 2)Spots

--pm-color-brand--brand / --primary2
--green-300--success-border1

8. Result field branch

Field now consumes the published package and renders identically to the previous version. Admin and the vendored library were not touched. No design-system changes were needed — every issue was the new DS contract that the consumer had to follow.
